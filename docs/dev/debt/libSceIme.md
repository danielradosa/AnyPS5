# libSceIme technical debt

### Unknown function info

- [sceImeOpen](../../../core/libs/prx/libSceIme/Export.cpp) (libSceIme) - opens one IME at a time (`BUSY` 0x80bc0001 for a second) after the parameter checks and error codes of [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/ime/ime.cpp), which come from the PS4 library: user ID (negative or the system user 0xff), type, enter label, input method, option bits (0x7bff as in `sceImeGetPanelSize`), multiline with password, multiline outside the default and Latin types and password outside the Latin and number types (`INVALID_PARAM`), maximum text length 1 to 2048, text buffer, position on a 1920x1080 screen (3840x2160 with option 0x4000), alignments, extended panel priority and reserved bytes, work memory (non-null and 4-byte aligned), handler, reserved bytes, and an initial text with surrogates or, outside multiline, line breaks. shadPS4's checks that depend on the compiled PS4 SDK version (supported languages, extended options, keyboard filter and devices), its overlap check between the text buffer and the work memory and its clearing of 0x5000 bytes of work memory are left out, as their PS5 counterparts are unknown. No panel is drawn and no user input reaches the IME: the first `sceImeUpdate` delivers the open event (id 0, with the panel rectangle) to its handler with the parameter's `arg`, and no enter or close event follows, so the title's text buffer is never written and the IME stays open until the title closes it. `sceImeSetText` replaces the IME's own copy of the text, clamped to the maximum length, and `sceImeSetCaret` accepts indices up to its length (`INVALID_PARAM` beyond); `sceImeSetTextGeometry` accepts only selection and preedit areas on a 1920x1080 screen, as shadPS4 does
- [sceImeGetPanelPositionAndForm](../../../core/libs/prx/libSceIme/Export.cpp) (libSceIme) - the output is taken to be the `PositionAndForm` that `sceImeDialogGetPanelPositionAndForm` fills. With an IME open it reports the position and alignments `sceImeOpen` was given, the size `sceImeGetPanelSize` computes and panel type 0 (hidden, in shadPS4's `OrbisImePanelType`), as no panel is drawn; a null output then returns `INVALID_ADDRESS`. That a closed panel is reported before a null output is assumed by analogy with `sceImeSetCaret`, not confirmed on a PS5 title

### Functional

- [sceImeKeyboardGetInfo](../../../core/libs/prx/libSceIme/Export.cpp) (libSceIme) returns `0x80bc0023` (no resource id) for every id while a keyboard is open, since the IME keyboard never reports a connected device. [sceImeKeyboardSetMode](../../../core/libs/prx/libSceIme/Export.cpp) validates the mode bits but the mode has no effect, as no IME keyboard events are delivered.
- [sceImeKeyboardGetResourceId](../../../core/libs/prx/libSceIme/Export.cpp) (libSceIme) reports that no USB keyboard is connected (`0x80bc0004`, as [shadPS4](https://github.com/shadps4-emu/shadPS4) does) because IME keyboard events are not delivered to the handler, although [libSceKeyboard](../../../core/libs/prx/libSceKeyboard/src/keyboard_impl.cpp) exposes the host keyboard
