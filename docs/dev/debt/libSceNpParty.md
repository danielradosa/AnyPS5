# libSceNpParty technical debt

### Unknown function info

- [sceNpPartyGetState](../../../core/libs/prx/libSceNpParty/Export.cpp) (libSceNpParty) - the 16-bit state, its `NOT_IN_PARTY` value 2 and the `INVALID_ARGUMENT` (`0x80552504`) error follow shadPS4's [np_party.h](https://github.com/shadps4-emu/shadPS4/blob/a808e76/src/core/libraries/np/np_party.h) and [np_error.h](https://github.com/shadps4-emu/shadPS4/blob/a808e76/src/core/libraries/np/np_error.h) (PS4); shadPS4 does not check for a null state, and whether the console needs an initialized party library first is not known. Not measured on a PS5
- [sceNpPartyGetStateAsUserA, sceNpPartyGetMemberInfoA, sceNpPartyGetMembersA](../../../core/libs/prx/libSceNpParty/Export.cpp) (libSceNpParty) - signatures from [orbital](https://github.com/AlexAltea/orbital/blob/b321fcdbd700cc02da1cb1ad25412781d5ec73c6/tools/ida/db_types.json). There is no party, so `sceNpPartyGetStateAsUserA` answers like `sceNpPartyGetState` for any user (null state `INVALID_ARGUMENT`, else `NOT_IN_PARTY`), and the two member queries return `SCE_NP_PARTY_ERROR_NOT_IN_PARTY` (`0x80552506`) without reading their arguments or writing the output, as [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/np/np_party.cpp) does for the PS4 member calls; argument checks before the party check are unknown. Not measured on a console.
- [The other libSceNpParty exports](../../../core/libs/prx/libSceNpParty/Export.cpp) (libSceNpParty) - orbital gives prototypes for `sceNpPartyInitialize`, `sceNpPartyTerminate`, `sceNpPartyCheckCallback`, `sceNpPartyRegisterHandlerA`, `sceNpPartyGetId`, `sceNpPartyGetMemberSessionInfo`, `sceNpPartyGetMemberVoiceInfo` and `sceNpPartySendBinaryMessage`, but shadPS4 only stubs them with `OK` and no public source shows their initialization rules or their answers outside a party; the rest have no public prototype. They keep throwing.
