# libSceVrTracker2 technical debt

### Silent stubs

- [libSceVrTracker2](../../../core/libs/prx/libSceVrTracker2/Export.cpp) tracks only its own initialization. No PS VR2 device can be opened on the host (`sceHmd2Open` never returns a handle and `scePadOpen` rejects the VR controller port types), so `sceVrTracker2RegisterDevice` rejects every handle with `INVALID_DEVICE_HANDLE`, `sceVrTracker2UnregisterDevice` rejects every handle with `ARGUMENT_INVALID`, as PS4's `sceVrTrackerUnregisterDevice` does for a handle it does not know ([shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/vr_tracker/vr_tracker.cpp)), and once initialized `sceVrTracker2GetResult`, `sceVrTracker2ResetLocalCoordinate`, `sceVrTracker2LocateCoordinateSystem` and `sceVrTracker2GetPlayAreaOrientedBoundingBox` return `DEVICE_NOT_REGISTERED` and write nothing. `sceVrTracker2Initialize` keeps neither the work memory nor the thread settings and starts no tracker thread, so it cannot check that the memory is large enough. `sceVrTracker2QueryMemory` validates its parameter and returns `NOT_SUPPORTED`, because the console's memory requirement is unknown; a title that sizes the work memory from it never initializes the tracker. `sceVrTracker2SetCoordinateSystem` throws: its parameters are unknown and the console may accept it without a device. PPSA01317 only reaches this library after `sceHmd2Initialize` succeeds, which it does not here

### Unknown function info

- [libSceVrTracker2](../../../core/libs/prx/libSceVrTracker2/Export.cpp) signatures and parameter layouts follow [PS5VR](https://github.com/theghostonline/PS5VR/blob/0e408909ce7a39891a2e06eee3438d07a09e11e3/app/src/app_vr.c#L58-L64) (PPSA99177), which drives PS VR2 on FW 13.60: `sceVrTracker2QueryMemory(param, result)` with a 0x20-byte param (size at `+0`, profile at `+4`, 0 being "the only one open to apps") and the [memory size and alignment](https://github.com/theghostonline/PS5VR/blob/0e408909ce7a39891a2e06eee3438d07a09e11e3/app/src/app_vr.c#L620-L641) as the second and third words of the result; `sceVrTracker2Initialize(param)` with a 0x48-byte param (size at `+0`, work memory at `+0x20`, its size at `+0x28` and alignment at `+0x2c`; PS5VR also sets 700 at `+8` and `+0xc` and 0x1f00 at `+0x10` and `+0x18`, unchecked here); `sceVrTracker2RegisterDevice(type, handle)`, type 0 for the headset and 1 and 2 for the controllers; `sceVrTracker2GetResult(param, result)` with a [0x20-byte param](https://github.com/theghostonline/PS5VR/blob/0e408909ce7a39891a2e06eee3438d07a09e11e3/app/src/app_vr.c#L669-L677) (size at `+0`, handle at `+4`, time at `+0x10`); `sceVrTracker2UnregisterDevice(handle)`; and `sceVrTracker2Finalize()`. Size fields must match exactly, as PS4's libSceVrTracker requires; the device types, profiles and memory alignments the console accepts are unknown. `sceVrTracker2ResetLocalCoordinate`, `sceVrTracker2LocateCoordinateSystem` and `sceVrTracker2GetPlayAreaOrientedBoundingBox` are declared without parameters and read none, so arguments the console might reject first are not checked
- [libSceVrTracker2](../../../core/libs/prx/libSceVrTracker2/Export.cpp) error codes put PS4 libSceVrTracker's low byte ([shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/vr_tracker/vr_tracker_error.h), 0x812608xx) under 0x8A740000: `NOT_INIT` 0x8A740001, `ALREADY_INITIALIZED` 0x8A740002, `DEVICE_NOT_REGISTERED` 0x8A740003, `ARGUMENT_INVALID` 0x8A740006, `INVALID_DEVICE_HANDLE` 0x8A740007 and `NOT_SUPPORTED` 0x8A74001E. Only 0x8A740006 is observed: [PS5VR](https://github.com/theghostonline/PS5VR/blob/0e408909ce7a39891a2e06eee3438d07a09e11e3/app/src/vr_system.c#L126-L132) replaces a libSceVrTracker2 export with one of "the same contract" that returns it for bad arguments. Its 0x8A740009 for a buffer that is too small does not match PS4's 0x09 (`INTERNAL_ERROR`), so the mapping is unverified. Initialization is checked first, as on PS4, except in `sceVrTracker2Initialize`, which checks for a previous initialization first, and `sceVrTracker2QueryMemory`, which needs none
