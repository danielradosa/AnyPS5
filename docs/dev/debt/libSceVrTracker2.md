# libSceVrTracker2 technical debt

### Silent stubs

- [libSceVrTracker2](../../../core/libs/prx/libSceVrTracker2/Export.cpp) tracks only its own initialization. No PS VR2 device can be opened on the host (`sceHmd2Open` never returns a handle and `scePadOpen` rejects the VR controller port types), so `sceVrTracker2RegisterDevice` rejects every handle with `INVALID_DEVICE_HANDLE`, `sceVrTracker2UnregisterDevice` rejects every handle with `ARGUMENT_INVALID`, as PS4's `sceVrTrackerUnregisterDevice` does for a handle it does not know ([shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/vr_tracker/vr_tracker.cpp)), and once initialized `sceVrTracker2GetResult`, `sceVrTracker2ResetLocalCoordinate`, `sceVrTracker2LocateCoordinateSystem` and `sceVrTracker2GetPlayAreaOrientedBoundingBox` return `DEVICE_NOT_REGISTERED` and write nothing. `sceVrTracker2Initialize` keeps neither the work memory nor the thread settings and starts no tracker thread, and does not hold the work memory to the 32 MiB `sceVrTracker2QueryMemory` reports, since the console's error for a smaller one is unknown. Its success is not the console's: with PPSA05666's parameter and no headset the console's initialization did not return within a minute (below). After initialization `sceVrTracker2GetCoordinateSystem`, `sceVrTracker2GetPlayAreaBoundaryGeometry`, `sceVrTracker2SetCoordinateSystem` and the unnamed exports that answer 0x8A740001 or clear a result before it throw, because what an initialized tracker answers there is unknown. PPSA01317 only reaches this library after `sceHmd2Initialize` succeeds, which it does not here
- [libSceVrTracker2](../../../core/libs/prx/libSceVrTracker2/Export.cpp) answers before initialization as the console's module does, measured in #7463 on a retail PS5 (firmware 13.60) with no PS VR2 headset by calling each of the 115 NIDs with null arguments, zeroed buffers and buffers filled with 0xAA and 0x01: 99 return 0x8A740001 and write nothing; `XknY0IDcOwU` and `ark13GkiskA` return 0x8A740006 for a null first argument and otherwise clear its first 24 and 16 bytes and return 0x8A740001; `-YvjOUph8B0` returns 0x8A740006 for a null second argument and otherwise 0x8A740001; `QyZvFyf-QEk` and `fTYZOZepkqE` return 0 and write nothing; `TZIUIk9id3c` writes 0xC000, 0, 0x40 and 0x40 as `uint32`, `uint32`, `uint16` and `uint16` at offsets 4 to 15 of its first argument and returns 0; `IB0qcDVu8vU` clears the `uint32` at its first argument and returns 0. The last two crash on the console for a null first argument and throw here. The 99 include the named exports, which check initialization first here as well. Signatures of the unnamed exports are unknown; the twelve exports with aerolib names keep them and the others carry this library's own names

### Unknown function info

- [sceVrTracker2QueryMemory](../../../core/libs/prx/libSceVrTracker2/Export.cpp) (libSceVrTracker2, NID `TwqZnaIjWv4`) - accepts only a parameter whose first `uint32` is 0x20 and whose bytes 4 to 31 are zero, found by searching sizes 8 to 0x400 and setting each field and byte; it then writes 32 bytes, `uint32` 0x20, 32 MiB and 64 KiB followed by zeros, and returns 0, and otherwise returns 0x8A740006 without writing, as it does for a null argument. The meaning of the parameter's reserved bytes and of the written fields is assumed from their values
- [libSceVrTracker2](../../../core/libs/prx/libSceVrTracker2/Export.cpp) signatures and parameter layouts follow [PS5VR](https://github.com/theghostonline/PS5VR/blob/0e408909ce7a39891a2e06eee3438d07a09e11e3/app/src/app_vr.c#L58-L64) (PPSA99177), which drives PS VR2 on FW 13.60: `sceVrTracker2QueryMemory(param, result)` with a 0x20-byte param (size at `+0`, profile at `+4`, 0 being "the only one open to apps") and the [memory size and alignment](https://github.com/theghostonline/PS5VR/blob/0e408909ce7a39891a2e06eee3438d07a09e11e3/app/src/app_vr.c#L620-L641) as the second and third words of the result; `sceVrTracker2Initialize(param)` with a 0x48-byte param (size at `+0`, work memory at `+0x20`, its size at `+0x28` and alignment at `+0x2c`; PS5VR also sets 700 at `+8` and `+0xc` and 0x1f00 at `+0x10` and `+0x18`, unchecked here); `sceVrTracker2RegisterDevice(type, handle)`, type 0 for the headset and 1 and 2 for the controllers; `sceVrTracker2GetResult(param, result)` with a [0x20-byte param](https://github.com/theghostonline/PS5VR/blob/0e408909ce7a39891a2e06eee3438d07a09e11e3/app/src/app_vr.c#L669-L677) (size at `+0`, handle at `+4`, time at `+0x10`); `sceVrTracker2UnregisterDevice(handle)`; and `sceVrTracker2Finalize()`. Size fields must match exactly, as PS4's libSceVrTracker requires; the device types, profiles and memory alignments the console accepts are unknown. `sceVrTracker2ResetLocalCoordinate`, `sceVrTracker2LocateCoordinateSystem`, `sceVrTracker2GetPlayAreaOrientedBoundingBox`, `sceVrTracker2GetCoordinateSystem`, `sceVrTracker2GetPlayAreaBoundaryGeometry` and `sceVrTracker2SetCoordinateSystem` are declared without parameters and read none, so arguments the console might reject first are not checked
- [libSceVrTracker2](../../../core/libs/prx/libSceVrTracker2/Export.cpp) - initialization (`6Jy73SRfG-o`) takes one parameter of 0x48 bytes. PPSA05666 passes the size 0x48 at offset 0, `uint32` 0x100 and 0x2BC at 0x8 and 0xC, `uint64` 0x1FFF at 0x10 and 0x18, a pointer to its work memory at 0x20, and the memory query's 32 MiB and 64 KiB as `uint32` at 0x28 and 0x2C, with the other bytes zero; the priority and CPU mask meanings of 0x8 to 0x1F are assumed from the values. Called with that parameter and 32 MiB of anonymous memory from a homebrew payload on a PS5 (firmware 13.60) with no PS VR2 headset, it did not return within a minute, so what it returns without a headset is unknown. The layout matches PS5VR's, which `sceVrTracker2Initialize` checks as above
- [libSceVrTracker2](../../../core/libs/prx/libSceVrTracker2/Export.cpp) error codes put PS4 libSceVrTracker's low byte ([shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/vr_tracker/vr_tracker_error.h), 0x812608xx) under 0x8A740000: `NOT_INIT` 0x8A740001, `ALREADY_INITIALIZED` 0x8A740002, `DEVICE_NOT_REGISTERED` 0x8A740003, `ARGUMENT_INVALID` 0x8A740006 and `INVALID_DEVICE_HANDLE` 0x8A740007. 0x8A740001 and 0x8A740006 are observed on a console (above); the others are not. [PS5VR](https://github.com/theghostonline/PS5VR/blob/0e408909ce7a39891a2e06eee3438d07a09e11e3/app/src/vr_system.c#L126-L132) replaces a libSceVrTracker2 export with one of "the same contract" that returns it for bad arguments. Its 0x8A740009 for a buffer that is too small does not match PS4's 0x09 (`INTERNAL_ERROR`), so the mapping is unverified. Initialization is checked first, as on PS4, except in `sceVrTracker2Initialize`, which checks for a previous initialization first, and `sceVrTracker2QueryMemory`, which needs none
- [libSceVrTracker2](../../../core/libs/prx/libSceVrTracker2/Export.cpp) - seven unnamed exports throw. `9R6W33Au4B4`, like initialization (`6Jy73SRfG-o`), returns 0x8A740006 on the console for null arguments, for zeroed, 0xAA- and 0x01-filled buffers and for a size field from 8 to 0x400 in any of the first three arguments; initialization also returned it for the memory query's parameter with 32 MiB aligned to 64 KiB passed inside the parameter or as further arguments, so the parameter layout it accepts is unknown. `NBhWy+Gl0tY` returns 0x8A740006 for those buffers but crashes for null arguments; `jRmuXjsknsI` returns 0x8A740006 for null arguments and crashes for buffers, also when every 8-byte slot points at readable memory; `O8ZkTFtvUL4`, `940WPg+WwIk`, `oZDm1bynCaA` and `U1VYczwqukY` crash for both
