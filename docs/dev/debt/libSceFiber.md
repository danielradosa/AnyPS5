# libSceFiber technical debt

### Functional

- [sceFiberGetInfo](../../../core/libs/prx/libSceFiber/Export.cpp) reports the requested-size window at the top of the host stack used for execution, rather than the original caller buffer, which is retained and pinned. The additional 1 MiB host-call margin below that window is not included in `size_context`. Planet Coaster (PPSA01736 v01.017) uses this range for ChakraCore garbage-collector stack scans; reporting the unused caller buffer makes the scan cross unmapped memory. The range is covered by a regression test while running, switching and migrating a fiber between threads. Console behavior for substituted host stacks has no direct equivalent and is not measured.

### Unknown function info

- [_sceFiberGetThreadFramePointerAddress](../../../core/libs/prx/libSceFiber/Export.cpp) (libSceFiber, NID `0dy4JtMUcMQ`) forwards to `sceFiberGetThreadFramePointerAddress`; that the argument list matches is inferred from the export without the underscore, as for the underscore Ult exports, not measured
- [libSceFiber internal exports](../../../core/libs/prx/libSceFiber/Export.cpp) - `_sceFiberInitializeWithInternalOptionImpl` takes `_sceFiberInitializeImpl`'s arguments with a 32-bit flags word before the build version, as [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/3a9f57265d28975658f1ca941daa5c879c7a74bd/src/core/libraries/fiber/fiber.cpp#L150-L153) (PS4) and [KytyPS5](https://github.com/KytyPS5/KytyPS5/blob/db41d0482f3a9489d97b94f6eaf72b2339d9256c/src/libs/libKernel.cpp#L2585-L2597) bind it. The flag meanings follow shadPS4's [`FiberFlags`](https://github.com/shadps4-emu/shadPS4/blob/3a9f57265d28975658f1ca941daa5c879c7a74bd/src/core/libraries/fiber/fiber.h#L27-L32): 0x1 (`NoUlobjmgr`) has no effect because [ulobjmgr](../../../core/libs/prx/ulobjmgr/Export.cpp) registers nothing, 0x10 turns the context size check on for that fiber, and 0x100 (`SetFpuRegs`, KytyPS5's `FIBER_FLAG_SET_FPU_REGS`) starts the fiber with MXCSR 0x9fc0 and x87 control word 0x037f instead of the caller's, the values shadPS4 [stores](https://github.com/shadps4-emu/shadPS4/blob/3a9f57265d28975658f1ca941daa5c879c7a74bd/src/core/libraries/fiber/fiber.cpp#L102-L106) for its [`_sceFiberSwitchEntry`](https://github.com/shadps4-emu/shadPS4/blob/3a9f57265d28975658f1ca941daa5c879c7a74bd/src/core/libraries/fiber/fiber_context.cpp#L88-L93) to load; any other bit throws. [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/3a9f57265d28975658f1ca941daa5c879c7a74bd/src/core/libraries/fiber/fiber.cpp#L180-L182) and [KytyPS5](https://github.com/KytyPS5/KytyPS5/blob/db41d0482f3a9489d97b94f6eaf72b2339d9256c/src/libs/libKernel.cpp#L2566) also set 0x100 on every fiber whose build version is at least 0x03500000; that is a PS4 SDK threshold, the PS5 SDK numbers differently, and what the console does is unverified, so it is not applied. `_sceFiberAttachContextAndRun` and `_sceFiberAttachContextAndSwitch` take `(fiber, addr_context, size_context, arg_on_run, out)` as shadPS4's [`sceFiberRunImpl`](https://github.com/shadps4-emu/shadPS4/blob/3a9f57265d28975658f1ca941daa5c879c7a74bd/src/core/libraries/fiber/fiber.cpp#L260-L284) and [`sceFiberSwitchImpl`](https://github.com/shadps4-emu/shadPS4/blob/3a9f57265d28975658f1ca941daa5c879c7a74bd/src/core/libraries/fiber/fiber.cpp#L336-L360), which its [`sceFiberRun` and `sceFiberSwitch`](https://github.com/shadps4-emu/shadPS4/blob/3a9f57265d28975658f1ca941daa5c879c7a74bd/src/core/libraries/fiber/fiber.cpp#L540-L546) call with a null context; that signature has only shadPS4's reverse engineering behind it, since KytyPS5 binds both NIDs to plain run/switch. A fiber can be initialized without a context (null address and size 0) and gets one from these calls, with the checks of shadPS4's [`_sceFiberAttachContext`](https://github.com/shadps4-emu/shadPS4/blob/3a9f57265d28975658f1ca941daa5c879c7a74bd/src/core/libraries/fiber/fiber.cpp#L46-L79): `RANGE` below 512 bytes, and `INVALID` for a size that is not a multiple of 16, a missing address or size, or a context that is already attached. Running or switching to a fiber that still has no context throws; shadPS4 runs it on the caller's stack. `_sceFiberGetThreadFramePointerAddress` is assumed to match `sceFiberGetThreadFramePointerAddress`
