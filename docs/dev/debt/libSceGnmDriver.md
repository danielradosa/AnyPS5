# libSceGnmDriver technical debt

### Silent stubs

- [sceGnmAreSubmitsAllowed](../../../core/libs/prx/libSceGnmDriver/Export.cpp) (libSceGnmDriver, PS4) - returns 1: submissions are never suspended here, because nothing on the host takes the GPU away from the title. shadPS4 returns 0 only while its submission lock is held.
- [sceGnmIsUserPaEnabled, sceGnmDriverCaptureInProgress, sceRazorIsLoaded](../../../core/libs/prx/libSceGnmDriver/Export.cpp) (libSceGnmDriver, PS4) - return false: the user performance analysis mode, GPU captures and the Razor GPU profiler belong to development tools and are not present, as shadPS4 also answers for retail firmware. A title only skips its tool hooks on these answers.
- [sceGnmLogicalCuMaskToPhysicalCuMask](../../../core/libs/prx/libSceGnmDriver/Export.cpp) (libSceGnmDriver, PS4) - returns the logical mask unchanged: no compute unit of the host maps to a disabled physical one, as [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/gnmdriver/gnmdriver.cpp) also answers.
- [sceGnmLogicalCuIndexToPhysicalCuIndex](../../../core/libs/prx/libSceGnmDriver/Export.cpp) (libSceGnmDriver, PS4) - returns 0 without reading an argument, the retail firmware answer [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/gnmdriver/gnmdriver.cpp) records (`int (void)`, "not available in retail firmware"); its argument list and the index the development firmware maps to are unknown.
- [sceGnmDriverTriggerCapture, sceGnmValidateCommandBuffers, sceRazorCaptureImmediate, sceRazorCaptureSinceLastFlip, sceRazorCaptureCommandBuffersOnlyImmediate, sceRazorCaptureCommandBuffersOnlySinceLastFlip](../../../core/libs/prx/libSceGnmDriver/Export.cpp) (libSceGnmDriver, PS4) - return the retail firmware's tool errors (Razor not loaded, validation not enabled, capture failed) without doing anything, as shadPS4 answers: the GPU capture and validation tools are not present.
- [sceGnmSetGsRingSizes](../../../core/libs/prx/libSceGnmDriver/Export.cpp) (libSceGnmDriver, PS4) - `(esgsRingSize, gsvsRingSize)` and the check of both sizes (4 to 8 MiB in 1 MiB steps, otherwise `0x08000000`) follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/gnmdriver/gnmdriver.cpp), which notes that Sony's library validates them. Valid sizes are accepted and have no effect: nothing in the AGC executor models the ES/GS and GS/VS rings of PS4 geometry shaders, so no ring is sized (shadPS4 stores them in its ring size registers).
- [sceGnmSetupMipStatsReport](../../../core/libs/prx/libSceGnmDriver/Export.cpp) (libSceGnmDriver, PS4) - `(outputBuffer, sizeInBytes, intervalsBetweenReports, numReportsBeforeReset, mipStatsResetForce)`, the checks (a null or not 64-byte aligned buffer returns `0x80000001`, a size below 0x1040 or not 0x40 past a multiple of 0x800 returns `0x80000002`) and the buffer initialization (zeroed, first word 0x40) follow shadPS4. The host GPU collects no mip statistics, so the buffer keeps that empty report; shadPS4's check that the address fits in 40 bits is left out because host addresses can be higher.

### Unknown function info

- [Command buffer writers](../../../core/libs/prx/libSceGnmDriver/Export.cpp) (libSceGnmDriver, PS4) - the packets, register offsets and reserved sizes the `sceGnm` writers emit follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/gnmdriver/gnmdriver.cpp); they are not checked on a console. The default hardware state, the pixel and compute shader writers live in [Commands.cpp](../../../core/libs/prx/libSceGnmDriver/src/Commands.cpp), which libSceGnmDriverForNeoMode compiles too, so both modules write the same packets. Submitted buffers run on the AGC executor ([Lowering.cpp](../../../core/libs/prx/libSceGnmDriver/src/Lowering.cpp)): PS4 EOP, EOS and SURFACE_SYNC packets are lowered to RELEASE_MEM and ACQUIRE_MEM, constant engine buffers are merged into the draw buffer, and the CP_DMA prefetch of the PS4 SDK is a NOP. An EOS GDS store becomes a RELEASE_MEM without data followed by a DMA_DATA of its dword count from the GDS into the destination; the GDS index is taken as a byte offset, as shadPS4 reads it (`ReadDataFromGds`), which is unverified (shadPS4 only handles one dword); other EOS commands throw. The constant engine runs lazily up to the draw engine's WAIT_ON_CE_COUNTER and at the end of each buffer pair; its WAIT_ON_DE_COUNTER_DIFF compares the signed counter difference, so a draw engine counter ahead of the lazily run constant engine does not block it, and a wait still blocked at the end of the pair throws (the console would resume it on a later submission). Interrupt flip reservations (`0x68750780`, and `0x68750781` with a label) are patched as [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/gnmdriver/gnmdriver.cpp) patches them: after the buffer label write and the flip, an EVENT_WRITE_EOP with the reserved event type and cache actions raises the end-of-pipe interrupt (writing the label first for the label form). `sceGnmRequestFlipAndSubmitDone` follows shadPS4: under 0x100 bytes it returns `SUBMISSION_NOT_ENOUGH_RESOURCES` (0x80D11001), otherwise it writes a flip reservation into the buffer, submits it and ends the frame like `sceGnmSubmitDone`.
- [Pending libSceGnmDriver exports](../../../core/libs/prx/libSceGnmDriver/Export.cpp) (libSceGnmDriver, PS4) - still throw: `sceGnmMapComputeQueue`, `sceGnmUnmapComputeQueue` and `sceGnmDingDong` (shadPS4's `(pipe, queue, ringBase, ringSizeInDwords, readPointer)` / `(vqid)` / `(vqid, nextOffsetInDwords)` map a guest compute ring and submit its new commands; the AGC executor offers libSceGnmDriver only a graphics submit entry point, so there is no compute ring to map, run or unmap), `sceGnmAddEqEvent` for a compute release-memory event id (no Gnm compute queue can raise it), `sceGnmGetTheTessellationFactorRingBufferBaseAddress` (shadPS4 hands out an address it reserves; no tessellation factor ring is modelled), and `sceGnmDebugHardwareStatus`, `sceGnmDisableMipStatsReport`, `sceGnmGetEqTimeStamp`, `sceGnmInsertSetColorMarker`, `sceGnmRequestMipStatsReportAndReset`, which shadPS4 only stubs without a prototype or a console answer.
