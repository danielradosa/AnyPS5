# libSceNpWebApi2 technical debt

### Silent stubs

- [sceNpWebApi2SetRequestTimeout](../../../core/libs/prx/libSceNpWebApi2/Export.cpp) (libSceNpWebApi2) - the `(request id, timeout)` signature follows [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/np/np_web_api2/np_web_api2.cpp). Pinball FX (PPSA08755) calls it while its main menu loads. It returns `INVALID_ARGUMENT` for a request id of 0 or below and otherwise succeeds and stores nothing: no request reaches a service, as `sceNpWebApi2SendRequest` fails with `UNAVAILABLE` at once, so no timeout can expire. shadPS4 returns `LIB_CONTEXT_NOT_FOUND`, `USER_CONTEXT_NOT_FOUND` or `REQUEST_NOT_FOUND` for an id it does not know; this call does not look the id up among the requests `sceNpWebApi2CreateRequest` records for `sceNpWebApi2AddWebTraceTag` (`sceNpWebApi2AbortRequest`, `sceNpWebApi2AddHttpRequestHeader` and `sceNpWebApi2DeleteRequest` also accept any id), so those errors are not reported

- [sceNpWebApi2InitializeForPresence, sceNpWebApi2IntInitialize and sceNpWebApi2IntInitialize2](../../../core/libs/prx/libSceNpWebApi2/Export.cpp) (libSceNpWebApi2) - create a library context like `sceNpWebApi2Initialize`, as [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/8d50471b7dc141dd700b51276b8edd1f293bce26/src/core/libraries/np/np_web_api2/np_web_api2.cpp#L174-L222) does on the PS4: the argument structures (32 and 40 bytes) and the `struct_size` check that returns `SCE_NP_WEBAPI2_ERROR_INVALID_ARGUMENT` follow its [declarations](https://github.com/shadps4-emu/shadPS4/blob/8d50471b7dc141dd700b51276b8edd1f293bce26/src/core/libraries/np/np_web_api2/np_web_api2.h#L15-L31). The context type shadPS4 records (2 for the internal initializers, 3 for presence), the context name and the push configuration group are not kept, and the 0x8000 context limit is not applied. Not measured on a PS5
- [sceNpWebApi2CreateMultipartRequest and sceNpWebApi2SendMultipartRequest](../../../core/libs/prx/libSceNpWebApi2/Export.cpp) (libSceNpWebApi2) - the request is not marked as multipart: creation returns `INVALID_ARGUMENT` for a null API group, path or method and then creates a request as `sceNpWebApi2CreateRequest` does without a content parameter, so the user context and the API group length are not checked (shadPS4: `USER_CONTEXT_NOT_FOUND`, `PARAMETER_TOO_LONG` from 63 bytes). Sending returns `INVALID_ARGUMENT` for a part index of 0 or below, null data or a size of 0, then fails with `UNAVAILABLE` as `sceNpWebApi2SendRequest` does. Signatures and argument checks follow the PS4 [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/np/np_web_api2/np_web_api2.cpp); not measured on a console
- [sceNpWebApi2IntPushEventCreateDestPs4CtxIndFilter](../../../core/libs/prx/libSceNpWebApi2/Export.cpp) (libSceNpWebApi2) - no credible prototype was found; it is declared without parameters solely to resolve known imports and makes no ABI claim.
- [sceNpWebApi2AddWebTraceTag](../../../core/libs/prx/libSceNpWebApi2/Export.cpp) (libSceNpWebApi2) - the `(int64 requestId, const char* value)` signature follows the SDK 12.000 reference, which lists no specific errors. Requests created by `sceNpWebApi2CreateRequest` are now tracked until `sceNpWebApi2DeleteRequest`: a null value returns `INVALID_ARGUMENT` (0x80553402) and an id that was never created or was deleted `REQUEST_NOT_FOUND` (0x80553406, the reference's code; the library's `UNAVAILABLE` constant has the same value). The tags are kept with the request in call order and never sent, since no request reaches PSN; the WebTrace debug setting that consumes them is a devkit feature. A tag length limit (`PARAMETER_TOO_LONG`) is not known, so any length is accepted
- [Push handle lifecycle](../../../core/libs/prx/libSceNpWebApi2/Export.cpp): PS5 create/delete/abort signatures and invalid-context/invalid-handle errors are confirmed. Handles track ownership, timeout and abort state; deletion and context termination remove them. Network push operations and cancellation of active requests remain unimplemented.
- [sceNpWebApi2PushEventCreateFilter](../../../core/libs/prx/libSceNpWebApi2/Export.cpp) (libSceNpWebApi2) - checks the context and push handle as the other push calls do, and a handle aborted with `sceNpWebApi2PushEventAbortHandle` returns `ABORTED` (0x80553409); that the console refuses a filter on an aborted handle, and with this code, is assumed, not measured
- [sceNpWebApi2GetMemoryPoolStats](../../../core/libs/prx/libSceNpWebApi2/Export.cpp): PS5 confirms the context/statistics arguments and 32-byte output. An invalid context returns `0x80553404` without changing output; a valid context with null output succeeds. Allocator accounting remains absent: peak and current usage still report zero instead of native pool allocations.
- [sceNpWebApi2PushEventSetHandleTimeout](../../../core/libs/prx/libSceNpWebApi2/Export.cpp): PS5 confirms three 32-bit arguments, ownership validation and storing the entire timeout value without range checks. The stored timeout is not consumed because asynchronous push operations are unimplemented.
