### Unknown function info

- [sceCompanionUtilOptParamInitialize and sceCompanionUtilGetRemoteOskEvent](../../../core/libs/prx/libSceCompanionUtil/Export.cpp) (libSceCompanionUtil) - names and NIDs are present in the [PS5 3.20 export inventory](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceCompanionUtil.c), and [orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json) gives `(SceCompanionUtilOptParam* pOptParam)` and `(SceUserServiceUserId userId)`, but both still throw: the option parameter's layout and defaults are unknown, and so is what the remote keyboard event call returns, as it takes no output
- [sceCompanionUtilInitialize, sceCompanionUtilTerminate and sceCompanionUtilGetEvent](../../../core/libs/prx/libSceCompanionUtil/Export.cpp) (libSceCompanionUtil) - no device can connect, so the event call answers `NO_EVENT` (0x80AD0008), as [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/companion/companion_util.cpp) does, without writing the event. Before that it checks as shadPS4's `getEvent` does: a null event `INVALID_ARGUMENT` (0x80AD0004), then `INVALID_POINTER` (0x80AD0006) while the library context is null, taken to mean before `sceCompanionUtilInitialize` or after `sceCompanionUtilTerminate`. The option, of unknown layout, is not read (null is accepted). No error is defined for a second initialization or a termination without one: both throw. The PS4 prototypes are in [orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json). Not measured on a console
