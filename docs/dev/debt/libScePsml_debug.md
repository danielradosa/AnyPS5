Only type 0 is accepted. The error codes for null pointers, short block lists and foreign handles are unknown, so those calls throw

### Functional

- [scePsmlMfsrInit](../../../core/libs/prx/libScePsml_debug/Export.cpp) (libScePsml) - succeeds and only sets the initialized state; the shared resources and contexts are bookkeeping objects that use none of the guest blocks. Whether Sony's library fails on hardware without PSSR is unknown. PPSA08330 calls the setup unconditionally and only uses a context when its cached `sceKernelIsTrinityMode` result is set (0x3c643d, 0x567f97; otherwise it stores a -0.25 mip bias itself at 0x567fe2), which AnyPS5 reports as 0, so the dispatch, mip bias and capture calls throw that the MFSR upscaler is not present on the host. The [EVO-PLAYER PSML notes](https://github.com/sainsaji/EVO-PLAYER-PS5/blob/9ee9a5420c73b5be448610e5f0a90a29a75592f3/docs/hardware/psml-research.md#L55-L61) say the library refuses outside Pro mode, which would make Init fail on a base PS5 with an unknown error; Init succeeds here so that titles calling the setup unconditionally get past it, and a title that would skip PSSR on that failure now reaches the calls that throw after Init
