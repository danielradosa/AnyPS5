### Unknown function info

- [scePsmlMfsr2Init](../../../core/libs/prx/libScePsml_debug/Export.cpp) (libScePsml_mfsr2) - throws. The library supports PSSR only in PS5 Pro mode: per the [EVO-PLAYER PSML notes](https://github.com/sainsaji/EVO-PLAYER-PS5/blob/9ee9a5420c73b5be448610e5f0a90a29a75592f3/docs/hardware/psml-research.md#L55-L61) it refuses unless `sceKernelIsTrinityMode()`, so a base PS5 returns an error here, but its value is unknown; titles such as PPSA20447 skip PSSR when Init fails. scePsmlMfsr2Init is assumed to behave like the console's scePsmlMfsrInit (EVO lists its success only as a Pro-mode observable)
- [scePsmlMfsr2CreateContext, scePsmlMfsr2CreateSharedResources, scePsmlMfsr2GetContextInitRequirement, scePsmlMfsr2GetDispatchPackets, scePsmlMfsr2GetDispatchPacketsSizeInDwords, scePsmlMfsr2GetSharedResourcesInitRequirement, scePsmlMfsr2ReleaseContext, scePsmlMfsr2ReleaseSharedResources](../../../core/libs/prx/libScePsml_debug/Export.cpp) (libScePsml_mfsr2) - return 0x8A810001 (not initialized) without reading their arguments, because Init never succeeds here. That every call tests the initialization first follows MFSR v1 ([KytyPS5 libPsml.cpp](https://github.com/KytyPS5/KytyPS5/blob/df5b9b92be7dfd463b47756b707d6d356a9f0550/src/libs/libPsml.cpp#L119-L321), #644); for MFSR2 it is assumed, and the signatures are unknown (imported by PPSA23566), so they stay declared without parameters
- [scePsmlMfsrGetSharedResourcesInitRequirement, scePsmlMfsrCreateSharedResources, scePsmlMfsrReleaseSharedResources, scePsmlMfsrGetContextBufferRequirement800M3_2, scePsmlMfsrCreateContext800M3_2, scePsmlMfsrReleaseContext](../../../core/libs/prx/libScePsml_debug/Export.cpp) (libScePsml) - only resource type 0 is supported. Validation throws for null pointers, short block lists and foreign handles instead of reproducing the system error and fault behaviour.

### Functional

- [scePsmlMfsrGetDispatchMfsrPacketSizeInDwords, scePsmlMfsrGetMipmapBias, scePsmlMfsrSelectConfig, scePsmlMfsrRequestCapture, scePsmlMfsrIsCaptureInProgress](../../../core/libs/prx/libScePsml_debug/Export.cpp) (libScePsml) - semantics from the APR-EMU `fakelib/libScePsml.sprx`. Guards: `0x8A810001` uninitialized, `0x8A810005` null/foreign handle (fakelib checks an engine id `0xA9C4`/`0x9231`; our map check is the equivalent), `0x8A810009` null output. `GetDispatchMfsrPacketSizeInDwords` writes `0x600`; `GetMipmapBias(context, bias, dimension)` writes `log2f(dimension / context->inputWidth) - 1.0f`, width recorded at `CreateContext800M3_2` from the parameter pair at 0x18 or `descriptor0 + 0x20` for callers that pass a descriptor pointer there (indirection inferred; zero width returns `0x8A810005`). `SelectConfig`, `RequestCapture`, `IsCaptureInProgress` validate then return 0. The `GetDispatchMfsrPacket*` calls still throw: the 0x158-byte template's packet routine is not understood
- [scePsmlMfsrInit](../../../core/libs/prx/libScePsml_debug/Export.cpp) (libScePsml) - succeeds and only sets the initialized state; the shared resources and contexts are bookkeeping objects that use none of the guest blocks. Whether Sony's library fails on hardware without PSSR is unknown. PPSA08330 calls the setup unconditionally and only uses a context when its cached `sceKernelIsTrinityMode` result is set (0x3c643d, 0x567f97; otherwise it stores a -0.25 mip bias itself at 0x567fe2), which AnyPS5 reports as 0, so the dispatch calls throw that the MFSR upscaler is not present on the host. The [EVO-PLAYER PSML notes](https://github.com/sainsaji/EVO-PLAYER-PS5/blob/9ee9a5420c73b5be448610e5f0a90a29a75592f3/docs/hardware/psml-research.md#L55-L61) say the library refuses outside Pro mode, which would make Init fail on a base PS5 with an unknown error; Init succeeds here so that titles calling the setup unconditionally get past it, and a title that would skip PSSR on that failure now reaches the calls that throw after Init
