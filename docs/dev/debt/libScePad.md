# libScePad technical debt

### Unknown function info

- [scePadSetAngularVelocityDeadbandState](../../../core/libs/prx/libScePad/src/PadState.cpp) (libScePad) - with the deadband on, each angular velocity axis whose magnitude is below 0.017453292 rad/s (1 degree per second) reads as 0, before the orientation is integrated; it starts off. Threshold, per-axis test and default follow [duaLib](https://github.com/WujekFoliarz/duaLib/blob/03bad1bea2a36561b520846776f2a07ced6773e0/src/source/duaLib.cpp#L44), which reimplements the PC `libScePad.dll`; the console's threshold is not measured, and the deadband is kept per library rather than per handle since one pad handle exists
- [scePadOpen and scePadOpenExt](../../../core/libs/prx/libScePad/Export.cpp) (libScePad) - special ports (type 2) return `DEVICE_NOT_CONNECTED` (0x80920007) because the host has no special controller, and `scePadGetHandle` has no handle for them; whether the console opens a handle and reports the device as disconnected later is unknown. PPSA01317 passes scePadOpenExt a 16-byte param that names the device by vendor and product id (`b7 0e 04 0e ...` for 0x0eb7:0x0e04, the [OpenOrbis](https://github.com/OpenOrbis/OpenOrbis-PS4-Toolchain/blob/7d08613c87e51eba22e530970cdb8e46d7605049/include/orbis/_types/pad.h#L114-L119) `OrbisPadExtParam`) and skips the user on any negative result. scePadOpenExt rejects a null param, then opens the port through scePadOpen and returns the same handle, as [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/cc728e1c7c97bb9dca71dea78e9e26a87a220280/src/core/libraries/pad/pad.cpp#L352-L356) and [fpPS4](https://github.com/red-prig/fpPS4/blob/accf9ec255e6d102aef5c1a9cf04a8059cb769b9/src/ps4_libscepad.pas#L373-L376) do for PS4; the vendor and product id in the param are not checked against the host controller
- [scePadReadExt](../../../core/libs/prx/libScePad/Export.cpp) (libScePad) - the `(int handle, ScePadData* data, int count)` signature comes from [OpenOrbis](https://github.com/OpenOrbis/OpenOrbis-PS4-Toolchain/blob/a2f0d7f282d672e205caaaa648dee0b5dfcde908/include/orbis/Pad.h#L75) and the [GoldHEN gamepad_helper](https://github.com/GoldHEN/GoldHEN_Plugins_Repository/blob/92fbac926f5351bbd0f5fbcf57c44053fc90ccf6/plugin_src/gamepad_helper/include/pad.h#L170) header. PS4 plugins that hook scePadRead call it to fetch the real samples of a standard pad ([example](https://github.com/pozpo/ps4-xbox-series-plugin/blob/14d669fdf408c75cae168b1a2ba8eb2355129a0a/src/hooks.c#L326)), so it reads through scePadRead: the same handle check, argument errors and sample queue. Whether the console's Ext read adds anything for special controllers is unknown, since none opens here
- [scePadVrControllerReadState](../../../core/libs/prx/libScePad/Export.cpp) (libScePad, NID `iA-DdobUen8`) - the name hashes to the imported NID; the `(int handle, void* state)` signature follows [PS5VR](https://github.com/theghostonline/PS5VR/blob/0e408909ce7a39891a2e06eee3438d07a09e11e3/app/src/app_vr.c#L326-L369) (PPSA99177), which passes a PS VR2 Sense controller handle from `scePadOpen` type 3 or 4 and a 0x68-byte state it reads as buttons at 0, stick bytes at 4 and a connected byte at 0x40. The title calls it only after `sceHmd2Initialize` succeeds, which it does not here, so every call throws; the state layout is otherwise unknown
- [scePadSetVibrationMode](../../../core/libs/prx/libScePad/Export.cpp) (libScePad) - modes 0 to 3 are accepted and stored; the meaning of mode 3 is unknown (PPSA21480 calls it with 3 right after `scePadOpen` and aborts on failure; [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/main/src/SharpProspero/Interop/Pad/Pad.cs) names only 1 and 2). The stored mode has no other effect
- [scePadIsRemoteController](../../../core/libs/prx/libScePad/Export.cpp) (libScePad) - the name hashes to NID `fCWdlnmB1Ks`; the signature `(int handle, bool* remote)` comes from PPSA16064, which zeroes a byte, passes its address after `scePadGetControllerInformation` and ignores the result. The error codes follow the other pad calls. Controllers are local devices, so the answer is always false
- [scePadSetAngularVelocityBiasCorrectionState](../../../core/libs/prx/libScePad/Export.cpp) (libScePad) - inferred signature `(int handle, bool enabled)` follows `scePadSetTiltCorrectionState` and `scePadSetAngularVelocityDeadbandState`; an invalid handle returns `PAD_ERROR_INVALID_HANDLE`, and the state controls the gyro bias integrator used by motion fusion
