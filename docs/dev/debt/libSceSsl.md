# libSceSsl technical debt

### Unknown function info

- [sceSslClose, sceSslEnableVerifyOption, sceSslDisableVerifyOption, sceSslSetMinSslVersion, sceSslSetAlpn and sceSslGetAlpnSelected](../../../core/libs/prx/libSceSsl/Export.cpp) (libSceSsl) - imported by PPSA01317 and PPSA07411. They act on the connections of PR #5226 (below) and follow its conventions: an unknown connection, or one whose context was terminated, throws. The signatures follow [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Net/Http.cs): `(int connection)`, `(int connection, uint32 option)` twice, `(int connection, SceSslVersion version)`, `(int connection, const char* protocols)` with the protocols in ALPN wire form (each name preceded by its length byte) and `const uint8* (int connection)`. None was measured on a PS5.
  - The enable and disable calls record which verification bits the title turned on and off (the last call wins for a bit), without assuming the library's default set, which is unknown; any bit is accepted. `sceSslSetMinSslVersion` stores a version from 0 (the library's own floor) to 5 (TLS 1.2), SharpProspero's `SceSslVersion` range, and returns `INVALID_VALUE` (0x8095F007, the value error the console returns from `sceSslGetMemoryPoolStats`) for any other value. `sceSslSetAlpn` stores a well-formed, non-empty wire-form list of at most 0xFFFF bytes and returns `INVALID_VALUE` for a null, empty or truncated one. These settings would steer a handshake; with no TLS transport they only appear in the error `sceSslConnect`, `sceSslRead` and `sceSslWrite` throw, so a later implementation can see what the title asked for.
  - No handshake ever completes, so `sceSslGetAlpnSelected` returns null, the "nothing negotiated" answer. `sceSslClose` marks the connection closed and returns 0, also when called again or before `sceSslConnect`, since no secure channel exists to send a close notification on; afterwards the three transport calls throw that the connection was closed. The console's errors for these states are unknown
- [sceSslGetNotBefore, sceSslGetNotAfter, sceSslGetFingerprint, sceSslGetPem](../../../core/libs/prx/libSceSsl/Export.cpp) (libSceSsl) - from upstream PR #6511 (which supersedes the Vita-style PEM signature of PR #5969). PPSA28002 v01.006.000 calls the PEM reader with four arguments: context, certificate, destination or null, and an in/out length pointer; PPSA12544 also imports it. The context-first validity and fingerprint signatures follow [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/60977b29103452b9681ae10c7a9011d44965bf16/src/SharpProspero/Interop/Net/Http.cs#L258-L305) rather than measured title calls. Validity is the certificate's notBefore/notAfter as an `SceRtcTick` (microseconds since 0001-01-01, as libSceRtc counts). The fingerprint is a digest of the DER certificate; the hash-type numbering 0-5 = MD5, SHA-1, SHA-224, SHA-256, SHA-384, SHA-512 is a guess, unknown types and null outputs return `INVALID_ARG` (0x8095177A). PEM output is Mbed TLS formatting with 64-column lines and the reported length includes the trailing NUL; as with the serial reader, the length is reported before a too-small buffer throws. Unknown contexts and foreign or expired certificates throw, like the other readers. Console error precedence, the PEM length policy and the digest numbering are unmeasured
- [sceSslCreateConnection, sceSslDeleteConnection, sceSslSetVerifyCallback, sceSslConnect, sceSslRead, sceSslWrite](../../../core/libs/prx/libSceSsl/Export.cpp) (libSceSsl) - from upstream PR #5226, imported by `ffmpeg.prx`. There is no TLS client over guest sockets, so a connection only records its context, socket, host and verification callback, and `sceSslConnect`, `sceSslRead` and `sceSslWrite` throw with the host and the socket's peer port where the handshake would start. Signatures follow [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/60977b29103452b9681ae10c7a9011d44965bf16/src/SharpProspero/Interop/Net/Http.cs#L195-L252), which also says the socket stays open after `sceSslDeleteConnection`. An unknown context returns `SSL_ERROR_INVALID_ID` (0x8095F006), as `sceSslGetMemoryPoolStats` does on the console; for an unknown connection, a connection whose context was terminated and a null host the console's codes are unknown, so these throw. Connections live in the library runtime beside the contexts and take their ids from the same counter; the socket is not checked when the connection is created, `sceSslTerm` leaves the context's connections to `sceSslDeleteConnection`, and `sceSslSetVerifyCallback` accepts any callback, null included, and returns 0; none of this is verified on the console. `SSL_ERROR_BEFORE_INIT` (0x8095F001) is never returned. The Mbed TLS backend already linked for certificates would allow a real handshake over the guest socket later
- [libSceSsl](../../../core/libs/prx/libSceSsl/Export.cpp) - libSceSsl certificate/context support uses source-built Mbed TLS 3.6.7 (068ff080b369adfac81509f9b57b2afabaf82dc5), selected under its offered GPL-2.0-or-later license, compatible with AnyPS5's GPLv2 license. It parses DER and PEM certificate chains, validates unencrypted private keys and matches client public/private keys. Loading certificates does not authenticate a TLS peer, validate a remote hostname, or require the client identity to chain to the server CA store; those decisions belong to a future handshake implementation. HTTP remains offline. No proprietary root bundle is included and the host trust store is not imported. Only explicitly loaded authorities appear in CA enumeration. Context-aware reader prototypes are corroborated by orbital commit cc408367da6a6ebbf5ac1ac559fefeadc73b2831's tools/ida/db_types.json and SharpProspero 5dfdb4b0b166e83dc9ae275001afb695f12c7174 Interop/Net/Http.cs; LoadCert and the 0x20 pool-stats/0x10 CA-list layout follow the latter. These are public compatibility references, not PS5 hardware evidence. sceSslGetNameEntryInfo currently emits numeric dotted OIDs and raw ASN.1 string-value octets; the OID is terminated, an extra value terminator is written only if capacity permits, and reported value length excludes that terminator. sceSslGetSerialNumber emits DER INTEGER content octets including leading sign padding, without INTEGER tag/length. Null data buffers support length queries. The exact Sony name/serial formatting, small-buffer length conventions, return codes and whether loading replaces/appends authorities still require hardware confirmation; the implementation appends authorities and replaces a supplied client identity atomically. Unknown error cases throw typed exceptions instead of inventing console error codes; the existing invalid-argument and no-authority constants are retained for established paths. The configured pool size limits requested bytes for real Mbed TLS allocations and returned CA/name data storage, recording current and peak requested bytes. Native allocator headers, Context/CertificateChain/Identity wrappers, registry maps/vectors/shared_ptr control blocks, temporary OID strings and opaque-handle tombstones are host bookkeeping outside this budget; repeated load/free can grow that bookkeeping until Term. No console-exact allocator overhead or up-front reservation is claimed. All exported operations serialize through the library mutex, and the privately linked backend uses the context active on that thread for allocations. Allocation failure or invalid CA/client/key input rolls back newly allocated backend state without replacing prior data. Faults in C++ bookkeeping allocation were structurally reviewed, not runtime fault-injected. CA handle-list snapshots retain their certificates over UnloadCert; DER byte snapshots and name handles are independent copies. Freeing the last retaining list after unload expires its certificate handles. Name/certificate tokens are not reused within a context, preventing stale pointers from resolving to a later object there. Term releases snapshots, copied names, keys and certificates; all associated pointers expire. These ownership choices and post-unload snapshot lifetimes are emulation semantics pending hardware confirmation. Foreign, freed and cross-context CA lists, names and certificates are rejected, except by `sceSslFreeCaCerts`, which clears a foreign list without an error (see below). Validation uses self-generated P-256 root/client fixtures and a matching/mismatching private key, not a retail executable or console dump. Tests cover DER roundtrip, PEM chains including partial parse rejection, multi-valued names, serial sign padding, eight-argument guest ABI, caller-buffer canaries, failed import rollback, pool exhaustion/peak/release, unload snapshots, stale/cross-context ownership and four concurrent contexts. The baseline shared library fails the real pool-stats regression with sceSslGetMemoryPoolStats not implemented; the candidate backend-linked suite passes. Open PR #1119 by TideOPL overlaps pool stats but models zero allocations; its idea is acknowledged and this batch measures real backend/data allocations. Mbed TLS's optional Everest accelerator files are Apache-2.0-only. This build explicitly disables MBEDTLS_ECDH_VARIANT_EVEREST_ENABLED and removes the unused everest target from mbedcrypto link dependencies. The linked library/include/p256-m sources were checked for the offered Apache-2.0 OR GPL-2.0-or-later license; the GPL option is selected. The unmodified dependency tree retains every upstream license notice.
- [sceSslLoadCert, sceSslGetCaList, sceSslFreeCaList, sceSslGetCaCerts, sceSslFreeCaCerts, sceSslUnloadCert](../../../core/libs/prx/libSceSsl/Export.cpp) (libSceSsl) - signatures and layouts follow [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Net/Http.cs). PPSA15508/01.002.000 calls `sceSslLoadCert` with one 1,408-byte PEM CA and null client certificate/key arguments; this confirms that call shape, not console error behavior. Mbed TLS 3.6.7 parses DER/PEM chains and checks an optional client certificate/key pair. Imports are retained per context and committed together; a failed import preserves existing credentials. CA queries return independently owned snapshots; unload clears active credentials while outstanding snapshots remain valid. Appending repeated CA imports, snapshot lifetime across unload, memory overhead and error precedence have not been measured on a PS5. Invalid loads, malformed material, exhausted pools and unsupported keys throw rather than inventing console error codes. No root bundle is shipped; an empty context still returns `NOT_FOUND`. The existing null-list error and unknown-context behavior remain unchanged, and `sceSslFreeCaCerts` still clears a list it did not hand out, or any list of an unknown context, and returns 0. Loading credentials neither starts a TLS connection nor authenticates a peer
