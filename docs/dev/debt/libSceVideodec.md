# libSceVideodec technical debt

### Unknown function info

- [sceVideodecCreateDecoder, sceVideodecDecode, sceVideodecFlush, sceVideodecReset, sceVideodecDeleteDecoder](../../../core/libs/prx/libSceVideodec/Export.cpp) (libSceVideodec) - prototypes from [orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json); the structure layouts, the error codes and the behaviour follow the PS4 library in [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/videodec/videodec.cpp) (`videodec.h`, `videodec_impl.cpp`, `video_utils.cpp`). Every stream is decoded as H.264, as in shadPS4, through libSceVideodec2: the configured codec type is not checked and pictures report codec type 0. Each Decode or Flush returns at most one picture in display order. The picture is written as shadPS4 writes it: NV12 with a pitch of the display width rounded up to 64, the display height rounded up to 16 (the last row repeated below the picture) and the chroma plane after that height; the picture info reports these sizes, the right crop as pitch minus display width and the bottom crop as the rounded height minus display height, and leaves the timing, aspect ratio and colour fields of the AVC info at zero (shadPS4 fills only the colour primaries). Decoding needs no caller memory: the resource info is only checked for its size and the frame scratch is allocated for the configured maximum size (shadPS4's 1920x1080, or 3840x2160 from level 150, when none is given). Null pointers return `ARGUMENT_POINTER` (0x80C1000F; shadPS4 does not check every one), a handle this library did not create or already deleted `HANDLE` (0x80C10003), a picture larger than the frame buffer `FRAME_BUFFER_SIZE` (0x80C1000B; shadPS4 asserts) and a null frame buffer pointer `FRAME_BUFFER_POINTER` (0x80C1000C). Decoder failures and output deeper than 8 bits throw. The console's layout and crop units, and whether it rejects other codec types, are unverified. `sceVideodecQueryResourceInfo` is not exported here, so titles size their frame buffers themselves
