### Functional

- [sceGameLiveStreamingGetCurrentStatus](../../../core/libs/prx/libSceGameLiveStreaming/Export.cpp) (libSceGameLiveStreaming) - the PS4 form: the `(SceGameLiveStreamingStatus*)` signature and the 72-byte layout (on-air flag, spectator count, user id, 60 reserved bytes) follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/615bcba/src/core/libraries/game_live_streaming/gamelivestreaming.h), which reports that no stream is on air. It answers as `sceGameLiveStreamingGetCurrentStatus2` does, with an invalid user id and a throw for a null pointer; shadPS4 leaves the user id 0 and does not check the pointer
- [sceGameLiveStreamingGetSocialFeedbackMessagesCount, sceGameLiveStreamingGetSocialFeedbackMessages, sceGameLiveStreamingClearSocialFeedbackMessages](../../../core/libs/prx/libSceGameLiveStreaming/Export.cpp) (libSceGameLiveStreaming) - the signatures follow [orbital](https://github.com/AlexAltea/orbital/blob/b321fcdbd700cc02da1cb1ad25412781d5ec73c6/tools/ida/db_types.json). With nothing broadcast there are no viewer messages: the count is 0, no message is acquired (the output array is not written) and clearing succeeds. The message types 1 to 3 and `SCE_GAME_LIVE_STREAMING_ERROR_INVALID_PARAM` (0x80A00002) for any other type or a null count follow [KytyPS5](https://github.com/KytyPS5/KytyPS5/blob/13b291f/src/libs/libNet.cpp)'s `sceGameLiveStreamingGetSocialFeedbackMessagesCount`; that the other two check the type the same way, and that `GetSocialFeedbackMessages` rejects a null acquired count with it, is assumed from it, not measured
