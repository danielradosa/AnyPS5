# libSceGameLiveStreaming technical debt

### Functional

- [sceGameLiveStreamingEnableLiveStreaming](../../../core/libs/prx/libSceGameLiveStreaming/Export.cpp) (libSceGameLiveStreaming) - a call outside `sceGameLiveStreamingInitialize` and `sceGameLiveStreamingTerminate` throws, as the console's error for it is unknown ([fpPS4](https://github.com/red-prig/fpPS4/blob/04cefd43e6fddd1ab033e7980cd356d14c964905/src/ps4_libscegamelivestreaming.pas#L18) defines `SCE_GAME_LIVE_STREAMING_ERROR_NOT_INITIALIZED` but does not return it from this call). Otherwise the flag is accepted for both values and changes nothing, as no broadcast is ever on air to allow or block. The signature, `int sceGameLiveStreamingEnableLiveStreaming(const bool isEnableLiveStreaming)`, follows [Orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json#L810) and [fpPS4](https://github.com/red-prig/fpPS4/blob/04cefd43e6fddd1ab033e7980cd356d14c964905/src/ps4_libscegamelivestreaming.pas#L111)
- [libSceGameLiveStreaming](../../../core/libs/prx/libSceGameLiveStreaming/Export.cpp) - native initialization requires exactly 0x4000 heap bytes before checking repeated initialization. Host lifecycle and pointer errors now match the wrapper, but service registration, allocation failures and asynchronous service readiness are not modelled. The host becomes ready immediately after initialization.
- [sceGameLiveStreamingGetCurrentStatus2](../../../core/libs/prx/libSceGameLiveStreaming/Export.cpp) - the supplied module confirms the 72-byte layout and inactive status (user -1, remaining bytes zero). Live service counters, active-user changes and broadcast-resolution conversion are unimplemented.
- [sceGameLiveStreamingGetProgramInfo](../../../core/libs/prx/libSceGameLiveStreaming/Export.cpp) - consumes one output pointer and uses a 4940-byte record. Field semantics remain unresolved; the call returns 0 without writing the record.
- [sceGameLiveStreamingPermitLiveStreaming](../../../core/libs/prx/libSceGameLiveStreaming/Export.cpp) - this and twelve related setting, feedback and message calls (PermitServerSideRecording, SetMaxBitrate, EnableSocialFeedback, SetMetadata, Set/ClearSpoilerTag, Set/ClearPresetSocialFeedbackCommands, ...Description, SetCameraFrameSetting, SetInvitationSessionId, PostSocialMessage) answer locally and store nothing. Not initialized is checked first, then null pointers, following GetCurrentStatus2. Not measured on a PS5: signatures, argument ranges, struct field semantics, a zero count with a null array.
- [sceGameLiveStreamingGetCurrentStatus](../../../core/libs/prx/libSceGameLiveStreaming/Export.cpp) (libSceGameLiveStreaming) - the PS4 form: the `(SceGameLiveStreamingStatus*)` signature and the 72-byte layout (on-air flag, spectator count, user id, 60 reserved bytes) follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/615bcba/src/core/libraries/game_live_streaming/gamelivestreaming.h), which reports that no stream is on air. It answers as `sceGameLiveStreamingGetCurrentStatus2` does: the not-initialized error before `sceGameLiveStreamingInitialize`, the invalid-argument error for a null pointer and otherwise an invalid user id; shadPS4 leaves the user id 0 and does not check the pointer
- [sceGameLiveStreamingGetSocialFeedbackMessagesCount, sceGameLiveStreamingGetSocialFeedbackMessages, sceGameLiveStreamingClearSocialFeedbackMessages](../../../core/libs/prx/libSceGameLiveStreaming/Export.cpp) (libSceGameLiveStreaming) - the signatures follow [orbital](https://github.com/AlexAltea/orbital/blob/b321fcdbd700cc02da1cb1ad25412781d5ec73c6/tools/ida/db_types.json). With nothing broadcast there are no viewer messages: the count is 0, no message is acquired (the output array is not written) and clearing succeeds. The message types 1 to 3 and `SCE_GAME_LIVE_STREAMING_ERROR_INVALID_PARAM` (0x80A00002) for any other type or a null count follow [KytyPS5](https://github.com/KytyPS5/KytyPS5/blob/13b291f/src/libs/libNet.cpp)'s `sceGameLiveStreamingGetSocialFeedbackMessagesCount`; that the other two check the type the same way, and that `GetSocialFeedbackMessages` rejects a null acquired count with it, is assumed from it, not measured
