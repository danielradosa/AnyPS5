# libSceNpFriendListDialog technical debt

### Silent stubs

- [sceNpFriendListDialogOpenA](../../../core/libs/prx/libSceNpFriendListDialog/Export.cpp) (libSceNpFriendListDialog) - there is no PSN friend list to show, so an accepted open finishes the dialog at once, as the authorized-app and commerce dialogs here do; nothing is shown and the parameter block is only checked for null.

### Unknown function info

- [sceNpFriendListDialogInitialize, sceNpFriendListDialogOpenA, sceNpFriendListDialogUpdateStatus, sceNpFriendListDialogGetStatus, sceNpFriendListDialogClose and sceNpFriendListDialogTerminate](../../../core/libs/prx/libSceNpFriendListDialog/Export.cpp) (libSceNpFriendListDialog) - the prototypes (`int32_t (void)`, `int32_t (const param*)`, `SceCommonDialogStatus (void)`) come from [orbital](https://github.com/AlexAltea/orbital/blob/b321fcdbd700cc02da1cb1ad25412781d5ec73c6/tools/ida/db_types.json). No public source implements this dialog, so the state machine and its common-dialog errors follow the NP profile dialog in [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/np/np_profile_dialog/np_profile_dialog.cpp): a second initialize is `ALREADY_INITIALIZED`, open outside the initialized or finished states is `INVALID_STATE` and a null parameter `ARG_NULL`, close is `NOT_INITIALIZED` before initialize and `NOT_RUNNING` when the dialog is not running (always, as it finishes at once), terminate is `NOT_INITIALIZED` before initialize. shadPS4's check that the common dialog system is initialized and not busy is not modelled. Not measured on a console.
- [sceNpFriendListDialogGetResult, sceNpFriendListDialogGetResultA and sceNpFriendListDialogOpen](../../../core/libs/prx/libSceNpFriendListDialog/Export.cpp) (libSceNpFriendListDialog) - names and NIDs are present in the [PS5 3.20 export inventory](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceNpFriendListDialog.c); `GetResult` and `Open` have no public prototype, and orbital gives `GetResultA` only as `int32_t (struct* resultParam)` without the result layout, so nothing can be written to it. They keep throwing; a title that opens the dialog and then reads the result still reaches a throwing call.
