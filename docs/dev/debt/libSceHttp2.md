# libSceHttp2 technical debt

### Silent stubs

- [sceHttp2AuthCacheFlush and sceHttp2RedirectCacheFlush](../../../core/libs/prx/libSceHttp2/Export.cpp) (libSceHttp2) - no credential or redirect is ever stored, as no request reaches the network, so the flushes find nothing. They take a library context, and any other id returns `INVALID_ID` (`0x817B1100`), as for `sceHttp2DeleteCookieBox` and `sceHttp2Term`. Signatures from [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Net/Http2.cs); not measured on a console
- [sceHttp2SetCookieRecvCallback and sceHttp2SetCookieSendCallback](../../../core/libs/prx/libSceHttp2/Export.cpp) (libSceHttp2) - accept callbacks that are never called, as no request is built, sent or answered; like `sceHttp2SetRedirectCallback` they accept any id. Signatures `(int id, callback, void* userArg)` from [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Net/Http2.cs)
- [libSceHttp2](../../../core/libs/prx/libSceHttp2/Export.cpp) - no request reaches the network, so `sceHttp2SetMinSslVersion` has no TLS connection to restrict and its value is ignored, as for `sceHttp2SslEnableOption` and `sceHttp2SslDisableOption`. The three setters validate `id` against the live handle registry and return `SCE_HTTP2_ERROR_INVALID_ID` (`0x817B1100`) for an invalid handle, following [prosper](https://github.com/mattias800/prosper). Whether the console restricts the object kind these setters accept, and what it does with an id from a previous init/term cycle, is unverified, so any live handle kind is accepted and ids are never reused. `sceHttp2Term`, `sceHttp2DeleteTemplate`, `sceHttp2DeleteRequest`, `sceHttp2CreateTemplate`, `sceHttp2CreateRequestWithURL` and `sceHttp2SendRequestAsync` also return the invalid-id error for a handle of the wrong kind or no longer live, following prosper (not measured on a console)

### Unknown function info

- [sceHttp2DeleteCookieBox](../../../core/libs/prx/libSceHttp2/Export.cpp) (libSceHttp2) - imported by PPSA35943's Unity player. The `(int cookieBoxId)` signature follows [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Net/Http2.cs#L215-L217). A box `sceHttp2CreateCookieBox` returned is discarded; an unknown or already deleted id returns the library's invalid-id error (0x817B1100), as [prosper](https://github.com/mattias800/prosper/blob/b1bec57186a0/prosper/src/hle/net/hle_http2.cpp#L512-L523) does; not measured on a console
- [sceHttp2SetResolveRetry](../../../core/libs/prx/libSceHttp2/Export.cpp) (libSceHttp2) - signature `(int id, int32_t retry)` from libSceHttp's `sceHttpSetResolveRetry`; the value is accepted and ignored like the other Http2 settings, since no request reaches the network
- [libSceHttp2 cookie boxes](../../../core/libs/prx/libSceHttp2/Export.cpp) (libSceHttp2) - `sceHttp2CreateCookieBox` takes a machine-sized pool size, requires at least 64 KiB and allocates independently of HTTP contexts. The host reserves the pool with 16 KiB rounding but does not reproduce native cookie-heap bookkeeping, identifier ranges or retained request references. Its delete signature and invalid-ID error are confirmed. `sceHttp2SetRequestNoContentLength` takes only the request id. `sceHttp2CookieFlush` empties a cookie box and answers 0 for any other id
- [libSceHttp2 cookie store](../../../core/libs/prx/libSceHttp2/Cookies.cpp) (libSceHttp2) - errors, limits and accounting are assumed, not measured. Signatures follow [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/main/src/SharpProspero/Interop/Net/Http2.cs). Parsing and matching follow [RFC 6265](https://www.rfc-editor.org/rfc/rfc6265) without a public suffix list; Secure cookies go only to `https` URLs. A cookie the RFC ignores, or larger than `sceHttp2SetCookieMaxSize`, returns 0 unstored. Error codes reuse libSceHttp's low words (OUT_OF_SIZE, UNKNOWN_SCHEME, INVALID_URL) in the `0x817B` facility. A limit of 0 is unlimited; past `sceHttp2SetCookieMaxNum` or `MaxNumPerDomain` the least recently used cookie is evicted and counted in `removedNum`. Stats count name plus value bytes. `sceHttp2GetCookie` writes `a=1; b=2` with a terminator that `required` counts, and only `required` for a null buffer; the pool size is not enforced


- [sceHttp2CookieExport, sceHttp2CookieImport and sceHttp2GetCookieBox](../../../core/libs/prx/libSceHttp2/Export.cpp) (libSceHttp2) - still throw, declared without parameters; the cookie export format is unknown. Names from the [PS5 3.20 export table](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceHttp2.c)
### Functional

- [libSceHttp2 asynchronous requests](../../../core/libs/prx/libSceHttp2/Export.cpp) (libSceHttp2) never reach the network: `sceHttp2SendRequestAsync` checks that the id is a live request (`INVALID_ID` otherwise), runs the synchronous `sceHttp2SendRequest` and queues a completion with its result (the library's network error) for that request, then triggers the user event named by the kqueue option (equeue at offset 0, event id at 8, user data at 16, layout inferred from PPSA17221). Completions are kept per request in submission order and dropped with the request, its template or its context; `sceHttp2WaitAsync` returns the oldest one. The completion's `event_type` value is unknown and left 0. PPSA17221 completes its request object only after `sceHttp2SendRequestAsync` returns, and its handler for a synchronous failure calls `shared_from_this` before that, so a send must not fail synchronously.
  - A null kqueue option queues the completion without an event, for a title that only waits with `sceHttp2WaitAsync`: PPSA15508 passes null kqueue and extra options (original VA 0xb63931), then waits with a 24-byte result and a 2,000,000 timeout and checks the result at offset 8. When the user event cannot be triggered (an equeue or event that does not exist), the completion is withdrawn and the kernel's error (`EBADF` or `ENOENT`) is returned; whether the console checks the option this way, or with its own error, is unverified.
  - `sceHttp2WaitAsync` returns the library's null-pointer error (0x817B1225, measured for `sceHttp2GetMemoryPoolStats`) for a null result and `INVALID_ID` for an id that is not a live request. Every operation completes at submission, so a wait with nothing pending could never be satisfied: it throws instead of blocking, as the console's error or wait for that case is unknown, and the timeout argument is not used. A non-null reserved last argument of either call throws, as its meaning and error are unknown
- [libSceHttp2 request options](../../../core/libs/prx/libSceHttp2/Export.cpp) - not measured on a console: accepted handle kinds, flag defaults (both enabled), template-to-request copying of flags, headers and callbacks, and case-insensitive header names follow [prosper](https://github.com/mattias800/prosper/blob/b1bec57186a0/prosper/src/hle/net/hle_http2.cpp#L245-L555). The flag getters take `(int id, int* enable)` like libSceHttp's; `sceHttp2SetAuthInfoCallback` and `sceHttp2SetPreSendCallback` take `(int id, callback, void* userArg)` as in [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Net/Http2.cs) and, for the pre-send callback, [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/network/http2.cpp) (PS4); the pre-send callback type is unknown and kept opaque. No request is sent, so recorded headers and callbacks are never used. Null names, values and out-pointers and header modes other than 0 or 1 throw
- [WebSocket ping settings](../../../core/libs/prx/libSceHttp2/Export.cpp): both setters take a 32-bit request ID and a 32-bit interval/timeout in microseconds, confirmed by the timer consumer and its clock conversion. The protected implementations remain unchanged.
