# libSceWebBrowserDialog technical debt

### Silent stubs

- [libSceWebBrowserDialog](../../../core/libs/prx/libSceWebBrowserDialog/Export.cpp) - `sceWebBrowserDialogOpen` and `sceWebBrowserDialogOpenForPredeterminedContent` run the common-dialog state machine without displaying an interactive browser, and `sceWebBrowserDialogGetResult` reports that the user cancelled. Minecraft Bedrock (PPSA17221) imports `sceWebBrowserDialogOpenForPredeterminedContent` (#5744). The 424-byte allow-list parameter and its twenty optional address pointers are validated, but address filtering is not modelled without an interactive browser. Main open-parameter validation remains incomplete.

### Functional

- [Web browser dialog](../../../core/libs/prx/libSceWebBrowserDialog/Export.cpp) (libSceWebBrowserDialog) shows nothing: `sceWebBrowserDialogOpen` and `sceWebBrowserDialogOpenForPredeterminedContent` finish at once and the result reports that the user canceled; the allow-list of the predetermined content is validated but not applied. Cookies set with `sceWebBrowserDialogSetCookie` are kept until `sceWebBrowserDialogResetCookie`, but no page is loaded, so they are never sent

### Unknown function info

- [sceWebBrowserDialogSetCookie, sceWebBrowserDialogResetCookie](../../../core/libs/prx/libSceWebBrowserDialog/Export.cpp) (libSceWebBrowserDialog) - the signatures follow [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/main/src/SharpProspero/Interop/Dialog/WebBrowserDialog.cs) and the PS4 prototypes in [orbital](https://github.com/AlexAltea/orbital/blob/master/tools/ida/db_types.json), which agree, and the parameter layouts match the system library. The 280-byte cookie param (size, url, cookie, 256 reserved bytes) and the 2048- and 4096-byte url and cookie buffers also appear in the [ps5debug headers](https://github.com/someguythatmods/PS5Debug-CleanELF/blob/master/Vanilla/include/imports.h); the 264-byte reset param (size, 256 reserved bytes) is SharpProspero's only. No reference gives the error codes: before `sceWebBrowserDialogInitialize` the calls return `NOT_INITIALIZED` and a null param returns `ARG_NULL`, as the other calls do, which is not confirmed for the cookie calls; a param whose size does not match, a null url or cookie and a string that does not end within its buffer throw
- [sceWebBrowserDialogGetEvent, sceWebBrowserDialogNavigate, sceWebBrowserDialogSetZoom](../../../core/libs/prx/libSceWebBrowserDialog/Export.cpp) (libSceWebBrowserDialog) - their names and NIDs are in the [PS5 3.20 export inventory](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceWebBrowserDialog.c); the no-parameter prototypes follow [shadPS4 `webbrowserdialog.cpp`](https://github.com/shadps4-emu/shadPS4/blob/f68923fe807f657348e6719ce658bcbd0a2b1c72/src/core/libraries/web_browser_dialog/webbrowserdialog.cpp#L23-L85) and are not measured on a console. They are declared without parameters solely to resolve known imports; this is not an ABI claim, and every call throws.
