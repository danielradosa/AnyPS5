# libSceVoice technical debt

### Unknown function info

- [sceVoiceWriteToIPort](../../../core/libs/prx/libSceVoice/Export.cpp) (libSceVoice) - data written to an input port that is not connected is consumed and `size` is left as passed; writing to a connected input port throws, since data is not routed to output ports. The frame gap count is ignored. Console behavior is unverified
- [sceVoiceGetResourceInfo](../../../core/libs/prx/libSceVoice/Export.cpp) (libSceVoice) - the (info) signature and the 8-byte layout of four 16-bit port maxima (IN_VOICE, OUT_VOICE, IN_DEVICE, OUT_DEVICE) follow [fpPS4](https://github.com/red-prig/fpPS4/blob/main/src/ps4_libscevoice.pas) (PS4), whose values 2, 4, 0, 5 are the port type numbers rather than limits. The reported 7, 7, 1, 1 are the PS Vita FW 3.60 limits from [vita-headers](https://github.com/vitasdk/vita-headers/blob/master/include/psp2/voice.h), whose libSceVoice uses the same 0x804E08xx error codes; the PS5 limits are unknown and sceVoiceCreatePort does not enforce them. The Vita structure has a fifth field (64 ports in total), which is not written. Like the other calls, it throws before sceVoiceInit
- [sceVoiceResetPort](../../../core/libs/prx/libSceVoice/Export.cpp) (libSceVoice) - the `(uint32_t portId)` signature is the PS Vita one in [VitaSDK](https://github.com/vitasdk/vita-headers/blob/ae5808f3105c42fa3373ba4ab64ab54e2e3ca848/include/psp2/voice.h#L503-L514) and the PS3 `cellVoiceResetPort` in [RPCS3](https://github.com/RPCS3/rpcs3/blob/be69c054eeac57e2e671697a463473d37fe5a7b2/rpcs3/Emu/Cell/Modules/cellVoice.cpp#L493-L510); that the PS5 library takes the same argument is assumed. A reset clears a port's buffered data, and ports here buffer nothing (`sceVoiceReadFromOPort` returns 0 bytes, and `sceVoiceWriteToIPort` drops the data of an unconnected input port and throws for a connected one), so it only checks that the library is initialized and the port exists, as RPCS3 does, and keeps the port's connections, volume and mute flag. An uninitialized library or an unknown port throws like the other port calls; the console's error codes are not measured. PPSA23566 imports it
- [sceVoiceEnableChat, sceVoiceDisableChat](../../../core/libs/prx/libSceVoice/Export.cpp) (libSceVoice) take no arguments and return 0, following [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Audio/AudioOut2.cs#L460-L464) and the `sceAudioOut2EnableChat` model. The host mixes no chat audio, so the calls only record whether chat audio is enabled and fail when the library is not initialized. Console error codes and chat session requirements are unverified. PPSA23566 and PPSA34015 import them
