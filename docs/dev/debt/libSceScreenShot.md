# libSceScreenShot technical debt

### Silent stubs

- [sceScreenShotDisableNotification, sceScreenShotEnableNotification, sceScreenShotSetParam](../../../core/libs/prx/libSceScreenShot/Export.cpp) (libSceScreenShot) - return 0 and change nothing: the notification and the photo parameters belong to system screenshots, which are never taken, as for the overlay image below. The `int32_t (void)` notification prototypes are [OpenOrbis](https://github.com/OpenOrbis/OpenOrbis-PS4-Toolchain/blob/0a1aaf9dd4a92695538bdeb09fb056d06dd11725/include/orbis/ScreenShot.h)'s and `sceScreenShotSetParam(const param*)` is [orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json)'s; the parameter is not read, its layout and the errors for a null or malformed one are unknown
- [sceScreenShotIsVshScreenCaptureDisabled](../../../core/libs/prx/libSceScreenShot/Export.cpp) (libSceScreenShot) - returns 0, capture not disabled: no system software here disables screen capture. The `int32_t (void)` prototype is [OpenOrbis](https://github.com/OpenOrbis/OpenOrbis-PS4-Toolchain/blob/0a1aaf9dd4a92695538bdeb09fb056d06dd11725/include/orbis/ScreenShot.h)'s; that the result is a flag rather than an error code is read from the name, not measured
- [sceScreenShotSetOverlayImage, sceScreenShotSetOverlayImageWithOrigin](../../../core/libs/prx/libSceScreenShot/Export.cpp) (libSceScreenShot) - prototypes `(const char* filePath, int32_t offsetX, int32_t offsetY)` and `(filePath, marginX, marginY, origin)` from [orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json); the [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/screenshot/screenshot.cpp) PS4 functions of the same names return 0. The image is laid over system screenshots, which are never taken, so both return 0 without opening the file, like [sceShareSetScreenshotOverlayImage](../../../core/libs/prx/libSceShare/Export.cpp). The origin values and the errors for a missing file or a null path are unknown

### Unknown function info

- [sceScreenShotCapture, sceScreenShotGetAppInfo, sceScreenShotGetDrcParam and sceScreenShotSetDrcParam](../../../core/libs/prx/libSceScreenShot/Export.cpp) (libSceScreenShot) - names and NIDs are present in the [PS5 3.20 export inventory](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceScreenShot.c), but no credible prototypes were found ([OpenOrbis](https://github.com/OpenOrbis/OpenOrbis-PS4-Toolchain/blob/0a1aaf9dd4a92695538bdeb09fb056d06dd11725/include/orbis/ScreenShot.h) declares the first two as `void` without parameters and [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/screenshot/screenshot.cpp) only logs all four). They are declared without parameters solely to resolve known imports; this is not an ABI claim, and every call throws
- [sceScreenShotDisable, sceScreenShotEnable, sceScreenShotIsDisabled](../../../core/libs/prx/libSceScreenShot/Export.cpp) (libSceScreenShot) - the `int32_t (void)` prototypes are [orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json)'s (`Disable`, `Enable`) and [OpenOrbis](https://github.com/OpenOrbis/OpenOrbis-PS4-Toolchain/blob/0a1aaf9dd4a92695538bdeb09fb056d06dd11725/include/orbis/ScreenShot.h)'s (`IsDisabled`). `Disable` and `Enable` set a process-wide flag that starts enabled and only `IsDisabled` reads, as no system screenshot is ever taken; `IsDisabled` returns 1 while disabled and 0 otherwise. That encoding is read from the name, and the console's answer for repeated calls is not measured
