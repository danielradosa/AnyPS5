# libSceAudio3d technical debt

### Silent stubs

- [libSceAudio3d](../../../core/libs/prx/libSceAudio3d/Export.cpp) - the port produces no sound: objects can be reserved and `sceAudio3dObjectSetAttributes` accepts their attributes, but the library has no bed exports or mixing to give them audio, the attributes have no effect and `sceAudio3dPortPush` only paces the queue at `granularity` samples per frame at 48 kHz. `sceAudio3dPortSetAttribute` accepts the late reverb level and the downmix spread attributes and ignores them. `sceAudio3dObjectSetAttributes` validates the port, the reserved object and the attribute array (an object id that was never reserved returns the invalid-object error, while shadPS4 returns success for it and the error only for a released object; neither is measured on a console), treating the reset-state attribute as valid with a null value and requiring a value for the others; the attribute identifiers and the value of each are not interpreted. `sceAudio3dPortFlush` drops the frames queued by `sceAudio3dPortAdvance` instead of mixing and submitting them to an output, as there is no output

### Unknown function info

- [sceAudio3dPortOpen](../../../core/libs/prx/libSceAudio3d/Export.cpp) (libSceAudio3d) - buffer modes 0 and 1 (also selected by the 0x10 and 0x18 parameter sizes) and 3 beds depend on an SDK version check in the module ([prosper](https://github.com/mattias800/prosper)) and throw. A repeated `sceAudio3dInitialize` (`NOT_READY` in shadPS4, 0 in prosper) and `sceAudio3dPortAdvance` on a full queue (`NOT_READY` in shadPS4, unhandled in KytyPS5) throw too
- [sceAudio3dPortCreate and sceAudio3dPortDestroy](../../../core/libs/prx/libSceAudio3d/Export.cpp) (libSceAudio3d) - the `(granularity, rate, reserved, port id*)` and `(port id)` signatures follow [orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json#L46-L47) and [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Audio/Audio3d.cs#L133-L137). sceAudio3dPortCreate follows [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/audio3d/audio3d.cpp#L793-L810) (PS4): a null port id or a nonzero reserved value returns `0x80EA0004`, then it opens the port through sceAudio3dPortOpen for the system user with a 0x10-byte parameter block, which returns `NOT_READY` before initialization and otherwise throws, as that block selects buffer mode 0. No source has a body for sceAudio3dPortDestroy: a port that is not open returns `INVALID_PORT`, as sceAudio3dPortClose does, and destroying a port opened by sceAudio3dPortOpen throws, since only sceAudio3dPortCreate is known to pair with it
- [sceAudio3dPortGetState, sceAudio3dPortFreeState, sceAudio3dPortQueryDebug and sceAudio3dPortGetStatus](../../../core/libs/prx/libSceAudio3d/Export.cpp) (libSceAudio3d) - the signatures follow [orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json#L49-L57) and, for sceAudio3dPortGetStatus, [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Audio/Audio3d.cs#L123-L125). The debug state and status layouts, the debug query values and their buffer formats are unknown, so a port that is not open returns `INVALID_PORT`, as the other port calls do, and an open port throws without writing the output. sceAudio3dPortFreeState releases what sceAudio3dPortGetState hands out, which never happens here, so it always throws
- [sceAudio3dPortGetAttributesSupported](../../../core/libs/prx/libSceAudio3d/Export.cpp) (libSceAudio3d) - the supported list (late reverb level, downmix spread radius, downmix spread height aware) is inferred from the attributes `sceAudio3dPortSetAttribute` accepts; its order and the count written when the caller capacity is smaller are unverified. [shadPS4](https://github.com/shadps4-emu/shadPS4) returns object attributes (PCM, gain...) instead, prosper and KytyPS5 have no body
- [sceAudio3dObjectReserve](../../../core/libs/prx/libSceAudio3d/Export.cpp) (libSceAudio3d) - object ids, the `max_objects` limit and the checks of `sceAudio3dObjectReserve` and `sceAudio3dObjectUnreserve` follow [shadPS4](https://github.com/shadps4-emu/shadPS4) (PS4), the only reference with a body: ids count up from 1 per port, skipping 0, 0xFFFFFFFF and ids in use, and a failed reserve writes 0xFFFFFFFF
- [sceAudio3dCreateSpeakerArray, sceAudio3dDeleteSpeakerArray, sceAudio3dGetSpeakerArrayMemorySize, sceAudio3dGetSpeakerArrayMixCoefficients, sceAudio3dGetSpeakerArrayMixCoefficients2](../../../core/libs/prx/libSceAudio3d/Export.cpp) (libSceAudio3d) - the 0x20-byte parameter block `{positions, num_speakers, is_3d, buffer, size}`, the 16-speaker limit and the checks follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/audio3d/audio3d_openal.cpp#L950-L1083) (PS4): a null handle, parameter block or position array, a speaker count of 0 or above 16, a null coefficient array, a coefficient count other than the speaker count and a handle that was not created or was deleted return `0x80EA0004`. The MixCoefficients2 arguments come from an [older shadPS4](https://github.com/shadps4-emu/shadPS4/blob/cfbd8691261e4d0b06a6ed29ec68c333ef6cc8d1/src/core/libraries/audio3d/audio3d.cpp#L161-L174) and [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Audio/Audio3d.cs#L101). shadPS4 keeps the arrays itself and computes its own gains; here the array is built in the caller's buffer by [sceAudioOut2SpeakerArrayCreate](../../../core/libs/prx/libSceAudioOut/src/AudioOut2SpeakerArray.cpp) without VBAP correction, the memory size and gains are those of `sceAudioOut2GetSpeakerArrayMemorySize` and `sceAudioOut2GetSpeakerArrayCoefficients`, and MixCoefficients is MixCoefficients2 without height awareness or a downmix spread radius. A missing, smaller or misaligned buffer, a memory size query for a speaker count outside 1 to 16, a nonzero spread and a nonzero downmix spread radius throw: the console's results are unknown
