# libSceVideoRecordingP technical debt

### Silent stubs

- [libSceVideoRecordingP](../../../core/libs/prx/libSceVideoRecordingP/Export.cpp) has no recorder: `sceVideoRecordingQueryMemSize`, `sceVideoRecordingOpen` and their `2` forms (the [orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json) prototypes `sceVideoRecordingQueryMemSize2(const param*)` and `sceVideoRecordingOpen2(path, param, heap, int32_t heapSize)`, the same as the first forms) return `SCE_VIDEO_RECORDING_ERROR_UNSUPPORTED` (0x80A80008), so no recording is ever open. `sceVideoRecordingGetStatus` reports the recording state, which stays `SCE_VIDEO_RECORDING_STATUS_NONE` (0), and `sceVideoRecordingStart`, `sceVideoRecordingStop` and `sceVideoRecordingClose` return `SCE_VIDEO_RECORDING_ERROR_INVALID_STATE` (0x80A80006, named in [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/f510f9aef273f820d5ba12d78786008b66c817b2/src/core/libraries/video_recording/video_recording_error.h)) without a recording. The transitions an open recording would take (Start to running, 1; Stop from running to paused, 2; Close back to none, with the statuses from fpPS4) are assumed and cannot be reached.

### Unknown function info

- [sceVideoRecordingGetInfo, sceVideoRecordingSetInfo](../../../core/libs/prx/libSceVideoRecordingP/Export.cpp) support native validation and errors before a recording context exists. No recording is ever opened and `sceVideoRecordingInitialize` remains unimplemented; live recording queries, control and volume changes are unavailable.
- [sceVideoRecordingOpen, sceVideoRecordingQueryMemSize, sceVideoRecordingGetStatus](../../../core/libs/prx/libSceVideoRecordingP/Export.cpp) (libSceVideoRecordingP) - PS4 parity: the argument order and the 32-bit heap size follow the PS4 `sceVideoRecordingOpen2` and `sceVideoRecordingQueryMemSize2` prototypes in [orbital](https://github.com/AlexAltea/orbital/blob/b321fcdbd700cc02da1cb1ad25412781d5ec73c6/tools/ida/db_types.json#L2389-L2395) and [fpPS4](https://github.com/red-prig/fpPS4/blob/7adf9077705fd47988967fc14f5d291cf4665eca/src/ps4_libscevideorecording.pas#L128-L165). Status `NONE` (0) is from fpPS4 and [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/f510f9aef273f820d5ba12d78786008b66c817b2/src/core/libraries/video_recording/video_recording.h#L32-L36); the name `UNSUPPORTED` for 0x80A80008 is only in [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/f510f9aef273f820d5ba12d78786008b66c817b2/src/core/libraries/video_recording/video_recording_error.h), and a [PS5 kernel log](https://github.com/Phi1ow/360-rcomp/blob/c3640f46f036753b1b43aecbaf18aaced43e4f08/evidence/ps5-f414844/revalidation-libkernel/3-m3-program/klog.txt#L807-L808) shows the system recorder getting it from `sceVideoRecordingOpenByRAFeatureId`. The memory size formula, the errors for a null path or param (they throw) and the console results of Start, Stop and Close with no recording open are unknown
- [iQS6DUtLybE](../../../core/libs/prx/libSceVideoRecordingP/Export.cpp) (libSceVideoRecordingP) - unknown name and signature
- [_sceVideoRecordingQueryParam_nid_postfix](../../../core/libs/prx/libSceVideoRecordingP/Export.cpp): the supplied module reads a 64-bit size and writes a 32-bit mode at offset 12 for sizes at least 16, plus a 32-bit option at offset 28 for sizes at least 64. Mode/option meanings remain unresolved; the protected implementation is unchanged.
- [sceVideoRecordingCloseByHandle, sceVideoRecordingGetInfoByHandle](../../../core/libs/prx/libSceVideoRecordingP/Export.cpp) - native handles are context pointers. Recording state and per-handle queries remain unimplemented.
- [sceVideoRecordingCopyBGRAtoNV12](../../../core/libs/prx/libSceVideoRecordingP/Export.cpp) (libSceVideoRecordingP) - the destination, source, 32-bit width and height arguments are confirmed; converts tightly packed BGRA8 to tightly packed NV12 using limited-range BT.601 coefficients, averages RGB over each available 2x2 block for chroma, ignores alpha, and supports odd dimensions with rounded-up chroma dimensions. The format layout, color matrix, range and rounding have not been measured on a PS5; callers must provide buffers large enough for `width * height * 4` source bytes and `width * height + 2 * ceil(width / 2) * ceil(height / 2)` destination bytes.
- [sceVideoRecordingGetSupportInfo, sceVideoRecordingGetVideoOutMode](../../../core/libs/prx/libSceVideoRecordingP/Export.cpp) - GetSupportInfo writes an 18-byte payload whose fields remain unresolved. GetVideoOutMode takes a four-byte output confirmed by the native recording assembly and Avcap2 IPC descriptor; the mode values remain unresolved. Both exports remain unimplemented.
- [sceVideoRecordingInit, sceVideoRecordingTerm](../../../core/libs/prx/libSceVideoRecordingP/Export.cpp) (libSceVideoRecordingP) - parameterless initialization and termination stubs; return 0, as the firmware does
- [sceVideoRecordingInitialize](../../../core/libs/prx/libSceVideoRecordingP/Export.cpp): the native initializer consumes no caller arguments; the former optional parameter is not read by the Avcap2 initializer or recording setup. Its unused parameter slot is retained because the protected body references it.
- [sceVideoRecordingOpen, sceVideoRecordingOpen2](../../../core/libs/prx/libSceVideoRecordingP/Export.cpp) - the 32-byte and 40-byte parameter variants, four argument registers and 32-bit heap size are recovered. Mode, output mode, option and format semantics remain incomplete. QueryHddSize2 returns a signed 64-bit size or error; recording and sizing exports remain unimplemented.
- [sceVideoRecordingSendCommand](../../../core/libs/prx/libSceVideoRecordingP/Export.cpp) (libSceVideoRecordingP) - command dispatch signature taking integer command ID and parameter pointer; unverified, returns 0 as the firmware does
- [Handle and support queries](../../../core/libs/prx/libSceVideoRecordingP/Export.cpp) - native recording handles are context pointers, and GetSupportInfo writes 18 bytes. Support payload field semantics remain incomplete. RestModeProcessStart, RestModeProcessGetStatus and SendCommand consume no caller arguments in the supplied native module; their existing unused parameter slots remain because the protected bodies reference those parameter names.
