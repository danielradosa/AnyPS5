# libSceRudp technical debt

### Silent stubs

- [sceRudpProcessEvents and sceRudpNetFlush](../../../core/libs/prx/libSceRudp/Export.cpp) (libSceRudp) - there is no reliable-UDP stack on the host, and every `sceRudpWrite`, `sceRudpRead` and `sceRudpGetStatus` call here reports a reset or idle context without queueing data, so no context ever holds pending data to process or send; both calls return success after `sceRudpInit` and `RUDP_ERROR_NOT_INITIALIZED` before it, as [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/rudp/rudp.cpp) returns OK from its stubs. PPSA03490 calls `sceRudpProcessEvents(0)` followed by `sceRudpNetFlush()` from its P2P service thread and ignores the first result; whether the real calls take parameters is unknown
- [sceRudpActivate](../../../core/libs/prx/libSceRudp/Export.cpp) (libSceRudp) - there is no reliable-UDP stack on the host to activate, so it returns success without doing anything, as [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/rudp/rudp.cpp) does for its own `sceRudpActivate`. PPSA01325 calls it with no arguments during start-up; what the console activates, and whether it reports an error before `sceRudpInit`, is unverified

### Unknown function info

- [sceRudpGetStatus](../../../core/libs/prx/libSceRudp/Export.cpp) - PPSA01521 passes an output pointer and byte count `0xF8`. Measured on a PS5 (firmware 13.60): the status is 0xF8 bytes; before `sceRudpInit` every call returns `RUDP_ERROR_NOT_INITIALIZED`, and after it a null pointer or a byte count of 0 or above 0xF8 returns `RUDP_ERROR_INVALID_ARGUMENT`. The layout matches `SceRudpStatus` in [Vita3K](https://github.com/AndnixSH/Vita3K-PS-Vita-OS-Fork/blob/master/vita3k/modules/SceRudp/SceLibRudp.cpp) with `currentContexts` at 0x64 and `allocs`, `frees`, `memCurrent` and `memPeak` at 0xC8 to 0xD4. Only `currentContexts` and the received UDP bytes and packets that `sceRudpNetReceived` counts are reported: the other traffic counters stay 0 because nothing is sent, and the allocator counters stay 0 because the library does not allocate from the title's pool (the console reports 6 allocations and 0x1260 bytes right after `sceRudpInit`, and 4 more allocations and 0x3F0 bytes per context). The console also writes `currentContexts` and the allocator counters when the byte count is smaller than their offset; only the requested bytes are written here.
- [sceRudpGetMaxSegmentSize](../../../core/libs/prx/libSceRudp/Export.cpp) (libSceRudp) - measured on a PS5 (firmware 13.60) in #3073: before `sceRudpInit` it returns `RUDP_ERROR_NOT_INITIALIZED` and leaves the value untouched, also for a null pointer; after it a null pointer returns `RUDP_ERROR_INVALID_ARGUMENT` and a valid one gets 1410 with result 0. It reports the size last given to `sceRudpSetMaxSegmentSize`, 1410 until then. The `uint16_t*` parameter is inferred: the measurement does not show how many bytes the console writes, PPSA03490 passes a pointer to a 16-bit value and [RPCS3](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/Emu/Cell/Modules/cellRudp.cpp) declares the PS3 `cellRudpSetMaxSegmentSize(u16 mss)`, so only 16 bits are written
- [sceRudpEnableInternalIOThread2, sceRudpGetOption, sceRudpGetRemoteInfo and sceRudpNetReceived](../../../core/libs/prx/libSceRudp/Export.cpp) (libSceRudp) - imported by PPSA06888's bundled `Media/Plugins/SceRudp.prx`. The signatures are the PS4 ones in [orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json): `(uint32 stackSize, uint32 priority, SceKernelCpumask affinityMask)`, `(int ctxId, int option, void* optVal, size_t optLen)`, `(int ctxId, SceNetSockaddr* addr, SceNetSocklen_t* addrLen, uint16* vport)` and `(int soc, const uint8* data, size_t dataLen, const SceNetSockaddr* from, SceNetSocklen_t fromLen)`; `sceRudpSetOption` now takes the `size_t` length of the same reference. None was measured on a PS5.
  - `sceRudpEnableInternalIOThread2` answers like `sceRudpEnableInternalIOThread`: `NOT_INITIALIZED` before `sceRudpInit`, success after it. No I/O thread is started, as none has anything to send or receive, and the stack size, priority and affinity mask are not checked.
  - Options follow the PS3/Vita numbering of [RPCS3](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/Emu/Cell/Modules/cellRudp.h) (1 to 11 and 14 to 19), and the defaults and 4-byte values follow the [Vita3K fork](https://github.com/AndnixSH/Vita3K-PS-Vita-OS-Fork/blob/c86ac732bc811057e690bed280c5076bdf95385e/vita3k/modules/SceRudp/SceLibRudp.cpp) (maximum payload 1346, buffers 65536, delivery and order critical 1, non-blocking 1, connection timeout 60000, aggregation timeout 30, the rest 0). Each context keeps its own values: `sceRudpSetOption` stores a 4-byte value and `sceRudpGetOption` returns it. An option outside that list returns `INVALID_OPTION` (0x80770005), a null value or a length other than 4 `INVALID_ARGUMENT`, as in the Vita3K fork; `sceRudpSetOption` accepted and ignored any option before. The PS5 defaults, option list and value sizes are unverified. Static inspection of PPSA06888 v01.001.008's bundled Unity transport shows its context-set constructor configuring IDs 2, 3, 5 and 6; runtime usage and other paths remain unverified.
  - `LAST_ERROR` (14) reports the last error of a context operation: a failed `sceRudpSetOption`, the `CONN_REFUSED` of `sceRudpInitiate` and the `CONN_RESET` of `sceRudpWrite` and `sceRudpRead`, as the Vita3K fork records them. Reading it does not clear it.
  - No context is ever connected, so `sceRudpGetRemoteInfo` checks its arguments (`INVALID_ARGUMENT` for a negative context id or a null output, as `sceRudpGetSizeReadable` treats a negative id) and the context, then returns `NOT_ACCEPTABLE`, the error the library already gives for a query that needs a connection, without writing the outputs. The console's answer for a context with no peer is unknown.
  - `sceRudpNetReceived` takes a datagram the title received on its own socket. A negative socket returns `INVALID_SOCKET` (0x80770019), and a null or empty datagram or a null or shorter-than-`SceNetSockaddrIn` source `INVALID_ARGUMENT`. A valid datagram is counted in the `rcvdUdpBytes` (0x08) and `rcvdUdpPackets` (0x14) fields that `sceRudpGetStatus` reports, at the offsets of the Vita3K `SceRudpStatus` the measured status size matches, and is then dropped: no context can accept a connection, and the RUDP wire format is not parsed, so a malformed datagram is not told apart. The counters restart at `sceRudpEnd`
- [sceRudpPollCreate, sceRudpPollControl, sceRudpPollWait, sceRudpPollDestroy](../../../core/libs/prx/libSceRudp/Export.cpp) (libSceRudp) - unverified on a PS5; imported by PPSA31327 and not called before the main menu. The signatures, the 8-byte `SceRudpPollEvent`, the operations (1 add, 2 modify, 3 remove) and the argument checks follow the PS Vita library in [Vita3K](https://github.com/AndnixSH/Vita3K-PS-Vita-OS-Fork/blob/master/vita3k/modules/SceRudp/SceLibRudp.cpp), and the error codes match [RPCS3](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/Emu/Cell/Modules/cellRudp.h). Vita3K leaves `sceRudpPollDestroy` unimplemented, so `int sceRudpPollDestroy(int pollId)` and its checks are inferred. No context can connect, so no event is ever reported: `sceRudpPollWait` returns 0 when its timeout elapses, also for an empty poll, where Vita3K returns at once
- [sceRudpAccept and sceRudpListen](../../../core/libs/prx/libSceRudp/Export.cpp) (libSceRudp) - names and NIDs are present in the [PS5 3.20 export inventory](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceRudp.c), but no credible prototypes were found. They are declared without parameters solely to resolve known imports; this is not an ABI claim.
- [sceRudpFlush and sceRudpGetLocalInfo](../../../core/libs/prx/libSceRudp/Export.cpp) (libSceRudp) - [orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json) gives the PS4 prototypes `int sceRudpFlush(int ctxId)` and `int sceRudpGetLocalInfo(int ctxId, int* soc, SceNetSockaddr* addr, SceNetSocklen_t* addrLen, uint16_t* vport, uint8_t* muxMode)`, but both still throw: no context ever has a connection, and whether flushing one answers 0, `NOT_ACCEPTABLE` (as `sceRudpGetSizeWritable` here) or `CONN_RESET` (as `sceRudpWrite` here) is unknown; no context is bound to a socket of the title, so there is no socket, address or multiplexing mode to report.
- [sceRudpSetMaxSegmentSize](../../../core/libs/prx/libSceRudp/Export.cpp) (libSceRudp) - any value is accepted, and the size survives `sceRudpEnd`, as in the PS Vita library of the [Vita3K fork](https://github.com/AndnixSH/Vita3K-PS-Vita-OS-Fork/blob/c86ac732bc811057e690bed280c5076bdf95385e/vita3k/modules/SceRudp/SceLibRudp.cpp), whose checks it follows: `NOT_INITIALIZED` before `sceRudpInit`, `NOT_ACCEPTABLE` (0x80770011) while any context exists, otherwise the size is kept for `sceRudpGetMaxSegmentSize`. It changes nothing else, as nothing is segmented. The `(uint16_t mss)` prototype is the PS4 one in [orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json) and the PS3 one in [RPCS3](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/Emu/Cell/Modules/cellRudp.cpp). Not measured on a PS5
- [sceRudpPollCancel](../../../core/libs/prx/libSceRudp/Export.cpp) (libSceRudp) - the `(int pollId)` prototype is the PS4 one in [orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json); the Vita3K fork leaves it unimplemented. It checks its argument as `sceRudpPollDestroy` does (`NOT_INITIALIZED`, `INVALID_ARGUMENT` for a negative id, `INVALID_POLL_ID`) and wakes every `sceRudpPollWait` blocked on that poll, which then returns `CANCELLED` (0x80770014, from the error list in [RPCS3](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/Emu/Cell/Modules/cellRudp.h)). A cancel with no wait in progress is not remembered: a later wait blocks for its timeout as before. Which code the console's cancelled wait returns, and whether it remembers a cancel, is unverified
