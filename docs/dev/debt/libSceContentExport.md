# libSceContentExport technical debt

### Functional

- [Content export sessions](../../../core/libs/prx/libSceContentExport/Export.cpp): the host has no media library, so `sceContentExportFromDataWithThumbnail` throws for a valid session without invoking data callbacks. Session allocation does not reproduce guest allocator calls, worker creation or their failure paths. `sceContentExportGetProgress` throws because an idle session returns either zero or an invalid-state error according to the caller's SDK compatibility mode, which is not available here. Initialization and session lookup still throw for some invalid inputs instead of reproducing the console's error precedence and legacy SDK behavior. Session IDs now use the lowest free slot in 0–9; exhaustion, termination with live sessions and cancellation before an export return the confirmed errors.

### Unknown function info

- [sceContentExportFromData](../../../core/libs/prx/libSceContentExport/Export.cpp) (libSceContentExport) - the signature is known (AlexAltea/orbital, SharpProspero). The data provider `int32_t (const void** data, size_t* size, void* userData)` follows the typedef in [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/content_export/content_export.h) and SharpProspero's return values, 0 for more data and 1 for the last chunk; PPSA21567 passes a 0x400-byte path buffer and a provider that hands over the whole PNG in one chunk and returns 1. The provider runs on the caller's thread with no library lock held, and each chunk is appended to `/_ce/export_N.<ext>`. A content length of 0, a provider return other than 0 or 1, a chunk past the content length or with a null pointer, a return of 0 once the content length was already reached and a total that differs from the content length at the last chunk are unverified and throw after removing the partial file; the console's provider error code is unknown. `sceContentExportFromFile*` copy the file to `/_ce` in the host root and return that guest path; the title and comment of `ContentExportParam` are validated for termination but not stored, and the console's per-call error for a busy or full service (`BUSY`, `EXECUTION_MAX`) is unverified; a provider that returns 0 (more) with no data throws instead of being called again, since the console's handling is unknown
- [sceContentExportDataProvideFunction, sceContentExportFree, sceContentExportFrom and sceContentExportMalloc](../../../core/libs/prx/libSceContentExport/Export.cpp): their signatures remain unresolved; these names have no matching exports in the supplied module's C or assembly listing.
- [sceContentExportInit](../../../core/libs/prx/libSceContentExport/Export.cpp) (libSceContentExport) - the `(const initparam*)` prototype is [orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json)'s; it takes the 24-byte `ContentExportInitParam` (allocators and user data, no buffer size or reserved fields) and checks the allocators as `sceContentExportInit2` does, as the PS4 functions in [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/content_export/content_export.cpp#L13-L36) do: there only `sceContentExportInit2` checks the reserved fields. Like `sceContentExportInit2`, a null parameter, missing allocators or a second initialization throw instead of returning shadPS4's `INVALDPARAM` and `MULTIPLEINIT`, which are not measured on a PS5
- [Content export arguments](../../../core/libs/prx/libSceContentExport/Export.cpp): file/data entry points and content-ID operations have restored argument lists. The Share Factory parameter contains a size, metadata string, content-ID list, count and option; metadata format and option values remain unresolved. Protected export bodies are unchanged.
