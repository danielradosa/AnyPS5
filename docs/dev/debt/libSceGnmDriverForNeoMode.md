- [sceGnmBeginWorkload, sceGnmEndWorkload, sceGnmCreateWorkloadStream](../../../core/libs/prx/libSceGnmDriverForNeoMode/Export.cpp) (libSceGnmDriverForNeoMode, PS4) - `(uint32_t stream, uint64_t* workload)`, `(uint64_t workload)` and `(uint64_t, uint32_t* stream)` and their answers follow shadPS4: Begin writes 1 for a stream below 16 (else 0) and returns 0 (else 1), 3 for a null output; End returns 2 for a 0 workload or one whose top byte is 16 or more, else 0; Create returns stream 1 and 0, or 3 for a 0 first argument or a null output. The init packet libSceGnmDriver submits before a frame's first buffer is the base (non-Neo) default state, as before.

### Unknown function info

- [Neo-mode shader writers](../../../core/libs/prx/libSceGnmDriverForNeoMode/Export.cpp) (libSceGnmDriverForNeoMode, PS4) - the prototypes, size checks, return values and packets of `sceGnmSetCsShaderWithModifier`, `sceGnmSetPsShader350`, `sceGnmUpdateGsShader`, `sceGnmUpdateHsShader`, `sceGnmUpdatePsShader`, `sceGnmUpdatePsShader350` and `sceGnmUpdateVsShader` follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/gnmdriver/gnmdriver.cpp) with `sceKernelIsNeoMode()` true, because this module is only loaded in Neo mode. None of it is checked on a console. The NOP bodies these writers reserve are zero-filled, where shadPS4 only clears their first dword. The shader update writers put each context register change in a NOP whose first dword is `0xC01E0000 | register`, as shadPS4 does; neither shadPS4 nor the AGC executor applies these updates, so an update only changes the program address and resource registers. `sceGnmDrawInitToDefaultContextStateInternalCommand` and `...InternalSize` pick the 0x100-dword form when the title's compiled SDK version is 4.00 (0x4000000) or later, else the 0x20-dword one, as shadPS4 decides. That context state, the pixel and compute shader writers are [shared with libSceGnmDriver](../../../core/libs/prx/libSceGnmDriver/src/Commands.cpp).
- [sceGnmSetEmbeddedPsShader, sceGnmSetEmbeddedVsShader](../../../core/libs/prx/libSceGnmDriverForNeoMode/Export.cpp) (libSceGnmDriverForNeoMode, PS4) - `(cmd, size, shaderId, modifier)`; the GCN programs (ids 0 and 1: zero colour exports, id 0 of the vertex form: a full-screen triangle) and their register values are shadPS4's. As in shadPS4 the programs are 256-byte aligned arrays in this module's own image (the console's live at 0xFE000F00..0xFE000F20) and the high address bits go into `SPI_SHADER_PGM_HI`; the size and the modifier are not checked, an unknown id returns `SCE_GNM_ERROR_FAILURE`. Whether the AGC executor's GCN path accepts a program outside the title's memory is untested.
- [Pending libSceGnmDriverForNeoMode exports](../../../core/libs/prx/libSceGnmDriverForNeoMode/Export.cpp) (libSceGnmDriverForNeoMode, PS4) - still throw: `sceGnmDingDongForWorkload` and `sceGnmMapComputeQueueWithPriority` (shadPS4 forwards them to `sceGnmDingDong` and `sceGnmMapComputeQueue`, which still throw in libSceGnmDriver because no compute ring is modelled), and `sceGnmDestroyWorkloadStream`, `sceGnmDrawIndexMultiInstanced`, `sceGnmDrawOpaqueAuto`, `sceGnmGetCoredumpAddress`, `sceGnmGetCoredumpMode`, `sceGnmGetCoredumpProtectionFaultTimestamp`, `sceGnmGetNumTcaUnits`, `sceGnmIsCoredumpValid`, `sceGnmLogicalTcaUnitToPhysical`, `sceGnmSetWaveLimitMultiplier` and `sceGnmSetWaveLimitMultipliers`, which shadPS4 only stubs without a prototype or a console answer. The export list itself comes from the [PS5 3.20 export table](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceGnmDriverForNeoMode.c), cross-checked against firmware 13.60.
