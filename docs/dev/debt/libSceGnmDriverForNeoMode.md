### Unknown function info

- [Neo-mode command buffer writers](../../../core/libs/prx/libSceGnmDriverForNeoMode/Export.cpp) (libSceGnmDriverForNeoMode, PS4) - the prototypes, size checks, return values and packets of `sceGnmDrawIndex`, `sceGnmDrawIndexAuto`, `sceGnmDrawIndexOffset`, `sceGnmDrawIndexIndirect`, `sceGnmDrawIndexIndirectMulti`, `sceGnmDrawIndexIndirectCountMulti`, `sceGnmDrawIndirect`, `sceGnmDrawIndirectMulti`, `sceGnmDrawIndirectCountMulti`, `sceGnmDispatchDirect`, `sceGnmDispatchIndirect`, `sceGnmDispatchIndirectOnMec`, `sceGnmComputeWaitOnAddress`, `sceGnmComputeWaitSemaphore`, `sceGnmInsertDingDongMarker`, `sceGnmSetVgtControl`, `sceGnmResetVgtControl`, `sceGnmSetCsShaderWithModifier`, `sceGnmSetPsShader350`, `sceGnmUpdateGsShader`, `sceGnmUpdateHsShader`, `sceGnmUpdatePsShader`, `sceGnmUpdatePsShader350`, `sceGnmUpdateVsShader`, `sceGnmDrawInitDefaultHardwareState`, `...200`, `...350`, `sceGnmDrawInitToDefaultContextState` and `...400` follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/gnmdriver/gnmdriver.cpp) and its [init sequences](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/gnmdriver/gnmdriver_init.h) with `sceKernelIsNeoMode()` true, because this module is only loaded in Neo mode: draws keep the top three flag bits in the draw initiator, the 200 and 350 states also set the static thread masks of the two extra shader engines (SH 0x219, 0x21A), all Neo states write context register 0xEB, the 200 and 350 hardware states and the 400 context state write `IA_MULTI_VGT_PARAM` through `SET_UCONFIG_REG` 0x40000258, and the VGT control writers use that register too (shadPS4's unused compat sequences are left out). None of it is checked on a console. The NOP bodies the writers reserve are zero-filled, where shadPS4 only clears their first dword. The shader update writers put each context register change in a NOP whose first dword is `0xC01E0000 | register`, as shadPS4 does; neither shadPS4 nor the AGC executor applies these updates, so an update only changes the program address and resource registers. `sceGnmDrawInitToDefaultContextStateInternalCommand` and `...InternalSize` pick the 0x100-dword form when the title's compiled SDK version is 4.00 (0x4000000) or later, else the 0x20-dword one, as shadPS4 decides. The default hardware state, the pixel and compute shader writers are [shared with libSceGnmDriver](../../../core/libs/prx/libSceGnmDriver/src/Commands.cpp).
- [sceGnmSetEmbeddedPsShader, sceGnmSetEmbeddedVsShader](../../../core/libs/prx/libSceGnmDriverForNeoMode/Export.cpp) (libSceGnmDriverForNeoMode, PS4) - `(cmd, size, shaderId, modifier)`; the GCN programs (ids 0 and 1: zero colour exports, id 0 of the vertex form: a full-screen triangle) and their register values are shadPS4's. As in shadPS4 the programs are 256-byte aligned arrays in this module's own image (the console's live at 0xFE000F00..0xFE000F20) and the high address bits go into `SPI_SHADER_PGM_HI`; the size and the modifier are not checked, an unknown id returns `SCE_GNM_ERROR_FAILURE`. Whether the AGC executor's GCN path accepts a program outside the title's memory is untested.
