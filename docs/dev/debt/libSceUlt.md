# libSceUlt technical debt

### Unknown function info

- [Bound condition variables](../../../core/libs/prx/libSceUlt/Export.cpp) use the creation-time mutex, inferred from PPSA28061 callers of `_sceUltConditionVariableCreate`; the wait caller reloads only the condition argument. Error precedence, busy/state errors, FIFO signal selection and unsupported recursive waits have not been measured on PS5 hardware. Non-null options and waits at recursion depth above one throw. A live condition prevents destroying its bound mutex. Finalization follows the existing host mutex lifecycle: it invalidates conditions and wakes queued or reacquiring waiters with a state error. Scheduling priority and build-version validation are not implemented.

- [libSceUlt ulthreads](../../../core/libs/prx/libSceUlt/Export.cpp) - Runtime option defaults still omit the native header, stack size, worker affinity and priority fields; affinity depends on unresolved process configuration queries. Concurrent join ownership is not modeled: the native runtime distinguishes an ordinary running thread from one with another joiner. Host threads do not use the guest context or worker scheduler.
- [libSceUlt queues](../../../core/libs/prx/libSceUlt/Export.cpp) - Queue-data pool destruction and shared slot limits still require comparison with the native node allocator.
- [Ult factory and creation exports](../../../core/libs/prx/libSceUlt/Export.cpp) without a leading underscore are absent from the supplied module; their signatures remain unresolved. Diagnostic signatures and synchronization argument lists are recovered; the factory and the module calls still throw.
- [sceUltMutexTryLock](../../../core/libs/prx/libSceUlt/Export.cpp) (libSceUlt) - the `(mutex)` signature and `ULT_ERROR_BUSY` for a mutex another thread holds follow [SharpEmu](https://github.com/sharpemu/sharpemu/blob/5052fae0718ee17eb4c7fae0a52b472738c64aaa/src/SharpEmu.Libs/Ult/UltExports.Sync.cs#L272-L296). SharpEmu refuses a mutex the caller already holds with `0x80810005`; here the caller's own mutex is taken again and counted whatever its attribute (`sceUltMutexLock` counts only a recursive mutex), so it needs one unlock per successful try. Neither answer is measured on a PS5
- [sceUltConditionVariableSignalAll](../../../core/libs/prx/libSceUlt/Export.cpp) (libSceUlt) - the `(condition)` signature follows [SharpEmu](https://github.com/sharpemu/sharpemu/blob/5052fae0718ee17eb4c7fae0a52b472738c64aaa/src/SharpEmu.Libs/Ult/UltExports.Sync.cs#L428-L470); it wakes every queued waiter of the bound condition, with the same null, unknown-object and finalized-state errors as `sceUltConditionVariableSignal`. [sceUltConditionVariableCreate](../../../core/libs/prx/libSceUlt/Export.cpp) and `_sceUltConditionVariableCreate` run the same code; that the export without the underscore takes the same arguments is inferred from the other underscore pairs, as for the creates above
- [sceUltUlthreadGetSelf, sceUltUlthreadExit, sceUltUlthreadYield](../../../core/libs/prx/libSceUlt/Export.cpp) (libSceUlt) - the `(ulthread** out)`, `(int32_t status)` and `()` signatures follow [SharpEmu](https://github.com/sharpemu/sharpemu/blob/5052fae0718ee17eb4c7fae0a52b472738c64aaa/src/SharpEmu.Libs/Ult/UltExports.cs#L364-L417), as does `0x80810005` (SharpEmu's `ErrorPermission`, `ULT_ERROR_PERMISSION` here) from `GetSelf` and `Exit` on a thread that is not an ulthread; `GetSelf` checks the null output first. `Exit` ends the ulthread's host thread through `scePthreadExit`, which skips the frames above it without unwinding them, and `Join` then reports the status. `Yield` yields the host thread, as SharpEmu does on any thread, because each ulthread runs on its own host thread here rather than on a worker of the runtime
- [sceUltSemaphoreOptParamInitialize, sceUltQueueOptParamInitialize, sceUltQueueDataResourcePoolOptParamInitialize, sceUltWaitingQueueResourcePoolOptParamInitialize, sceUltUlthreadOptParamInitialize, sceUltReaderWriterLockOptParamInitialize and sceUltConditionVariableOptParamInitialize](../../../core/libs/prx/libSceUlt/Export.cpp) (libSceUlt) zero 128 bytes, the size of the PS Vita libult option structures in [RPCS3](https://github.com/RPCS3/rpcs3/blob/13aa88c3c4d66ea8799e987f7d762d90943ab17b/rpcs3/Emu/PSP2/Modules/sceUlt.h#L25-L78) and the size [SharpEmu](https://github.com/sharpemu/sharpemu/blob/5052fae0718ee17eb4c7fae0a52b472738c64aaa/src/SharpEmu.Libs/Ult/UltExports.cs#L109-L152) gives the ulthread and runtime option parameters. SharpEmu's condition-variable [underscore forms](https://github.com/sharpemu/sharpemu/blob/5052fae0718ee17eb4c7fae0a52b472738c64aaa/src/SharpEmu.Libs/Ult/UltExports.Sync.cs#L95-L125) only reject a null parameter and write nothing. The creates without the underscore ignore these options; the underscore creates check the recovered common header, which these zeroed structures lack, and both condition variable creates throw for any non-null one. That the PS5 structures match, their contents and the build version argument are unverified
- [_sceUltConditionVariableOptParamInitialize](../../../core/libs/prx/libSceUlt/Export.cpp) (libSceUlt) forwards to `sceUltConditionVariableOptParamInitialize` with the `(optParam, buildVersion)` arguments of the other underscore pairs: SharpEmu binds it, `_sceUltMutexOptParamInitialize` and `_sceUltQueueOptParamInitialize` to one [handler](https://github.com/sharpemu/sharpemu/blob/b6347f9/src/SharpEmu.Libs/Ult/UltExports.Sync.cs#L95-L125) that only rejects a null parameter and writes nothing; here it zeroes 128 bytes like the other option initializers. That the PS5 export takes these arguments and the structure's size are not measured
- [_sceUltWaitingQueueResourcePoolOptParamInitialize, _sceUltSemaphoreOptParamInitialize, _sceUltQueueDataResourcePoolOptParamInitialize, _sceUltQueueOptParamInitialize and _sceUltUlthreadOptParamInitialize](../../../core/libs/prx/libSceUlt/Export.cpp) and [_sceUltReaderWriterLockOptParamInitialize and _sceUltReaderWriterLockCreate](../../../core/libs/prx/libSceUlt/src/ReaderWriterLock.cpp) (libSceUlt) forward to the exports without the underscore; that their argument lists match is inferred from the other underscore Ult exports, not measured. Unlike the other underscore creates, `_sceUltReaderWriterLockCreate` takes a build version argument and does not check the common option header
- [The reader-writer lock](../../../core/libs/prx/libSceUlt/src/ReaderWriterLock.cpp) (libSceUlt) - the signatures follow the PS Vita libult in [RPCS3](https://github.com/RPCS3/rpcs3/blob/13aa88c3c4d66ea8799e987f7d762d90943ab17b/rpcs3/Emu/PSP2/Modules/sceUlt.cpp) (a 256-byte lock and 128-byte option structures), not a PS5 binary. The rules are assumed: readers may take the lock while a writer waits, a thread that holds the write lock gets `ULT_ERROR_STATE` for any further lock instead of waiting on itself, a reader asking for the write lock waits on its own read lock, and the try forms return `ULT_ERROR_BUSY`.
- [`sceUltConditionVariableCreate` and `sceUltConditionVariableOptParamInitialize`](../../../core/libs/prx/libSceUlt/Export.cpp) (libSceUlt) are absent from the console export list, where only the underscored variants `_sceUltConditionVariableCreate` and `_sceUltConditionVariableOptParamInitialize` appear; their non-underscored signatures are assumed.
- [Status query exports](../../../core/libs/prx/libSceUlt/Export.cpp) (`sceUltGetConditionVariableInfo`, `sceUltGetMutexInfo`, `sceUltGetQueueDataResourcePoolInfo`, `sceUltGetQueueInfo`, `sceUltGetReaderWriterLockInfo`, `sceUltGetSemaphoreInfo`, `sceUltGetUlthreadInfo`, `sceUltGetUlthreadRuntimeInfo` and `sceUltGetWaitingQueueResourcePoolInfo`) populate recovered structure layouts and return `ULT_ERROR_NULL` or `ULT_ERROR_STATE` on absent objects. `sceUltGetQueueInfo` counts blocked pushers and poppers in their separate fields, but the waiter records it copies only carry their size: host waiters are not enumerated, so no thread identity, wait type or wait value is reported. `sceUltGetUlthreadRuntimeInfo` throws when the caller supplies a non-empty worker thread array, because this runtime starts no worker threads and has no handles to return. Waiting thread arrays and hardware priority accounting remain unverified on PS5 hardware.

### Functional

- [libSceUlt queues](../../../core/libs/prx/libSceUlt/Export.cpp) use preallocated host storage instead of the supplied guest work area; the guest object layouts remain incomplete. Waiting-queue pool thread limits and waiter priority ordering are not implemented. Finalization wakes blocked queue callers with `ULT_ERROR_STATE`.
- [sceUltWaitingQueueResourcePoolDestroy](../../../core/libs/prx/libSceUlt/Export.cpp) refuses with `ULT_ERROR_STATE` only when a thread is currently waiting on a pool-backed mutex, semaphore or queue, matching the PS5 libSceUlt disassembly (0x473a in or55417wcDk); bound but idle objects do not block pool destruction. Waiting-queue pool guest work area node accounting is not implemented.
