Signatures from [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/network/http.cpp); not measured on a console
- [sceHttpSetRecvBlockSize, sceHttpRedirectCacheFlush, sceHttpsUnloadCert, HTTP callbacks and CA-list helpers](../../../core/libs/prx/libSceHttp/Export.cpp) (libSceHttp) - `sceHttpSetRecvBlockSize` does not change the size returned by `sceHttpReadData`; redirect caching is not kept; `sceHttpsUnloadCert` succeeds without a stored certificate; redirect, cookie, authentication, socket-creation and request-status callbacks are not dispatched; `sceHttpsSetSslCallback` is passed to libSceSsl for HTTPS verification; SSL-version options do not change negotiation; CA-list calls return an empty list. Signatures follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/network/http.cpp) (PS4) or [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/main/src/SharpProspero/Interop/Net/Http.cs); PS5 behavior is unverified
- [HTTP options not applied to transport](../../../core/libs/prx/libSceHttp/src/Options.cpp) (libSceHttp) - `sceHttpCacheRedirectedConnectionEnabled` keeps no redirect cache, and `sceHttpsEnableOptionPrivate` / `sceHttpsDisableOptionPrivate` retain flags but do not change TLS verification options. The private calls refuse flags outside `0x2dff` with `ERROR_INVALID_VALUE` before checking the id; `sceHttpAbortRequestForce` delegates to `sceHttpAbortRequest`. Signatures, mask and check order follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/a808e76/src/core/libraries/network/http.cpp) (PS4), not measured on PS5

The signature `(id, HTTP proxy conf, WLAN proxy conf, host, port)` and check order (`ERROR_BEFORE_INIT`, then `ERROR_INVALID_VALUE` for a null host, then `ERROR_INVALID_ID`) follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/a808e76/src/core/libraries/network/http.cpp) (PS4), which stores the proxy; not measured on PS5

### Unknown function info

- [HTTP object options](../../../core/libs/prx/libSceHttp/src/Options.cpp) (libSceHttp) - a template starts with redirects followed, blocking calls and no `Accept-Encoding: gzip`, and a connection or request copies its parent's options when it is created. The signatures of the option calls, these defaults, the copying and the order of the checks (`BEFORE_INIT` first; the last `sceHttpTerm` ends every object's options) follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/a808e76/src/core/libraries/network/http.cpp) (PS4) and are not measured on a PS5. `sceHttpSetDefaultAcceptEncodingGZIPEnabled` sets the gzip value for templates created later in that context, where shadPS4 keeps one value for the library, and `sceHttpUnsetEpoll` takes a template or connection id, where shadPS4 looks only at requests. Gzip state is stored but compression and decompression are not implemented
- [sceHttpGetConnectionStat](../../../core/libs/prx/libSceHttp/Export.cpp) (libSceHttp) - connection and request diagnostic signatures are recovered; their outputs contain four and three 32-bit words, respectively. Field semantics remain incomplete. Epoll setters/getters distinguish a 32-bit epoll ID from a pointer-sized handle, and use a pointer-sized user argument. The supplied firmware getter dispatch does not handle the pointer-handle selector used by GetEpoll, so its intended successful behavior is not recoverable from this implementation.

- [sceHttpSetCookieEnabled, sceHttpGetCookieEnabled](../../../core/libs/prx/libSceHttp/Export.cpp) - the two-argument signature and 0/1 enable values follow [VitaSDK](https://github.com/vitasdk/vita-headers/blob/master/include/psp2/net/http.h) and [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/network/http.cpp); PPSA01521 passes 0 to disable cookies. The value is kept per template, connection and request like the other HTTP options (off on a new template, inherited by children) and read back by `sceHttpGetCookieEnabled`, but the transport keeps no cookie jar and the cookie jar calls throw, so no cookie is received, sent or read back and the setting has no effect. Invalid enable values use the same error as `sceHttpSetInflateGZIPEnabled` and are refused before the initialization and handle checks. Console behavior is unverified
- [sceHttpParseResponseHeader](../../../core/libs/prx/libSceHttp/Export.cpp) (libSceHttp) - signature follows [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/main/src/SharpProspero/Interop/Net/Http.cs); the result, value bounds and error codes follow a payload process on a PS5 (firmware 13.60). Unmeasured there: a bare carriage return, and vertical tab or form feed around the value, which are skipped as blanks before it as before. A value end above `INT_MAX` throws instead of wrapping
- [sceHttpParseStatusLine](../../../core/libs/prx/libSceHttp/src/Parse.cpp) (libSceHttp) - follows a payload process on a PS5 (firmware 13.60) for 124 lines and lengths. As on the console, `lineLen` is only checked to be at least 8 and to leave the 3 code digits (`lineLen - index < 3` in unsigned arithmetic): the version digits and the `.` and space after them are read past `lineLen`, and the line feed is searched up to and including the byte at `lineLen`, so a length that stops right before the line feed still parses. When the version ends past `lineLen` both subtractions wrap and the search goes on until a line feed; what the console does when none follows in readable memory was not measured
- [sceHttpUriMerge](../../../core/libs/prx/libSceHttp/src/Uri.cpp) (libSceHttp) - signature follows [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/main/src/SharpProspero/Interop/Net/Http.cs); results, errors and `require` (the base's `sceHttpUriParse` size plus 2 and twice the two string lengths, also for a reference copied unchanged) follow a payload process on a PS5 (firmware 13.60). A reference with an authority (`//` after an optional scheme) is copied unchanged; any other, including `mailto:x`, `http:d`, `?q` and `#f`, is appended unswept to the base path up to its last `/`, and the base query and fragment are dropped. A reference that `sceHttpUriParse` rejects returns that error, which was not measured.
- [sceHttpUriParse](../../../core/libs/prx/libSceHttp/src/Uri.cpp) (libSceHttp) - follows a payload process on a PS5 (firmware 13.60) for every ASCII byte inside a scheme, userinfo and hostname, and for letters, digits, `+`, `-` and `.` at the start of a scheme, where a digit ends it; other bytes at the start of a scheme are taken as they are inside one. The userinfo ends at the first `@` after bytes from the RFC 3986 userinfo set; a hostname is letters, digits, `-`, `_` and `.` without a leading `.`, and the first byte outside it starts the path instead of failing (`http://bad host/` has the host `bad` and the path ` host/`). A port is up to 5 digits that end at `/` or the end, at most 65536, which reads as 0; an empty port takes 443 for a scheme starting with `https`, 80 for one starting with `http` (case-insensitive) and 0 otherwise. The path is swept as `sceHttpUriSweepPath` does, while the pool keeps room for the unswept path. With a pool too small the console returns `ERROR_OUT_OF_MEMORY`, leaves `require` alone and has already written part of the pool; how much is not known, so nothing is written here.
- [sceHttpUriSweepPath](../../../core/libs/prx/libSceHttp/src/Uri.cpp) (libSceHttp) - follows a payload process on a PS5 (firmware 13.60), which agrees with the [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/network/http.cpp) reimplementation of the PS4 library: it is not RFC 3986 5.2.4, a path that doesn't start with `/` is copied unchanged and a trailing `.` or `..` is kept. Like the console, the byte at `srcSize - 1` is read as the `/` that ends a `..` segment, and `srcSize == 1` with a leading `/` writes `/`; whether it also ends a `.` segment was not measured, so a `.` there is still kept as before
- [sceHttpRedirectCacheFlush, sceHttpsUnloadCert](../../../core/libs/prx/libSceHttp/Export.cpp) (libSceHttp) - signatures follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/network/http.cpp) (PS4); no PS5 reference has them
- [sceHttpSetRequestStatusCallback](../../../core/libs/prx/libSceHttp/Export.cpp) - the three-argument ABI follows [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/network/http.cpp). Handle hierarchy, inheritance and deleted-handle validation remain incomplete; callback statuses and dispatch timing are unknown.

- [sceHttpSetAuthInfoCallback](../../../core/libs/prx/libSceHttp/Export.cpp) (libSceHttp) - signature and callback type follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/network/http.h) (PS4); no PS5 reference has them. ### Functional
- [sceHttpGetMemoryPoolStats](../../../core/libs/prx/libSceHttp/Export.cpp) (libSceHttp) - reports the pool size given to `sceHttpInit`, with peak and current use 0, as the library allocates nothing from the pool. The recovered layout is 24 bytes (pool size, peak, current); the console already reports some use of a fresh pool for libSceHttp2. `BEFORE_INIT`, `INVALID_ID` for an unknown context and `INVALID_VALUE` for a null output, in that order, follow the epoll calls here; unverified
- [sceHttpCookieExport, sceHttpCookieImport](../../../core/libs/prx/libSceHttp/Export.cpp) (libSceHttp) - the prototypes are in [orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json) and [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/network/http.cpp), but they still throw: the export and import formats of the cookie store are unknown
- [sceHttpGetAuthEnabled, sceHttpGetCookieEnabled](../../../core/libs/prx/libSceHttp/Export.cpp) (libSceHttp) - the defaults of the authentication and cookie settings (both off on a new template) are unknown (shadPS4 does not model them)
- [sceHttpAddRequestHeader, sceHttpRemoveRequestHeader](../../../core/libs/prx/libSceHttp/Export.cpp), [sceHttpAddRequestHeaderRaw](../../../core/libs/prx/libSceHttp/src/Request.cpp) (libSceHttp) - the headers of a request are kept by the transport and sent with it: there `sceHttpAddRequestHeader` returns `INVALID_VALUE` for a null or malformed name or value, another mode or a request already sent, and `sceHttpAddRequestHeaderRaw` splits `name: value` and takes request ids only (`INVALID_ID` for a template or connection). On a template or connection `sceHttpAddRequestHeader` only keeps the header, which is neither sent nor passed to the requests created from it, as in shadPS4, and still returns 0 for anything, also for a null name or value, another mode or an unknown id, where shadPS4 returns `INVALID_VALUE` or `INVALID_ID`. Both add calls return `BEFORE_INIT` with no live context. `sceHttpRemoveRequestHeader` drops every header of that name (case-insensitive) on that object only, and returns, as shadPS4 does, `BEFORE_INIT` with no live context, `NOT_FOUND` (0x80431025) for a null name or no match and `INVALID_ID` for an unknown id. The `(int id, const char* name)` signature is in [orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json); not measured on a console
- [Nonblocking requests, request epoll events, chunked request bodies, persistent connection reuse, gzip and console-specific TLS flags](../../../core/libs/prx/libSceHttp/src/Request.cpp) remain unimplemented or unverified. Synchronous HTTP/1.1 supports headers, request bodies, fixed/chunked/close-delimited reads, ten redirects and the configured resolver timeout. Timed-out lookups return at deadline, but libc `getaddrinfo` cannot be cancelled; the process-lifetime resolver pool discards late results. Prospero Themes (PPSA90210) uses [StoreHttpClient](https://github.com/Darkatek7/ProsperoThemes/blob/7bbf66c043fc57d4695efb3e647a5d9dd54e64d1/ThemeApp/Library/StoreHttpClient.cs) for GET/POST, TLS, headers and DNS/connect/I/O timeouts. Console behavior is unverified; all four focused HTTP tests pass under x86-64 QEMU emulation, but a native x86-64/full project build was unavailable

- [sceHttpAbortWaitRequest, sceHttpWaitRequest](../../../core/libs/prx/libSceHttp/Export.cpp) (libSceHttp) - the abort takes only the epoll handle, as in [Orbital](https://github.com/AlexAltea/orbital/blob/master/tools/ida/db_types.json) and [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/main/src/SharpProspero/Interop/Net/Http.cs); behaviour and error codes follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/network/http.cpp) (PS4), not confirmed on a PS5 title or hardware. An abort stays set: every later wait on the handle, a poll included, returns `SCE_HTTP_ERROR_ABORTED` (0x80431080) until the handle is destroyed. A wait woken by `sceHttpDestroyEpoll`, or by the `sceHttpTerm` that ends the last context, returns 0 events. The epoll calls return `BEFORE_INIT` (0x80431001) while no `sceHttpInit` context is alive and `INVALID_ID` (0x80431100) for an unknown context or handle, and `sceHttpTerm` returns the same errors instead of succeeding for any id. Handles are numbered from 1 and never reused, as shadPS4 encodes its epoll ids. `HttpNBEvent` is shadPS4's 24-byte `{events, eventDetail, id, userArg}`; fpPS4 declares the same fields packed into 20 bytes, and no event is ever written, so the layout is not exercised
- [sceHttpUriParse, sceHttpUriBuild, sceHttpUriMerge](../../../core/libs/prx/libSceHttp/src/Uri.cpp) - bytes 0x80 to 0xFF were measured only as 0x80, 0xC3 and 0xFF in a hostname; the others, and any of them in a scheme or userinfo, are taken as the measured ASCII bytes outside those sets are. ASCII classification and scheme case folding are independent of the host locale. A bracketed host such as `[::1]` is parsed, merged and built without its brackets, as a PS5 (firmware 13.60) does; a PS4 (firmware 10.71) takes no bracketed host (`http://[::1]x/` has an empty host and the path `[::1]x/`) and keeps `[::1]:80` in a merge, as measured in #9058, so this follows the PS5 only.

- [sceHttpUriEscape](../../../core/libs/prx/libSceHttp/src/Uri.cpp) escapes every byte except the ASCII unreserved set in [RFC 3986 section 2.3](https://www.rfc-editor.org/rfc/rfc3986#section-2.3), independently of the host locale. Console behaviour for non-ASCII input remains unmeasured.

- [sceHttpAuthCacheFlush, sceHttpCookieFlush](../../../core/libs/prx/libSceHttp/Export.cpp) (libSceHttp) - the context-id signatures follow [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/main/src/SharpProspero/Interop/Net/Http.cs), and the NIDs `zzB0StvRab4` and `seCvUt91WHY` match [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/network/http.cpp). The offline backend never stores authentication credentials, so flushing them succeeds with an empty cache; `sceHttpCookieFlush` empties the cookie store below. Calls return `BEFORE_INIT` (0x80431001) when no context is alive and `INVALID_ID` (0x80431100) for an unknown, deleted or non-context handle, following the existing context lifecycle checks. These error codes and their precedence have not been measured on PS5 hardware; shadPS4 only stubs these calls. Network-backed caches remain unimplemented.
- [Cookie store](../../../core/libs/prx/libSceHttp/src/Cookies.cpp) (libSceHttp) - follows [RFC 6265](https://www.rfc-editor.org/rfc/rfc6265) sections 5.1-5.4; the console's limits, eviction order and errors are not measured. No request sends or receives cookies. `sceHttpAddCookie` reads a `Set-Cookie` value of `size` bytes; a cookie the RFC ignores (no `=`, empty name, a `Domain` the host does not match, over the size limit) returns 0 unstored, and public suffixes are not checked. `sceHttpGetCookie` writes `a=1; b=2` and a terminator counted in `required`, longest path first, `Secure` cookies only with `isSecure`; a short buffer returns `OUT_OF_SIZE`. The four limits start at 0, meaning none, as the defaults are not known; going over one evicts the least recently used cookie into `removedNum`. The `isSecure` argument and the 40-byte stats follow [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/main/src/SharpProspero/Interop/Net/Http.cs). The stats keep the recovered field offsets (current size 0, count 8, peak size 16, peak count 24, removed 28) but add SharpProspero's reserved word at 32; the earlier recovery found a 32-byte structure, so if that holds the last 8 bytes written lie past the guest's structure
