# libkernel_sys technical debt

### Silent stubs
- [pthread_mutex_setname_np, pthread_cond_setname_np, pthread_rwlock_setname_np, sem_setname](../../../core/libs/prx/libkernel_sys/Pthread.cpp) (libkernel_sys) - the name is kept nowhere and the call returns 0, as libkernel's mutexes, condition variables, read-write locks and semaphores have no name (`scePthreadMutexInit`, `scePthreadCondInit` and `scePthreadRwlockInit` ignore theirs too) and no export reads one back. Argument checks follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/kernel/threads/condvar.cpp) (PS4): a null name returns `EINVAL` from the condition-variable and read-write-lock calls, -1 with `errno` `EINVAL` from `sem_setname`, and is accepted by `pthread_mutex_setname_np`; a null object pointer, which shadPS4 dereferences, throws
- [fchmodat](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) - `AT_SYMLINK_NOFOLLOW` on a symbolic link (on Windows and Linux)

### Functional

- [sceKernelIsInSandbox](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) returns 1, as [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/kernel/process.cpp) answers for a title (prototype `int32_t sceKernelIsInSandbox(void)` from OpenOrbis), matching the sandbox libkernel models with `sceKernelGetFsSandboxRandomWord`
- [tcgetsid, tcsetsid](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) follow FreeBSD 11.4's [`termios.c`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/lib/libc/gen/termios.c): `tcsetsid` returns `EINVAL` for a process id other than `getsid(0)`, and both then fail as their `TIOCGSID` and `TIOCSCTTY` ioctls do on a descriptor that is not a terminal, with the errors libkernel's `tcgetattr` gives (`EBADF`, `ENOTTY`, and for sockets `EADDRNOTAVAIL` or `EOPNOTSUPP`), which FreeBSD's file, pipe and socket ioctl paths give for these requests as well. A descriptor libkernel took for a terminal throws, as terminal sessions are not modelled
- [pselect](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) follows FreeBSD 11.4's [`sys_pselect` and `kern_pselect`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/sys_generic.c) over libkernel's `select` and `sigprocmask`: the timeout is truncated to microseconds as `TIMESPEC_TO_TIMEVAL` does (so `select` rejects a nanosecond field outside 0 to 999999999 with `EINVAL`), a given mask is installed for the call and the previous one restored afterwards, also when `select` fails. The mask is not swapped atomically with the wait: a signal unblocked by the mask that arrives just before the wait starts is not guaranteed to cut it short with `EINTR`, which libkernel's `select` does not report anyway. Console behaviour is unverified
- [settimeofday, sceKernelSettimeofday](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) check like FreeBSD 11.4's [`kern_settimeofday`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/kern_time.c#L687-L707) for a root caller: a time with a negative second count or a microsecond count outside 0 to 999999 fails with `EINVAL`, and null time and zone succeed. A valid time throws, as `clock_settime` does, since the host clock is never set; a zone of 0 minutes west without daylight saving succeeds, as it is the zone libkernel's `gettimeofday` reports, and any other zone throws, since no kernel zone is kept. `sceKernelSettimeofday` (prototype from [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/kernel/time.cpp), which stubs both) returns the error biased by `0x80020000`. Whether a title holds `PRIV_SETTIMEOFDAY` on the console, which FreeBSD checks first, is unverified
- [sceKernelMlockall](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) is libkernel's `mlockall` with its error biased by `0x80020000` (prototype `int sceKernelMlockall(int flags)` from Orbital), so invalid flags return `SCE_KERNEL_ERROR_EINVAL` and a valid request throws as `mlockall` does
- [sem_open, sem_close, sem_unlink](../../../core/libs/prx/libkernel_sys/Semaphore.cpp) (libkernel_sys) follow FreeBSD 11.4's [`sem_new.c`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/lib/libc/gen/sem_new.c), but a name's backing file `/tmp/SEMD<name>` is a process-local entry instead of a file, so named semaphores are not seen by other processes or later runs, and do not appear in `/tmp`. A name not starting with `/` fails with `EINVAL` (`ENOENT` for `sem_unlink`), a `/tmp/SEMD` path of 1024 bytes or more or a file name over 255 bytes with `ENAMETOOLONG`, flags other than `O_CREAT` and `O_EXCL` with `EINVAL`, a missing name without `O_CREAT` with `ENOENT`, and an existing one with `O_CREAT | O_EXCL` with `EEXIST`; opening a name this process already has open returns the same `sem_t` and counts the open, and once the name was unlinked and created again a later open gets the new semaphore, as FreeBSD compares the file's device and inode. The semaphore is a libkernel POSIX semaphore (`sem_init` with `pshared` 1), so `sem_wait`, `sem_post` and the other calls work on it; an initial value above `SEM_VALUE_MAX` fails with `EINVAL` as `sem_init` does, where FreeBSD's `sem_open` stores it unchecked. `sem_close` returns `EINVAL` for a `sem_t` that is not an open named semaphore (an unnamed one included) and releases the semaphore when it is closed and unlinked; `sem_unlink` returns `ENOENT` for a missing name and leaves open handles working. A name with a further `/`, which would name a file below a `/tmp/SEMD...` directory, and a null name throw. Console behaviour is unverified
- [chown, lchown, fchownat](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) - ownership is not modelled, as for `fchown`: the path is looked up first, as FreeBSD 11.4's [`kern_fchownat`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/vfs_syscalls.c#L2614-L2633) runs `namei` before `setfown` (`EFAULT` for a null path, `ENOENT` for an empty or missing one, `ENOTDIR` through a file, `ENAMETOOLONG` for a path of 1024 bytes or more or a component over 255, `ELOOP` from the host), then the guest's own owner and group (0) and the unchanged value (-1) are accepted and any other owner or group throws, naming the path. `chown` follows a final symbolic link and `lchown` does not; `fchownat` rejects flags other than `AT_SYMLINK_NOFOLLOW` (0x200) with `EINVAL` first, as `sys_fchownat` does, passes `AT_FDCWD` (-100) and absolute paths to the guest path resolver and joins any other relative path to the descriptor's host directory, as `openat` does (`EBADF`, `ENOTDIR`). The console's ownership rules are unverified

- [fchmodat](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) passes `AT_FDCWD` (-100) and absolute paths to `chmod`; any other relative path is joined to the descriptor's host directory the same way as for `openat`, so guest path aliases and case-insensitive name matching do not apply to it and a `..` component is not kept inside the guest root. - [pathconf, fpathconf, _fpathconf](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) query filesystem configuration values. `pathconf` looks the path up as FreeBSD 11's `kern_pathconf` does (links followed, `ENAMETOOLONG` for a path of 1024 bytes or more or a component over 255). `fpathconf` and `_fpathconf` follow FreeBSD 11.4's [`kern_fpathconf`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/kern_descrip.c): a descriptor that is not open fails with `EBADF` (libkernel's `fstat` decides, so guest sockets and app0.zar files are known), `_PC_ASYNC_IO` is `_POSIX_ASYNCHRONOUS_IO` (200112) for any descriptor, a pipe or a socket answers `_PC_PIPE_BUF` with `PIPE_BUF` (512) and every other name with `EINVAL`, and a descriptor that is neither, nor a file or a directory (a character device or a kqueue, whose console filesystems are not known), throws. Whether the console's filesystems report the same is not verified. For files and directories they throw for the names whose UFS value depends on the mount (`_PC_ALLOC_SIZE_MIN`, `_PC_REC_INCR_XFER_SIZE`, `_PC_REC_MIN_XFER_SIZE`, `_PC_MIN_HOLE_SIZE`), the kernel options (`_PC_ACL_EXTENDED`, `_PC_ACL_PATH_MAX`, `_PC_ACL_NFS4`, `_PC_MAC_PRESENT`) or the page size (`_PC_REC_XFER_ALIGN`), and on which UFS and `vop_stdpathconf` disagree (`_PC_MAX_CANON`, `_PC_MAX_INPUT`, `_PC_VDISABLE`, `_PC_ASYNC_IO`); other names fail with `EINVAL`

- [readlink and symlink](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) - `symlink` stores a relative target as given and an absolute one as the absolute host path that the guest path resolves to (through the run directory or a mount alias such as `/savedata0`), so the host follows the link; an absolute target that the guest path resolver rejects (a `..` after a missing directory or a file, an unmounted alias) throws. `readlink` returns a relative target as stored, with `/` separators on Windows, and maps an absolute host target back to a guest path through the first mount alias whose host directory holds it, otherwise through the run directory ([`GuestPathFromHost`](../../../core/libs/prx/libc/src/General.cpp)); a target outside both throws, as a host path has no guest form. The result can differ from the text given to `symlink` (letter case resolved against existing names, `.` and `..` components and repeated slashes removed, another alias of the same directory), where FreeBSD returns the stored text unchanged, and a link with an absolute target breaks when the run directory moves. On Windows a junction is read like a symbolic link with an absolute target (its print name, or its substitute name without `\??\`), and any other reparse point is a file that is not a link (`EINVAL`). Both report FreeBSD's `ENAMETOOLONG` for a path of 1024 bytes or more or a component over 255 before the lookup, and `symlink` also for a target of 1024 bytes or more; `symlink` returns `ENOTDIR` when the new name's parent is a file or lies under one, and maps the host's `EACCES`, `EROFS`, `ENOSPC` and `ENAMETOOLONG`. The guest filesystem has no read-only mounts, so a link created under `/app0` gets what the host directory allows instead of `EROFS`. An empty target fails with `ENOENT`, as on Linux, where FreeBSD's UFS accepts it. Console behaviour is unverified
- [aio_read, aio_write, aio_fsync, aio_error, aio_return, aio_suspend, aio_waitcomplete, aio_cancel](../../../core/libs/prx/libkernel_sys/Aio.cpp) (libkernel_sys) - a request with `SIGEV_SIGNAL`, `SIGEV_THREAD_ID` or `SIGEV_KEVENT` completion, or on a socket, throws, because delivering a guest signal or kevent and socket aio are not modelled. - [unlinkat](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) passes `AT_FDCWD` (-100) and absolute paths to `rmdir` (with `AT_REMOVEDIR`, 0x800) or `unlink`. Any other relative path is joined to the descriptor's host directory, found the same way as for `fchdir`, so guest path aliases and case-insensitive name matching do not apply to it, and a `..` component is not kept inside the guest root. It returns `EBADF` for a descriptor that is not open and `ENOTDIR` for one that is not a directory. Removing a directory without `AT_REMOVEDIR` fails with `EPERM`, removing `.` or `..` with `AT_REMOVEDIR` fails with `EINVAL`, and flags other than `AT_REMOVEDIR` fail with `EINVAL`. Console behaviour is unverified

Any other relative path is joined to its descriptor's host directory, found the same way as for `fchdir`, so guest path aliases and case-insensitive name matching do not apply to relative descriptors, and a `..` component is not kept inside the guest root. - [fork](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) creates no process: it returns -1 with `errno` set to `ENOSYS` (78), as a title cannot start a process. The console's errno is unverified: FreeBSD's `fork` documents only `EAGAIN` and `ENOMEM`, and `ENOSYS` is what PPSA85300's PS5 compatibility layer returns from its own `fork` and `vfork` ([libc_missing.c](https://github.com/ZiZc3/VLC/blob/f3253020a64368153233ede29183014c0b6c8979/ps5/compat/libc_missing.c#L290-L292)), the one PS5 source found; `EAGAIN` would invite callers to retry. PPSA19111 imports it and fails to load without it. Its engine calls `fork` in `Posix_Daemonize`, only with `-daemonize`, and in `Platform_ShellExecute` before `execvp("xdg-open")`, which the main menu's Previews button reaches; that call now fails instead of throwing, and how the engine handles the failure is not verified. [umask](../../../core/libs/prx/libkernel_sys/Export.cpp) keeps the guest's mask (initially 022, masked to 07777) and returns the previous one, Linux named shared-memory creation applies it, but ordinary files are still created with the host process's mask

A null path is `EFAULT`, as FreeBSD 11.4 `kern_utimesat`, not Linux's descriptor-only extension.

- [chroot](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) follows FreeBSD 11.4's [`sys_chroot`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/vfs_syscalls.c#L776-L807) and [`pwd_chroot`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/kern_descrip.c#L3059-L3085) for a root caller: `EFAULT` for a null path, `ENOENT` for an empty or missing one, `ENAMETOOLONG` for a path of 1024 bytes or more or a component over 255, and `ENOTDIR` for a path that is not a directory or passes through a file. A directory that is the guest root (`/`, `/..`, or `.` after `fchdir` to a descriptor of `/`) succeeds and changes nothing, as the root stays the same directory; the guest is taken never to have changed its root, so open directory descriptors do not make it fail with `EPERM` (`kern.chroot_allow_open_directories` 1). Any other directory throws, naming the path: the guest path resolver has a fixed root and mount aliases (`/app0`, `/savedata0`) that do not move with it. On the console a title starts in a sandbox root, where `pwd_chroot` refuses with `EPERM` while a directory is open; whether that holds for titles, and whether a title holds `PRIV_VFS_CHROOT`, are unverified. Porpoise (PPSA99764) weak-imports it and calls it only as `fchdir` to its saved descriptor of `/` then `chroot(".")`, to put its sandbox root back after a jailbreak daemon replaced it ([`put_root_back`](https://github.com/elripalda/Porpoise-Dolphin-Emulator-for-PS5/blob/2ed1ab5a06995aa198f7bccd4da0f90c3fc29d39/src/porpoise_jailbreak.cpp#L303-L331))

The check reads the descriptor with `fstat`, ignoring the CRT's invalid-parameter handler on Windows as `DescriptorControl` does. The console's ownership rules are unverified. Morrowind (`mshivam019/morrowind-ps5`) imports it
- [sceKernelTitleWorkaroundIsEnabled](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) - not measured on a console; the `{version, align, ids[2]}` layout, the bit test and the limit of 0x3A bits follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/a808e76/src/core/libraries/kernel/kernel.cpp), which notes that the limit changes between firmwares. A negative bit is `EINVAL` here; shadPS4 compares it signed and reads outside `ids`. Titles usually pass the `title_workaround` block of `sceKernelGetAppInfo`, which does not write that block here, so the bits read are whatever the caller's memory held

- [swapcontext](../../../core/libs/prx/libkernel_sys/UserContext.cpp) (libkernel_sys) follows FreeBSD 11.4's [`sys_swapcontext`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/kern_context.c#L104-L131) over libkernel's `getcontext` and `setcontext`: a null old or new context returns `EINVAL`, then the caller's registers and signal mask are saved into the old context as `getcontext` saves them (with `rax` and `rdx` cleared and the carry flag reset, as `GET_MC_CLEAR_RET` does, and only the bytes before `uc_link` written), and the new context is installed through `setcontext`. An invalid new machine context returns `EINVAL` after the old context has been written, as on FreeBSD. Resuming the saved context returns 0 from `swapcontext` to its caller. It shares the limits of libkernel's `getcontext` and `setcontext`; console behaviour is unverified
- [sigqueue](../../../core/libs/prx/libkernel_sys/Signals.cpp) (libkernel_sys) follows FreeBSD 11.4's [`kern_sigqueue`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/kern_sig.c#L1884-L1918) for the only guest process: a signal outside 0 to 128 or a process id of 0 or below returns `EINVAL`, any other process `ESRCH`, and signal 0 only checks the target. The signal then goes through libkernel's signal emulation as `raise` sends it: while it is blocked it is queued with `SI_QUEUE`, the guest pid and the value, which `sigwaitinfo` and `sigtimedwait` report, every call queues one more instance as FreeBSD's `sigqueue_add` does, and an instance beyond 128 pending at once fails with `EAGAIN` (`max_pending_per_proc`, counted over `sigqueue` instances only); an unblocked signal is delivered or ignored as `raise` does it, so a handler runs without the value and an `SA_SIGINFO` handler still throws. Console behaviour is unverified
- [kmq_open, kmq_unlink, kmq_setattr, kmq_timedsend, kmq_timedreceive, kmq_notify](../../../core/libs/prx/libkernel_sys/MessageQueues.cpp) (libkernel_sys) follow FreeBSD 11.4's [`uipc_mqueue.c`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/uipc_mqueue.c#L1685-L2430) with a process-local namespace of queues, as if the `mqueuefs` module were loaded: whether the console kernel provides it is not known, and other processes do not see the queues. `kmq_open` returns `EINVAL` for `O_ACCMODE` or `O_EXEC` flags, for an `O_CREAT` attribute outside 1 to 100 messages or 1 to 16384 bytes, and for a name shorter than two bytes, not starting with `/` or holding another `/`, `EFAULT` for a null name, `ENAMETOOLONG` past 255 bytes, `ENOENT`, `EEXIST`, and `ENFILE` beyond 100 queues (counted in this process); a new queue without an attribute holds 10 messages of 1024 bytes. A descriptor is a reserved host descriptor, so `close` ends it and drops its notification as `mqueue_fdclose` does, but `dup`, `fstat`, `select`, `poll` and `kevent` do not see a queue. Sends and receives return `EBADF` for a descriptor that is not a queue or lacks the access, `EINVAL` for a priority of 64 or more, `EMSGSIZE` for a message longer than the queue's size or a buffer shorter than it, `EFAULT` for a null message, `EAGAIN` without blocking, and, after one failed attempt, `EINVAL` for an invalid deadline and `ETIMEDOUT` once the `CLOCK_REALTIME` deadline passes; messages are ordered by priority, first in first out within one, and a received message whose buffer is null is lost as on FreeBSD. `kmq_setattr` changes only `O_NONBLOCK` (`EINVAL` for other flags) and reports the previous flag, size limits and message count. `kmq_notify` takes `SIGEV_NONE`, `SIGEV_SIGNAL` and `SIGEV_THREAD_ID` (`EINVAL` otherwise, and for a signal outside 1 to 128), returns `EBUSY` while any descriptor of the queue is registered, and a null event removes this descriptor's registration and its queued signal; a message arriving at an empty queue with no waiting receiver, or left after a receive, sends the signal once with `SI_MESGQ`, the value and the descriptor through libkernel's signal emulation as `sigqueue` does, and removes the registration, and a `SIGEV_THREAD_ID` whose thread is gone sends nothing. Waits are not interrupted by signals (`EINTR`), and modes and ownership are not modelled. Console behaviour is unverified
- [pthread_set_defaultstacksize_np and scePthreadSetDefaultstacksize](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) set the stack size that `scePthreadAttrInit` and a thread created without attributes use, as [fpPS4's `pthread_set_defaultstacksize_np`](https://github.com/red-prig/fpPS4/blob/04cefd4/kernel/ps4_pthread_attr.pas#L89-L102) does: a size of 16384 bytes or less fails with `EINVAL` (`0x80020016` from the sce form) and there is no upper limit, so a default the host cannot allocate fails only when a thread is created. Attributes initialised earlier keep their size. Not checked on a PS5
