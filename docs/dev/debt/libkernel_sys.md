# libkernel_sys technical debt

### Silent stubs
- [pthread_mutex_setname_np, pthread_cond_setname_np, pthread_rwlock_setname_np, sem_setname](../../../core/libs/prx/libkernel_sys/Pthread.cpp) (libkernel_sys) - the name is kept nowhere and the call returns 0, as libkernel's mutexes, condition variables, read-write locks and semaphores have no name (`scePthreadMutexInit`, `scePthreadCondInit` and `scePthreadRwlockInit` ignore theirs too) and no export reads one back. Argument checks follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/kernel/threads/condvar.cpp) (PS4): a null name returns `EINVAL` from the condition-variable and read-write-lock calls, -1 with `errno` `EINVAL` from `sem_setname`, and is accepted by `pthread_mutex_setname_np`; a null object pointer, which shadPS4 dereferences, throws
- [fchmodat](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) - `AT_SYMLINK_NOFOLLOW` on a symbolic link (on Windows and Linux), and so `lchmod` on one

### Functional

- [chown, lchown, fchownat](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) - ownership is not modelled, as for `fchown`: the path is looked up first, as FreeBSD 11.4's [`kern_fchownat`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/vfs_syscalls.c#L2614-L2633) runs `namei` before `setfown` (`EFAULT` for a null path, `ENOENT` for an empty or missing one, `ENOTDIR` through a file, `ENAMETOOLONG` for a path of 1024 bytes or more or a component over 255, `ELOOP` from the host), then the guest's own owner and group (0) and the unchanged value (-1) are accepted and any other owner or group throws, naming the path. `chown` follows a final symbolic link and `lchown` does not; `fchownat` rejects flags other than `AT_SYMLINK_NOFOLLOW` (0x200) with `EINVAL` first, as `sys_fchownat` does, passes `AT_FDCWD` (-100) and absolute paths to the guest path resolver and joins any other relative path to the descriptor's host directory, as `openat` does (`EBADF`, `ENOTDIR`). The console's ownership rules are unverified
- [linkat](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) follows FreeBSD 11.4's [`sys_linkat` and `kern_linkat`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/vfs_syscalls.c#L1306-L1420) over `link`: a flag other than `AT_SYMLINK_FOLLOW` (0x400) returns `EINVAL`, both paths are resolved as for `fchownat` (`EFAULT`, `ENOENT`, `ENAMETOOLONG`, `EBADF`, `ENOTDIR`), then a missing source returns `ENOENT`, a directory `EPERM`, an existing new name `EEXIST` and a link across host volumes `EXDEV`. With `AT_SYMLINK_FOLLOW` a symbolic link's target is linked, as `link` does; without it a source that is a symbolic link throws, since the host cannot be relied on to link the link itself, which is what FreeBSD does. Console behaviour is unverified
- [lchmod](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) is `fchmodat(AT_FDCWD, path, mode, AT_SYMLINK_NOFOLLOW)`, as FreeBSD 11.4's [`sys_lchmod`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/vfs_syscalls.c#L2490-L2496) is, and has its limits (see `fchmodat`)
- [getlogin](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) follows FreeBSD 11.4's [`getlogin`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/lib/libc/gen/getlogin.c) and [`sys_getlogin`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/kern_prot.c#L2110-L2126): the name comes from libkernel's `getlogin_r` (the host account name, see libkernel) into one process-wide 33-byte (`MAXLOGNAME`) buffer under a lock, the first successful answer is kept for later calls, a name of 33 bytes or more returns null with `errno` `ERANGE`, and an empty name returns null. The console's login name is unknown
- [vfork](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) creates no process and fails like `fork` (-1, `errno` `ENOSYS`), as PPSA85300's PS5 compatibility layer does for both ([libc_missing.c](https://github.com/ZiZc3/VLC/blob/f3253020a64368153233ede29183014c0b6c8979/ps5/compat/libc_missing.c#L290-L292)); FreeBSD documents only `EAGAIN` and `ENOMEM`, and the console's answer is unverified
- [pthread_timedjoin_np](../../../core/libs/prx/libkernel_sys/Pthread.cpp) (libkernel_sys) follows FreeBSD 11.4's [`_pthread_timedjoin_np` and `join_common`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/lib/libthr/thread/thr_join.c), which shadPS4 also follows: a null deadline, a negative one or a nanosecond field outside 0 to 999999999 returns `EINVAL` before the thread is looked at, then the checks of libkernel's `scePthreadJoin` apply (`EINVAL` for a null or detached thread, `EDEADLK` for the caller, `ESRCH` for a joined one, `EOPNOTSUPP` while another thread joins it), and the wait ends with `ETIMEDOUT` once the `CLOCK_REALTIME` deadline passes, leaving the thread joinable. The deadline is turned into a host monotonic one when the call starts, so a later change of the guest real-time clock does not move it. The wait runs in libkernel (`PthreadTimedJoin_nid_no_patch`), which shares the join with `scePthreadJoin`
- [pthread_rwlock_reltimedrdlock_np, pthread_rwlock_reltimedwrlock_np, pthread_rwlockattr_settype_np](../../../core/libs/prx/libkernel_sys/Pthread.cpp) (libkernel_sys) are the PS4 extensions [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/kernel/threads/rwlock.cpp) implements, with its prototypes (`(rwlock, u32 usec)`, `(attr, type)`): the relative locks wait through libkernel's `scePthreadRwlockTimedrdlock` and `scePthreadRwlockTimedwrlock` and return their errors as POSIX values (`ETIMEDOUT`, `EDEADLK` for a read lock by the writer, `EINVAL` for a destroyed lock), and a statically initialized lock is created on first use. `pthread_rwlockattr_settype_np` returns `EINVAL` for a null or uninitialized attribute and stores any type, as libkernel's `scePthreadRwlockattrSettype` does; shadPS4 also refuses when the type already stored is above 2, a check of the previous value that is not applied here. None of this is measured on a PS5
- [scePthreadMutexInitForInternalLibc, scePthreadMutexattrInitForInternalLibc](../../../core/libs/prx/libkernel_sys/Pthread.cpp) (libkernel_sys) return libkernel's POSIX `pthread_mutex_init` and `pthread_mutexattr_init` errors biased by `0x80020000`, as [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/kernel/threads/mutex.cpp) (PS4) registers them (`ORBIS(posix_pthread_mutex_init)`, `ORBIS(posix_pthread_mutexattr_init)`), so they create the POSIX default (error-checking) mutex and attribute, where `scePthreadMutexInit` defaults differently. Not measured on a PS5
- [sceKernelGetCompiledSdkVersion](../../../core/libs/prx/libkernel_sys/Export.cpp) and [scePthreadCondattrGetclock](../../../core/libs/prx/libkernel_sys/Pthread.cpp) (libkernel_sys) run libkernel's implementations of the same exports: `sceKernelGetCompiledSdkVersion` shares the body of libkernel's (`CompiledSdkVersion_nid_no_patch`), and `scePthreadCondattrGetclock` returns `pthread_condattr_getclock`'s error biased by `0x80020000`, as [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/kernel/threads/condvar.cpp) registers it (`ORBIS(posix_pthread_condattr_getclock)`), so a null or uninitialized attribute returns `EINVAL` where libkernel's own `scePthreadCondattrGetclock` throws. - [pwrite](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) shares the POSIX positioned-write implementation and remaining limitations of [libkernel](libkernel.md), including error precedence and Windows append handling. Console behaviour is unverified.

- [fchdir](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) changes the guest working directory to the descriptor's directory: on Windows through the path recorded when the descriptor was opened, on Linux through the `/proc/self/fd` link target. It returns `EBADF` for a descriptor that is not open and `ENOTDIR` for one that is not a directory. Outside Windows it checks search permission on the directory with `faccessat`, which fails with `EACCES` as FreeBSD `change_dir` does; on Windows that check is not modelled. A directory renamed after it was opened is still reached through the recorded path. Console behaviour is unverified
- [openat](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) passes `AT_FDCWD` (-100) and absolute paths to `open`. Any other relative path is joined to the descriptor's host directory, found the same way as for `fchdir`, so guest path aliases and case-insensitive name matching do not apply to it, and a `..` component is not kept inside the guest root. It returns `EBADF` for a descriptor that is not open and `ENOTDIR` for one that is not a directory. As with `open`, `O_NOFOLLOW` and `O_NONBLOCK` are ignored. PPSA99003 opens directory entries this way. Console behaviour is unverified
- [fchmodat](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) passes `AT_FDCWD` (-100) and absolute paths to `chmod`; any other relative path is joined to the descriptor's host directory the same way as for `openat`, so guest path aliases and case-insensitive name matching do not apply to it and a `..` component is not kept inside the guest root. A flag other than `0` or `AT_SYMLINK_NOFOLLOW` (0x200) returns `EINVAL`; the mode is masked to `07777`. With `AT_SYMLINK_NOFOLLOW` a symbolic link returns success silently on Windows and Linux, since the host cannot change a link's own mode, while a regular file is changed either way. The mode maps to the host file mode, which on Windows is only the CRT's read-only bit. PPSA99621 calls it through `std::filesystem::permissions`. Console behaviour is unverified
- [pathconf, fpathconf, _fpathconf](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) query filesystem configuration values. `pathconf` looks the path up as FreeBSD 11's `kern_pathconf` does (links followed, `ENAMETOOLONG` for a path of 1024 bytes or more or a component over 255). `fpathconf` and `_fpathconf` follow FreeBSD 11.4's [`kern_fpathconf`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/kern_descrip.c): a descriptor that is not open fails with `EBADF` (libkernel's `fstat` decides, so guest sockets and app0.zar files are known), `_PC_ASYNC_IO` is `_POSIX_ASYNCHRONOUS_IO` (200112) for any descriptor, a pipe or a socket answers `_PC_PIPE_BUF` with `PIPE_BUF` (512) and every other name with `EINVAL`, and a descriptor that is neither, nor a file or a directory (a character device or a kqueue, whose console filesystems are not known), throws. For files and directories all three report the constants of FreeBSD 11's UFS `ufs_pathconf` for files and directories alike: `_PC_LINK_MAX` 32767, `_PC_NAME_MAX` 255, `_PC_PATH_MAX` and `_PC_SYMLINK_MAX` 1024, `_PC_PIPE_BUF` 512, `_PC_CHOWN_RESTRICTED` and `_PC_NO_TRUNC` 1, `_PC_FILESIZEBITS` 64, `_PC_REC_MAX_XFER_SIZE` -1, `_PC_PRIO_IO` and `_PC_SYNC_IO` 0. Whether the console's filesystems report the same is not verified. For files and directories they throw for the names whose UFS value depends on the mount (`_PC_ALLOC_SIZE_MIN`, `_PC_REC_INCR_XFER_SIZE`, `_PC_REC_MIN_XFER_SIZE`, `_PC_MIN_HOLE_SIZE`), the kernel options (`_PC_ACL_EXTENDED`, `_PC_ACL_PATH_MAX`, `_PC_ACL_NFS4`, `_PC_MAC_PRESENT`) or the page size (`_PC_REC_XFER_ALIGN`), and on which UFS and `vop_stdpathconf` disagree (`_PC_MAX_CANON`, `_PC_MAX_INPUT`, `_PC_VDISABLE`, `_PC_ASYNC_IO`); other names fail with `EINVAL`
- [mkdirat](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) passes `AT_FDCWD` (-100) and absolute paths to `mkdir`. Any other relative path is joined to the descriptor's host directory, found the same way as for `fchdir`, so guest path aliases and case-insensitive name matching do not apply to it, and a `..` component is not kept inside the guest root. It returns `EBADF` for a descriptor that is not open and `ENOTDIR` for one that is not a directory. On Windows, `mode` is ignored. Console behaviour is unverified
- [readlink and symlink](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) - `symlink` stores a relative target as given and an absolute one as the absolute host path that the guest path resolves to (through the run directory or a mount alias such as `/savedata0`), so the host follows the link; an absolute target that the guest path resolver rejects (a `..` after a missing directory or a file, an unmounted alias) throws. `readlink` returns a relative target as stored, with `/` separators on Windows, and maps an absolute host target back to a guest path through the first mount alias whose host directory holds it, otherwise through the run directory ([`GuestPathFromHost`](../../../core/libs/prx/libc/src/General.cpp)); a target outside both throws, as a host path has no guest form. The result can differ from the text given to `symlink` (letter case resolved against existing names, `.` and `..` components and repeated slashes removed, another alias of the same directory), where FreeBSD returns the stored text unchanged, and a link with an absolute target breaks when the run directory moves. On Windows a junction is read like a symbolic link with an absolute target (its print name, or its substitute name without `\??\`), and any other reparse point is a file that is not a link (`EINVAL`). Both report FreeBSD's `ENAMETOOLONG` for a path of 1024 bytes or more or a component over 255 before the lookup, and `symlink` also for a target of 1024 bytes or more; `symlink` returns `ENOTDIR` when the new name's parent is a file or lies under one, and maps the host's `EACCES`, `EROFS`, `ENOSPC` and `ENAMETOOLONG`. The guest filesystem has no read-only mounts, so a link created under `/app0` gets what the host directory allows instead of `EROFS`. An empty target fails with `ENOENT`, as on Linux, where FreeBSD's UFS accepts it. Console behaviour is unverified
- [readlink](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) on Windows reads a symbolic link's target from its reparse data and returns it with `/` separators, only when the target is relative, as `symlink` creates them. A symbolic link with an absolute target returns its print name, or its substitute name when the print name is empty, without a `\??\` or `\\?\` prefix. A directory junction returns the same kind of name when it is a drive path (`X:\...`), using the print name when that is a drive path and the substitute name otherwise. A mounted volume, whose substitute name is `\??\Volume{GUID}\`, stays a throw, because the name left after the prefix is not a drive path. Any other reparse point throws too, where FreeBSD reports `EINVAL` for a file that is not a link

- [fork](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) creates no process: it returns -1 with `errno` set to `ENOSYS` (78), as a title cannot start a process. The console's errno is unverified: FreeBSD's `fork` documents only `EAGAIN` and `ENOMEM`, and `ENOSYS` is what PPSA85300's PS5 compatibility layer returns from its own `fork` and `vfork` ([libc_missing.c](https://github.com/ZiZc3/VLC/blob/f3253020a64368153233ede29183014c0b6c8979/ps5/compat/libc_missing.c#L290-L292)), the one PS5 source found; `EAGAIN` would invite callers to retry. - [chroot](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) follows FreeBSD 11.4's [`sys_chroot`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/vfs_syscalls.c#L776-L807) and [`pwd_chroot`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/kern_descrip.c#L3059-L3085) for a root caller: `EFAULT` for a null path, `ENOENT` for an empty or missing one, `ENAMETOOLONG` for a path of 1024 bytes or more or a component over 255, and `ENOTDIR` for a path that is not a directory or passes through a file. - [scePthreadBarrier*, scePthreadBarrierattr*, scePthreadGetcpuclockid, scePthreadGetconcurrency and sceKernelMsync](../../../core/libs/prx/libkernel_sys/Export.Discovery.cpp) (libkernel_sys) call libkernel's `pthread_barrier*`, `pthread_getcpuclockid`, `pthread_getconcurrency` and `msync` and turn a POSIX error into `0x80020000 | errno`; that the console's `sce` forms do the same is not measured. Signatures follow the [Orbital type database](https://github.com/AlexAltea/orbital/blob/master/tools/ida/db_types.json); `scePthreadBarrierInit` ignores its name, and `scePthreadBarrierWait` returns -1 to the serial thread, both as in [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/kernel/threads/barrier.cpp) (PS4). `scePthreadGetconcurrency` returns the level unchanged
- [scePthreadAttrGetscope, scePthreadAttrSetscope, scePthreadAtfork and scePthreadSetconcurrency](../../../core/libs/prx/libkernel_sys/Export.Discovery.cpp) (libkernel_sys) call libkernel's `pthread_attr_getscope`, `pthread_attr_setscope`, `pthread_atfork` and `pthread_setconcurrency` and turn a POSIX error into `0x80020000 | errno`, as [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/15abf68c9b52c4b04d094f2837719fdb871021f3/src/core/libraries/kernel/threads/pthread_attr.cpp#L392) exports `scePthreadAttrGetscope` as `ORBIS(posix_pthread_attr_getscope)`; shadPS4 has no export for the other three, whose names and NIDs are in the [symbol database](https://github.com/zecoxao/sce_symbols/blob/2883963a0a514ba6e77407a08ef4730a65e88254/aerolib.csv) and whose signatures follow the same POSIX forms. Not measured on a console. As in libkernel, the scope is 0 (process) or 2 (system), and `scePthreadAtfork` handlers are only recorded, as no process forks
