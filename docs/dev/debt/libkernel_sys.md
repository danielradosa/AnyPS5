# libkernel_sys technical debt

### Silent stubs
- [pthread_mutex_setname_np, pthread_cond_setname_np, pthread_rwlock_setname_np, sem_setname](../../../core/libs/prx/libkernel_sys/Pthread.cpp) (libkernel_sys) - the name is kept nowhere and the call returns 0, as libkernel's mutexes, condition variables, read-write locks and semaphores have no name (`scePthreadMutexInit`, `scePthreadCondInit` and `scePthreadRwlockInit` ignore theirs too) and no export reads one back. Argument checks follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/kernel/threads/condvar.cpp) (PS4): a null name returns `EINVAL` from the condition-variable and read-write-lock calls, -1 with `errno` `EINVAL` from `sem_setname`, and is accepted by `pthread_mutex_setname_np`; a null object pointer, which shadPS4 dereferences, throws
- [fchmodat](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) - `AT_SYMLINK_NOFOLLOW` on a symbolic link (on Windows and Linux), and so `lchmod` on one

### Functional

- [sceKernelGetModuleInfoInternal](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) fills the extended module record (`ModuleInfoEx`, as libkernel's `sceKernelGetModuleInfoFromAddr` fills it) for a module handle through libkernel's `sceKernelGetModuleInfo` lookup (`ModuleInfoExForHandle_nid_no_patch`), with the checks of [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/kernel/process.cpp) (PS4, `HZO7xOos4xc`): `EFAULT` for a null record, `EINVAL` when `st_size` is not the record size, `ESRCH` for an unknown handle; the prototype is OpenOrbis' `int32_t sceKernelGetModuleInfoInternal(OrbisKernelModule handle, OrbisKernelModuleInfoEx* info)`. System libraries are reported too, as `sceKernelGetModuleInfo` does. Console behaviour is unverified
- [sceKernelIsInSandbox](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) returns 1, as [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/kernel/process.cpp) answers for a title (prototype `int32_t sceKernelIsInSandbox(void)` from OpenOrbis), matching the sandbox libkernel models with `sceKernelGetFsSandboxRandomWord`
- [tcgetsid, tcsetsid](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) follow FreeBSD 11.4's [`termios.c`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/lib/libc/gen/termios.c): `tcsetsid` returns `EINVAL` for a process id other than `getsid(0)`, and both then fail as their `TIOCGSID` and `TIOCSCTTY` ioctls do on a descriptor that is not a terminal, with the errors libkernel's `tcgetattr` gives (`EBADF`, `ENOTTY`, and for sockets `EADDRNOTAVAIL` or `EOPNOTSUPP`), which FreeBSD's file, pipe and socket ioctl paths give for these requests as well. A descriptor libkernel took for a terminal throws, as terminal sessions are not modelled
- [pselect](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) follows FreeBSD 11.4's [`sys_pselect` and `kern_pselect`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/sys_generic.c) over libkernel's `select` and `sigprocmask`: the timeout is truncated to microseconds as `TIMESPEC_TO_TIMEVAL` does (so `select` rejects a nanosecond field outside 0 to 999999999 with `EINVAL`), a given mask is installed for the call and the previous one restored afterwards, also when `select` fails. The mask is not swapped atomically with the wait: a signal unblocked by the mask that arrives just before the wait starts is not guaranteed to cut it short with `EINTR`, which libkernel's `select` does not report anyway. Console behaviour is unverified
- [settimeofday, sceKernelSettimeofday](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) check like FreeBSD 11.4's [`kern_settimeofday`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/kern_time.c#L687-L707) for a root caller: a time with a negative second count or a microsecond count outside 0 to 999999 fails with `EINVAL`, and null time and zone succeed. A valid time throws, as `clock_settime` does, since the host clock is never set; a zone of 0 minutes west without daylight saving succeeds, as it is the zone libkernel's `gettimeofday` reports, and any other zone throws, since no kernel zone is kept. `sceKernelSettimeofday` (prototype from [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/kernel/time.cpp), which stubs both) returns the error biased by `0x80020000`. Whether a title holds `PRIV_SETTIMEOFDAY` on the console, which FreeBSD checks first, is unverified
- [sceKernelMlockall](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) is libkernel's `mlockall` with its error biased by `0x80020000` (prototype `int sceKernelMlockall(int flags)` from Orbital), so invalid flags return `SCE_KERNEL_ERROR_EINVAL` and a valid request throws as `mlockall` does
- [sem_open, sem_close, sem_unlink](../../../core/libs/prx/libkernel_sys/Semaphore.cpp) (libkernel_sys) follow FreeBSD 11.4's [`sem_new.c`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/lib/libc/gen/sem_new.c), but a name's backing file `/tmp/SEMD<name>` is a process-local entry instead of a file, so named semaphores are not seen by other processes or later runs, and do not appear in `/tmp`. A name not starting with `/` fails with `EINVAL` (`ENOENT` for `sem_unlink`), a `/tmp/SEMD` path of 1024 bytes or more or a file name over 255 bytes with `ENAMETOOLONG`, flags other than `O_CREAT` and `O_EXCL` with `EINVAL`, a missing name without `O_CREAT` with `ENOENT`, and an existing one with `O_CREAT | O_EXCL` with `EEXIST`; opening a name this process already has open returns the same `sem_t` and counts the open, and once the name was unlinked and created again a later open gets the new semaphore, as FreeBSD compares the file's device and inode. The semaphore is a libkernel POSIX semaphore (`sem_init` with `pshared` 1), so `sem_wait`, `sem_post` and the other calls work on it; an initial value above `SEM_VALUE_MAX` fails with `EINVAL` as `sem_init` does, where FreeBSD's `sem_open` stores it unchecked. `sem_close` returns `EINVAL` for a `sem_t` that is not an open named semaphore (an unnamed one included) and releases the semaphore when it is closed and unlinked; `sem_unlink` returns `ENOENT` for a missing name and leaves open handles working. A name with a further `/`, which would name a file below a `/tmp/SEMD...` directory, and a null name throw. Console behaviour is unverified
- [aio_read, aio_write, aio_fsync, aio_error, aio_return, aio_suspend, aio_cancel, aio_waitcomplete](../../../core/libs/prx/libkernel_sys/Aio.cpp) (libkernel_sys) follow FreeBSD 11.4's [`vfs_aio.c`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/vfs_aio.c) with the 160-byte `struct aiocb` of its `sys/aio.h` (ps5-payload-sdk), but a request is carried out by the submitting thread before `aio_read`, `aio_write` or `aio_fsync` returns, through libkernel's `pread`, `pwrite` and `fsync`, where FreeBSD hands it to its AIO daemons; POSIX allows a request to complete before the call returns. Submission follows `aio_aqueue`: the private status, error and kernel reference are reset, more than 256 requests not yet collected (`max_aio_queue_per_proc`) fail with `EAGAIN`, a size above `SSIZE_MAX` with `EINVAL` (not stored), an unknown notification with `EINVAL`, a signal notification with an invalid signal with `EINVAL`, a descriptor that is not open or lacks the needed read or write access with `EBADF`, `aio_fsync` on a pipe or socket and a negative offset with `EINVAL`, a read or write on a pipe with `EOPNOTSUPP` (`vfs.aio.enable_unsafe` 0), and `aio_fsync` with an `op` other than `O_SYNC` with `EINVAL`; each stores its error in the control block where FreeBSD does, so `aio_error` reports it. Until `aio_return` or `aio_waitcomplete` collects a request its control block keeps `EINPROGRESS` and status -1, as on FreeBSD; `aio_error` answers `EINPROGRESS` only while another thread is still transferring. `aio_return` and `aio_waitcomplete` return the status, or -1 with the request's error, and forget the request; `aio_suspend` returns at once when a listed request is done or none is known (`EAGAIN` before the first request), waits for another thread's transfer otherwise, and checks its count, list and timeout as `sys_aio_suspend` does; `aio_waitcomplete` takes the oldest completed request, fails with `EAGAIN` at once for a zero timeout and after a timeout, and waits without one until another thread completes a request. `aio_cancel` returns `EBADF` for a descriptor that is not open, `AIO_NOTCANCELED` for a request another thread is transferring, which FreeBSD cannot cancel once it runs, and `AIO_ALLDONE` otherwise. Signal, thread-id and kevent notifications throw after the checks, as libkernel delivers none; sockets and character devices throw, since FreeBSD completes socket requests when data arrives and serves disks through its bio path. Interrupting a wait with a signal (`EINTR`) is not modelled, and console behaviour is unverified
- [chown, lchown, fchownat](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) - ownership is not modelled, as for `fchown`: the path is looked up first, as FreeBSD 11.4's [`kern_fchownat`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/vfs_syscalls.c#L2614-L2633) runs `namei` before `setfown` (`EFAULT` for a null path, `ENOENT` for an empty or missing one, `ENOTDIR` through a file, `ENAMETOOLONG` for a path of 1024 bytes or more or a component over 255, `ELOOP` from the host), then the guest's own owner and group (0) and the unchanged value (-1) are accepted and any other owner or group throws, naming the path. `chown` follows a final symbolic link and `lchown` does not; `fchownat` rejects flags other than `AT_SYMLINK_NOFOLLOW` (0x200) with `EINVAL` first, as `sys_fchownat` does, passes `AT_FDCWD` (-100) and absolute paths to the guest path resolver and joins any other relative path to the descriptor's host directory, as `openat` does (`EBADF`, `ENOTDIR`). The console's ownership rules are unverified
- [linkat](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) follows FreeBSD 11.4's [`sys_linkat` and `kern_linkat`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/vfs_syscalls.c#L1306-L1420) over `link`: a flag other than `AT_SYMLINK_FOLLOW` (0x400) returns `EINVAL`, both paths are resolved as for `fchownat` (`EFAULT`, `ENOENT`, `ENAMETOOLONG`, `EBADF`, `ENOTDIR`), then a missing source returns `ENOENT`, a directory `EPERM`, an existing new name `EEXIST` and a link across host volumes `EXDEV`. With `AT_SYMLINK_FOLLOW` a symbolic link's target is linked, as `link` does; without it a source that is a symbolic link throws, since the host cannot be relied on to link the link itself, which is what FreeBSD does. Console behaviour is unverified

- [pthread_timedjoin_np](../../../core/libs/prx/libkernel_sys/Pthread.cpp) (libkernel_sys) follows FreeBSD 11.4's [`_pthread_timedjoin_np` and `join_common`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/lib/libthr/thread/thr_join.c), which shadPS4 also follows: a null deadline, a negative one or a nanosecond field outside 0 to 999999999 returns `EINVAL` before the thread is looked at, then the checks of libkernel's `scePthreadJoin` apply (`EINVAL` for a null or detached thread, `EDEADLK` for the caller, `ESRCH` for a joined one, `EOPNOTSUPP` while another thread joins it), and the wait ends with `ETIMEDOUT` once the `CLOCK_REALTIME` deadline passes, leaving the thread joinable. The wait runs in libkernel (`PthreadTimedJoin_nid_no_patch`), which shares the join with `scePthreadJoin`

- [fchdir](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) changes the guest working directory to the descriptor's directory: on Windows through the path recorded when the descriptor was opened, on Linux through the `/proc/self/fd` link target. It returns `EBADF` for a descriptor that is not open and `ENOTDIR` for one that is not a directory. Outside Windows it checks search permission on the directory with `faccessat`, which fails with `EACCES` as FreeBSD `change_dir` does; on Windows that check is not modelled. A directory renamed after it was opened is still reached through the recorded path. Console behaviour is unverified
- [openat](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) passes `AT_FDCWD` (-100) and absolute paths to `open`. Any other relative path is joined to the descriptor's host directory, found the same way as for `fchdir`, so guest path aliases and case-insensitive name matching do not apply to it, and a `..` component is not kept inside the guest root. It returns `EBADF` for a descriptor that is not open and `ENOTDIR` for one that is not a directory. As with `open`, `O_NOFOLLOW` and `O_NONBLOCK` are ignored. PPSA99003 opens directory entries this way. Console behaviour is unverified
- [fchmodat](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) passes `AT_FDCWD` (-100) and absolute paths to `chmod`; any other relative path is joined to the descriptor's host directory the same way as for `openat`, so guest path aliases and case-insensitive name matching do not apply to it and a `..` component is not kept inside the guest root. A flag other than `0` or `AT_SYMLINK_NOFOLLOW` (0x200) returns `EINVAL`; the mode is masked to `07777`. With `AT_SYMLINK_NOFOLLOW` a symbolic link returns success silently on Windows and Linux, since the host cannot change a link's own mode, while a regular file is changed either way. The mode maps to the host file mode, which on Windows is only the CRT's read-only bit. PPSA99621 calls it through `std::filesystem::permissions`. Console behaviour is unverified
- [pathconf, fpathconf, _fpathconf](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) query filesystem configuration values. `pathconf` looks the path up as FreeBSD 11's `kern_pathconf` does (links followed, `ENAMETOOLONG` for a path of 1024 bytes or more or a component over 255). `fpathconf` and `_fpathconf` follow FreeBSD 11.4's [`kern_fpathconf`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/kern_descrip.c): a descriptor that is not open fails with `EBADF` (libkernel's `fstat` decides, so guest sockets and app0.zar files are known), `_PC_ASYNC_IO` is `_POSIX_ASYNCHRONOUS_IO` (200112) for any descriptor, a pipe or a socket answers `_PC_PIPE_BUF` with `PIPE_BUF` (512) and every other name with `EINVAL`, and a descriptor that is neither, nor a file or a directory (a character device or a kqueue, whose console filesystems are not known), throws. For files and directories all three report the constants of FreeBSD 11's UFS `ufs_pathconf` for files and directories alike: `_PC_LINK_MAX` 32767, `_PC_NAME_MAX` 255, `_PC_PATH_MAX` and `_PC_SYMLINK_MAX` 1024, `_PC_PIPE_BUF` 512, `_PC_CHOWN_RESTRICTED` and `_PC_NO_TRUNC` 1, `_PC_FILESIZEBITS` 64, `_PC_REC_MAX_XFER_SIZE` -1, `_PC_PRIO_IO` and `_PC_SYNC_IO` 0. Whether the console's filesystems report the same is not verified. For files and directories they throw for the names whose UFS value depends on the mount (`_PC_ALLOC_SIZE_MIN`, `_PC_REC_INCR_XFER_SIZE`, `_PC_REC_MIN_XFER_SIZE`, `_PC_MIN_HOLE_SIZE`), the kernel options (`_PC_ACL_EXTENDED`, `_PC_ACL_PATH_MAX`, `_PC_ACL_NFS4`, `_PC_MAC_PRESENT`) or the page size (`_PC_REC_XFER_ALIGN`), and on which UFS and `vop_stdpathconf` disagree (`_PC_MAX_CANON`, `_PC_MAX_INPUT`, `_PC_VDISABLE`, `_PC_ASYNC_IO`); other names fail with `EINVAL`
- [mkdirat](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) passes `AT_FDCWD` (-100) and absolute paths to `mkdir`. - [readlink and symlink](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) - `symlink` stores a relative target as given and an absolute one as the absolute host path that the guest path resolves to (through the run directory or a mount alias such as `/savedata0`), so the host follows the link; an absolute target that the guest path resolver rejects (a `..` after a missing directory or a file, an unmounted alias) throws. `readlink` returns a relative target as stored, with `/` separators on Windows, and maps an absolute host target back to a guest path through the first mount alias whose host directory holds it, otherwise through the run directory ([`GuestPathFromHost`](../../../core/libs/prx/libc/src/General.cpp)); a target outside both throws, as a host path has no guest form. The result can differ from the text given to `symlink` (letter case resolved against existing names, `.` and `..` components and repeated slashes removed, another alias of the same directory), where FreeBSD returns the stored text unchanged, and a link with an absolute target breaks when the run directory moves. On Windows a junction is read like a symbolic link with an absolute target (its print name, or its substitute name without `\??\`), and any other reparse point is a file that is not a link (`EINVAL`). Both report FreeBSD's `ENAMETOOLONG` for a path of 1024 bytes or more or a component over 255 before the lookup, and `symlink` also for a target of 1024 bytes or more; `symlink` returns `ENOTDIR` when the new name's parent is a file or lies under one, and maps the host's `EACCES`, `EROFS`, `ENOSPC` and `ENAMETOOLONG`. The guest filesystem has no read-only mounts, so a link created under `/app0` gets what the host directory allows instead of `EROFS`. An empty target fails with `ENOENT`, as on Linux, where FreeBSD's UFS accepts it. Console behaviour is unverified
- [readlink](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) on Windows reads a symbolic link's target from its reparse data and returns it with `/` separators, only when the target is relative, as `symlink` creates them. A symbolic link with an absolute target returns its print name, or its substitute name when the print name is empty, without a `\??\` or `\\?\` prefix. A directory junction returns the same kind of name when it is a drive path (`X:\...`), using the print name when that is a drive path and the substitute name otherwise. A mounted volume, whose substitute name is `\??\Volume{GUID}\`, stays a throw, because the name left after the prefix is not a drive path. Any other reparse point throws too, where FreeBSD reports `EINVAL` for a file that is not a link

- [ktimer_create, ktimer_delete, ktimer_settime, ktimer_gettime, ktimer_getoverrun](../../../core/libs/prx/libkernel_sys/Timers.cpp) (libkernel_sys) follow FreeBSD 11.4's POSIX timers in [`kern_time.c`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/kern_time.c#L1158-L1690) (`kern_ktimer_create`, `kern_ktimer_delete`, `realtimer_settime`, `realtimer_gettime`, `realtimer_expire`, `itimer_fire`, `itimer_accept`) per process: only `CLOCK_REALTIME` and `CLOCK_MONOTONIC` take timers (`EINVAL` for other clocks), a notification other than `SIGEV_NONE`, `SIGEV_SIGNAL` and `SIGEV_THREAD_ID` (so also `SIGEV_THREAD`, which FreeBSD's librt builds on `SIGEV_THREAD_ID`; no PS5 export of `timer_create` was found) or a signal outside 1 to 128 returns `EINVAL`, ids 3 to 31 are handed out (`EAGAIN` once all are taken), a null id output returns `EFAULT` without keeping the timer, and a null event means `SIGEV_SIGNAL` with `SIGALRM` and the id as value. `ktimer_settime` returns `EFAULT` for a null value before it looks at the id, `EINVAL` for a value, or the interval of a set value, with a negative field or 1000000000 nanoseconds or more, honours `TIMER_ABSTIME` (1) and reports the previous setting as `ktimer_gettime` does (the remaining time, or 1 ns once it is due). Expiries run on a host thread: missed periods count as overruns, as does an expiry while the previous signal is still queued, and the signal is queued through libkernel's signal emulation with `SI_TIMER`, the value, the timer id and the overrun count as of the moment the signal is taken, which `ktimer_getoverrun` then returns; deleting a timer removes its queued signal. A `SIGEV_THREAD_ID` timer whose thread is gone is disarmed when it expires, as `sigev_findtd` fails; a live thread is not targeted, since the emulation keeps one process-wide pending set. A `SIGEV_NONE` timer is advanced when it is read. Delivery while no thread blocks the signal is not modelled: an ignored signal is dropped, `SIGALRM` with the default disposition exits the process as libkernel's alarm does, and any other disposition throws from the timer thread. An interval below 1 ms throws, as `setitimer` does, because FreeBSD rounds it up to a clock tick whose length on the console is not known; a value below a tick is not rounded. Console behaviour is unverified
- [ksem_init, ksem_open, ksem_unlink, ksem_close, ksem_destroy, ksem_post, ksem_wait, ksem_trywait, ksem_timedwait, ksem_getvalue](../../../core/libs/prx/libkernel_sys/KernelSemaphores.cpp) (libkernel_sys) follow FreeBSD 11.4's [`uipc_sem.c`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/uipc_sem.c#L457-L925) with libkernel's POSIX semaphores as the counters, so `ksem_wait` and `ksem_timedwait` are cancellation points as `sem_wait` is, where FreeBSD's syscalls are not. A semaphore id is a reserved host descriptor (as libkernel's `kqueue` reserves one), so `close` ends it as FreeBSD's `kern_close` does, but `dup` and `fstat` do not see a semaphore. A value above `SEM_VALUE_MAX` returns `EINVAL`, flags other than `O_CREAT` and `O_EXCL` for `ksem_open` `EINVAL`, a null id output `EFAULT` (no descriptor is kept), a descriptor that is not a semaphore `EINVAL` from every call, `ksem_close` of an anonymous one and `ksem_destroy` of a named one `EINVAL`, `ksem_destroy` while a thread waits `EBUSY`, a post at the maximum `EOVERFLOW`, an invalid `ksem_timedwait` nanosecond count `EINVAL` before the id is looked at and a passed deadline `ETIMEDOUT`. `ksem_open` with a null name creates an anonymous semaphore, as `ksem_create` does. Names live in a process-local dictionary, so other processes do not see them; a name must start with `/` (`EINVAL`), a missing one without `O_CREAT` gives `ENOENT`, an existing one with `O_CREAT | O_EXCL` `EEXIST`, and `ksem_unlink` of a missing one `ENOENT`. The name length limit is taken as `MAXPATHLEN` (`ENAMETOOLONG` from 1024 bytes on), as for a caller outside a jail: FreeBSD prefixes a jailed caller's names with the jail's path, which is not known for the console. At most 30 semaphores (`SEM_MAX`) exist at once, counted in this process only, after which `ksem_init` returns `ENOSPC` and a creating `ksem_open` `ENFILE`. Modes and ownership are not modelled, as the guest is its semaphores' owner. Console behaviour is unverified
