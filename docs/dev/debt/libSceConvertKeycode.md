### Unknown function info

- [sceConvertKeycodeGetCharacter](../../../core/libs/prx/libSceConvertKeycode/Export.cpp) (libSceConvertKeycode) - the signature `int (uint16_t keycode, uint32_t status, SceImeKeyboardType keyboardType, wchar_t* character)` is [Orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json#L570)'s, with the guest's 16-bit `wchar_t`. [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Input/KeycodeConverter.cs#L175-L194) packs the USB modifier byte into bits 8 to 15 of `status` and the Num, Caps and Scroll Lock LEDs into bits 16 to 18, and numbers the keyboard types, 4 being US English ([#L15-L106](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Input/KeycodeConverter.cs#L15-L106)); other `status` bits and every keyboard type other than 4 and 0 throw. Type 0, which SharpProspero calls None, is the type this runtime's `sceConvertKeycodeGetImeKeyboardType` reports, so it is taken as US English; the console's answer for it is unknown. A null `character` returns `0x80BC0031`, the invalid-address code `sceConvertKeycodeGetImeKeyboardType` returns for its null output in [KytyPS5](https://github.com/KytyPS5/KytyPS5/blob/df5b9b92be7dfd463b47756b707d6d356a9f0550/src/libs/libConvertKeycode.cpp#L13-L28), before the other arguments are looked at; neither the code nor the order is measured

### Functional

- [sceConvertKeycodeGetCharacter](../../../core/libs/prx/libSceConvertKeycode/Export.cpp) (libSceConvertKeycode) takes the keycode as a USB HID keyboard usage and gives the character that [sceKeyboardGetKey2Char](../../../core/libs/prx/libSceKeyboard/src/keyboard_impl.cpp) gives for the 101-key arrangement with the same LEDs and modifiers: Shift and Caps Lock select capitals, Num Lock the keypad digits, Ctrl and Alt change nothing, and Enter, Backspace and Tab give their control characters. A key without a character (Escape, function, cursor and modifier keys) returns 0 with the character 0, as SharpProspero describes the null character for such keys; whether the console returns an error code for it instead is not measured. Layouts other than US English are not implemented
