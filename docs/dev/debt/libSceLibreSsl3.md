# libSceLibreSsl3 technical debt

### Unknown function info

- [libSceLibreSsl3 pending exports](../../../core/libs/prx/libSceLibreSsl3/Export.cpp) - the named callable exports still declared there are listed in the [PS5 3.20 export table](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceLibreSsl3.c) and were cross-checked against the same module in PS5 firmware 13.60. Their signatures and behaviour are unverified; the declarations use the no-parameter unknown-signature convention and throw through `NotImplemented_nid_no_patch`.
- [MD5, SHA1 and CRYPTO_memcmp](../../../core/libs/prx/libSceLibreSsl3/src/Digest.cpp) (libSceLibreSsl3) - follow LibreSSL's [md5.c, sha1.c](https://github.com/libressl/openbsd/tree/bc9483725c5815efb64b6d9acc52fc5fba139212/src/lib/libcrypto) and `CRYPTO_memcmp`, which returns the OR of the differing bytes in 3.0 through current; `MD5` and `SHA1` hash through libSceLibreSsl's `MD5_*` and `SHA1_*`. A null digest buffer throws: LibreSSL up to 3.8 returns a static buffer, later versions do not check it. Nothing is checked on the console

### Forwarded exports

- [EVP_sha1, EVP_sha224, EVP_MD_CTX_new, EVP_MD_CTX_free, EVP_DigestInit, EVP_EncryptInit, EVP_CIPHER_CTX_set_flags and EVP_aes_{128,192,256}_wrap](../../../core/libs/prx/libSceLibreSsl3/src/Evp.cpp) (libSceLibreSsl3) - prototypes from the [LibreSSL 3.4.1 headers](https://github.com/openbsd/src/tree/a37b3deb471156262bc68bcaa97d2cb9f78494f8/lib/libcrypto) (`EVP_MD_CTX` and `EVP_CIPHER_CTX` keep the layout of 2.6, which libSceLibreSsl uses), behaviour from the current EVP_DigestInit(3), EVP_EncryptInit(3), EVP_CIPHER_CTX_set_flags(3) and EVP_aes_128_cbc(3). The calls run in libSceLibreSsl (see its debt file), so contexts, digests and ciphers are interchangeable between the two modules. `EVP_MD_CTX_new` and `EVP_MD_CTX_free` are `EVP_MD_CTX_create` and `EVP_MD_CTX_destroy`; `EVP_DigestInit` clears the context and calls `EVP_DigestInit_ex`, so a context used before leaks its state unless it was reset, as the manual warns; `EVP_EncryptInit` with a cipher clears the context first (the manual: the context does not need to be initialized), which also drops `EVP_CIPHER_CTX_FLAG_WRAP_ALLOW`, so the wrap ciphers fail with it as documented. `EVP_CIPHER_CTX_set_flags` ORs the flags into the context. The module's own export list lacks the libSceLibreSsl calls a title also needs (`EVP_DigestUpdate`, `EVP_EncryptUpdate`, `BIO_new`, ...): titles importing those from libSceLibreSsl3 do not resolve against this build
- [BIO_up_ref, BIO_vfree, ERR_peek_last_error and ERR_load_crypto_strings](../../../core/libs/prx/libSceLibreSsl3/src/Runtime.cpp) (libSceLibreSsl3) - prototypes from the 3.4.1 `bio.h` and `err.h`, behaviour from BIO_new(3), ERR_get_error(3) and ERR_load_crypto_strings(3). `BIO_up_ref` adds a reference that `BIO_free` drops, `BIO_vfree` is `BIO_free` without a result, `ERR_peek_last_error` returns the newest code of the calling thread's libSceLibreSsl queue, and `ERR_load_crypto_strings` returns without doing anything, as no error strings are registered (see libSceLibreSsl)
- [X509_up_ref, d2i_X509_bio, X509_get_version, X509_get0_notBefore, X509_get0_notAfter, X509_getm_notBefore, X509_getm_notAfter, X509_get_ext_count, ASN1_STRING_get0_data, d2i_ASN1_INTEGER, ASN1_INTEGER_free and ASN1_OBJECT_free](../../../core/libs/prx/libSceLibreSsl3/src/X509.cpp) (libSceLibreSsl3) - prototypes from the 3.4.1 `x509.h` and `asn1.h`, behaviour from the current X509_new(3), d2i_X509(3), X509_get_version(3), X509_get0_notBefore(3), X509v3_get_ext_by_NID(3), ASN1_STRING_length(3) and ASN1_item_d2i(3); the certificates are libSceLibreSsl's (see its debt file). `X509_get_version` returns the version field (2 for v3), the time getters the certificate's own `ASN1_TIME` (UTCTime or GeneralizedTime as encoded), `X509_get_ext_count` the number of extensions in the TBSCertificate. `d2i_X509_bio` reads one DER certificate and leaves what follows in the BIO; data that is not one returns null and stays unread. `d2i_ASN1_INTEGER` decodes one INTEGER (magnitude, `V_ASN1_NEG_INTEGER` for negatives) that `ASN1_INTEGER_free` releases; freeing an integer that belongs to a certificate throws. `ASN1_OBJECT_free` does nothing for the static table objects (as for LibreSSL's static objects), frees the objects `OBJ_txt2obj` created and throws for a certificate's dynamic object. Reusing an existing object through the first argument throws
- [OBJ_cmp and OBJ_txt2obj](../../../core/libs/prx/libSceLibreSsl3/src/Objects.cpp) (libSceLibreSsl3) - prototypes from the 3.4.1 `objects.h`, behaviour from the current [OBJ_nid2obj(3)](https://github.com/openbsd/src/blob/74bf4f178707d7daa0f177d9db18893aa18b8a42/lib/libcrypto/man/OBJ_nid2obj.3); the object table is libSceLibreSsl's with the 3.4.1 `obj_mac.h` changes (see its debt file). `OBJ_txt2obj` with `no_name` 0 returns the static table object whose short or long name matches (a text that is the short name of one entry and the long name of another throws), otherwise it parses a dotted decimal OID into a new object with `NID_undef`, no names and the dynamic flags 0x0d, which `ASN1_OBJECT_free` frees; text that is no valid OID returns null, leading zeros and arcs above 64 bits throw. `OBJ_cmp` returns 0 for equal encodings (also for two objects without one), otherwise the difference of the lengths or of the first differing bytes; only zero and non-zero are documented. Null objects throw
