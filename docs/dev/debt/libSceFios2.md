### Functional

- [libSceFios2](../../../core/libs/prx/libSceFios2/Export.cpp) - nothing is measured on a PS4 or PS5. Files and directories go through libkernel's file calls (`sceKernelOpen`, `sceKernelStat`, the read and write calls, `sceKernelUnlink`, `sceKernelMkdir`, `sceKernelRmdir`, `sceKernelRename`, ...), so guest paths resolve as for them. Prototypes, the `SceFiosOpAttr` (48 bytes) and `SceFiosOpenParams` (24 bytes) layouts, the callback `(context, op, event, error)` with `COMPLETE` = 1, the open flags (read 1, write 2, append 4, create 8, truncate 0x10, 0x1000 direct I/O; null parameters read only; mode 0777 unless `sceFiosFHOpenWithMode` gives one other than -1), nanosecond times and the errors `BAD_PATH` (0x80820005) and `BAD_OP` (0x8082000A) follow [kalaposfos13/fios2](https://github.com/kalaposfos13/fios2/blob/ae6ca1d78e7a822c2528f7660959167b9b3d8b63/src/fios2.cpp) (shadPS4 Emulator Project, PS4)
  - Prototypes that kalaposfos13/fios2 leaves empty (writes, offset vector reads, truncation, sync, delete, rename, directory calls, the op getters, initialization and suspension) and the 64-bit returns of the seek, tell and Sync transfer calls are from [RPCS3's Vita module](https://github.com/RPCS3/rpcs3/blob/88fef183a365bcf7c0fb264b8fcb6019f840383e/rpcs3/Emu/PSP2/Modules/sceFios.cpp) of the same library, pointer-sized fields widened; `sceFiosFileExistsSync` (false for a directory) and `SCE_FIOS_HANDLE_INVALID` (0) from [GPCS4](https://github.com/Inori/GPCS4/blob/49e45885837fe8437202f597994c43d5c5094105/GPCS4/SceModules/SceFios2/sce_fios2.cpp)
  - Every op completes when it is submitted: its callback, if the attribute has one, is called once with `COMPLETE` and the op's error before the submitting call returns (Sync forms included); `START` and `DELETE` events are never delivered, deadlines and priorities are kept (`sceFiosOpReschedule` updates the deadline) but change nothing, `sceFiosIsIdle` is always true, and cancelling (`sceFiosOpCancel`, `sceFiosCancelAllOps`) finds the op complete, so `sceFiosOpIsCancelled` is false. A Sync form submits the op and deletes it, returning its error, or for a transfer its byte count. A null attribute is kept as zeros
  - Ops, file and directory handles share one counter from 1 (wrapping, skipping live handles), so `sceFiosIsValidHandle` is true for a live handle of any kind. An unknown op returns `BAD_OP` from the wait, error, delete and actual-count calls and is false for `sceFiosOpIsDone`; the other op getters, and every getter for a property the op does not have (a path for a handle op, a buffer for a vector op, an offset or a count for a non-transfer op), throw. `sceFiosFHGetPath` and `sceFiosDHGetPath` return null for an unknown handle
  - A missing path (kernel `ENOENT`) is `BAD_PATH`, and a failed open or directory open writes `SCE_FIOS_HANDLE_INVALID`; any other kernel error, an unknown file or directory handle, a null path or handle output, a negative length, opening a directory as a file or a file as a directory, creating a directory whose parent is missing (whether parents are created is unknown) or that already exists, and `sceFiosFileGetSizeSync` on a directory throw, as their console errors are unknown. A read past the end returns the bytes read with error 0; the console's end-of-file error, if any, is not known
  - `sceFiosInitialize` neither reads nor keeps its parameters; a null block, a second initialization, any op before it or after `sceFiosTerminate`, `sceFiosIsInitialized` with an output while initialized, and an op submitted while suspended (holding it until `sceFiosResume` is not modelled) throw, as does a resume that is not suspended. `sceFiosTerminate` and `sceFiosCloseAllFiles` close the open files (terminate also forgets directory handles and ops). `sceFiosTimeGetCurrent` is the host's steady clock in nanoseconds; the console's epoch for it is unknown
