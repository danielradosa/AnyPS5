# libSceAudioIn technical debt

### Silent stubs

- [sceAudioInInit](../../../core/libs/prx/libSceAudioIn/Export.cpp) (libSceAudioIn) - returns 0 without library-wide setup, as `sceAudioOutInit` does; each `sceAudioInOpen` opens its own SDL capture device

### Unknown function info

- [sceAudioInOpen](../../../core/libs/prx/libSceAudioIn/Export.cpp) (libSceAudioIn) - formats 1 and 2 (16-bit mono and stereo) and 0x11 and 0x12 (float mono and stereo) are the ones [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Audio/AudioIn.cs#L19-L32) lists. Format 0x10 opens a float mono port, the same as 0x11, as [KytyPS5](https://github.com/KytyPS5/KytyPS5/blob/df5b9b92be7dfd463b47756b707d6d356a9f0550/src/libs/audio.cpp#L1039-L1046) decodes it; KytyPS5 is the only source that accepts it and states no origin for it, and SharpProspero does not list it, so the console's reading of 0x10 is unverified. Format 0 returns `0x80260106`, as in KytyPS5, which [moved](https://github.com/KytyPS5/KytyPS5/commit/3cf426662e59135393182006a76393676be5200e) 16-bit mono from 0 to 1; [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/audio/audioin.h#L21) takes 0 as 16-bit mono but accepts only 0 and 2, the PS4 formats. `sceAudioInHqOpen` and `sceAudioInAsyncOpen` share these formats. No title seen passes 0 or 0x10: Astro Bot (PPSA21567) calls `sceAudioInOpen` once, at 0xff2bd6, with type 0, index 0, 256 samples, 16000 Hz and format 1, and on the other branch of the same function `sceAudioInHqOpen` at 0xff2b70 with type 1, index 0, 128 samples, 48000 Hz and format 2; SILENT HILL: The Short Message (PPSA10112) calls `sceAudioInOpen` once, at 0x48eab92, with type 0, index 0, 256 samples, 16000 Hz and format 1. Both pass the user id first and keep the result as the handle for `sceAudioInInput`; PPSA10112 takes a negative result as failure
- [sceAudioInIsPadEmbeddedMic](../../../core/libs/prx/libSceAudioIn/Export.cpp) (libSceAudioIn) - name from its NID (`X+4jdIS75P0`); signature `int32_t(int32_t handle)` from the Ghost of Yotei (PPSA26344) call site in #2355. Astro Bot (PPSA21567) compares the result with 1 at both of its call sites and takes 1 to mean that the port captures from the pad's microphone. A port reports 1 when it captures from the host's default recording device and that device's name contains "DualSense", the match AudioOut2 uses to find the pad's speaker, and 0 otherwise, also without a device; unknown handles return `0x80260101` like the other AudioIn calls. The console's code for an unknown handle and whether the result follows a change of device after the port opened are unknown

### Functional

- [sceAudioInHqOpen, sceAudioInAsyncOpen](../../../core/libs/prx/libSceAudioIn/Export.cpp) (libSceAudioIn) open the same port as `sceAudioInOpen`, so `sceAudioInInput`, `sceAudioInGetSilentState` and `sceAudioInClose` accept their handles. The signatures agree across [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/fc5d2cc219c43c8c8f354153e7b3d0c04a5d506e/src/core/libraries/audio/audioin.cpp), [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/60977b29103452b9681ae10c7a9011d44965bf16/src/SharpProspero/Interop/Audio/AudioIn.cs) and [KytyPS5](https://github.com/KytyPS5/KytyPS5/blob/c86c8b4d9333a766cc8c4495f89f893bf35e6199/src/libs/audio.cpp). HqOpen is limited to 128 samples at 48 kHz, as [KytyPS5](https://github.com/KytyPS5/KytyPS5/blob/c86c8b4d9333a766cc8c4495f89f893bf35e6199/src/libs/audio.cpp) and [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/60977b29103452b9681ae10c7a9011d44965bf16/src/SharpProspero/Interop/Audio/AudioIn.cs) describe the higher-quality path: a longer grain returns the invalid-size error and a lower rate the invalid-frequency error. AsyncOpen also accepts the 384-sample grain, the largest [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/60977b29103452b9681ae10c7a9011d44965bf16/src/SharpProspero/Interop/Audio/AudioIn.cs) documents for the low-latency path, and returns the invalid-size error for every other size; the console's shorter average return interval of an async port's blocks is not modelled, so like a synchronous port `sceAudioInInput` paces one grain at a time. Host capture pacing and console behavior remain unverified.
