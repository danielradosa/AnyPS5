# libSceKeyboard technical debt

### Functional

- [sceKeyboardGetKey2Char and sceDbgKeyboardGetKey2Char](../../../core/libs/prx/libSceKeyboard/src/keyboard_impl.cpp) (libSceKeyboard) translate the 101-key (US) arrangement and the alphanumeric layer of the 106-key (Japanese) one, which follows the JIS layout of the HID usages: the Yen (0x89) and Ro (0x87) keys return `\` (0x5C) unshifted, as JIS X 0201 places the yen sign there; whether the console returns U+00A5 instead is unverified. With the Kana LED (bit 4, the HID position) set the 106-key arrangement throws, as the kana the console returns are unknown. Ctrl and Alt do not change the character.

### Unknown function info

- [sceDbgKeyboardInit, sceDbgKeyboardOpen, sceDbgKeyboardClose, sceDbgKeyboardRead, sceDbgKeyboardReadState and sceDbgKeyboardGetKey2Char](../../../core/libs/prx/libSceKeyboard/src/keyboard_impl.cpp) (libSceKeyboard, library libSceDbgKeyboard) - the prototypes come from [orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json#L587-L592) and match the standard keyboard calls, so the debug keyboard is served by the host keyboard like the standard one: it has its own initialization, handle (1) and 16-sample queue, while the key, modifier, LED and connection state are the one host keyboard's, tracked while either library has it open and cleared when neither does. The error codes are the standard keyboard's (0x80DA00xx); the console's codes for this library are unverified. On PS4 the sysmodule id that loads it (0xa3) is flagged as a devkit-only module ([shadPS4 sysmodule_table.h](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/sysmodule/sysmodule_table.h#L464), flag 8 at [L32](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/sysmodule/sysmodule_table.h#L32)), so a retail console normally does not load it for a title; AnyPS5's sysmodule loads 0xa3, and whether a retail PS5 answers these calls at all is unknown. A title that kept debug-keyboard code therefore sees host key presses there too
- [sceKeyboardConnectPort, sceKeyboardDebugGetDeviceId, sceKeyboardDeviceOpen, sceKeyboardDisconnectAll, sceKeyboardDisconnectDevice, sceKeyboardDisconnectPort, sceKeyboardGetConnection, sceKeyboardGetDeviceInfo, sceKeyboardGetHandle, sceKeyboardMbusInit, sceKeyboardPadEmulateClose, sceKeyboardPadEmulateOpen, sceKeyboardSetProcessFocus, sceKeyboardSetProcessPrivilege](../../../core/libs/prx/libSceKeyboard/Export.cpp) (libSceKeyboard) - throwing stubs declared without parameters from the firmware export database (aerolib.csv); their guest signatures are unverified on hardware. No allowed source declares their parameters: shadPS4 stubs them without arguments, OpenOrbis `Keyboard.h` and `KbEmulate.h` list them as not reversed, and orbital, SharpProspero, KytyPS5 and sharpemu do not have them
