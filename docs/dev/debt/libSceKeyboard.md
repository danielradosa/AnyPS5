# libSceKeyboard technical debt

### Functional

- [sceKeyboardGetKey2Char and sceDbgKeyboardGetKey2Char](../../../core/libs/prx/libSceKeyboard/src/keyboard_impl.cpp): the original validates HID usages 4 through 231 before the handle and preserves unconverted HID usages in the output with `processed == 0`. The host instead accepts out-of-range usages and writes zero for unconverted keys. The original ignores the Kana LED, while the host throws for it. This partially implemented function contains `NotImplemented_nid_no_patch(__func__)`; its body is preserved under the requested restriction. One title (PPSA15246) disassembled for this entry calls it once with an output buffer cleared to 24 bytes, uses a character only when the result is 0 and the first output byte is nonzero, and then reads the 16-bit value at offset 8, which agrees with `processed` and `char_code` as laid out here. Which other output fields it reads and what its other arguments mean are not shown. `sceDbgKeyboardGetKey2Char` translates the same way.

### Unknown function info

- [sceDbgKeyboardInit, sceDbgKeyboardOpen, sceDbgKeyboardClose, sceDbgKeyboardRead, sceDbgKeyboardReadState and sceDbgKeyboardGetKey2Char](../../../core/libs/prx/libSceKeyboard/src/keyboard_impl.cpp) (libSceKeyboard, library libSceDbgKeyboard) - the prototypes come from [orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json#L587-L592) and match the standard keyboard calls, so the debug keyboard is served by the host keyboard like the standard one: it has its own initialization, handle (1) and 16-sample queue, while the key, modifier, LED and connection state are the one host keyboard's, tracked while either library has it open and cleared when neither does. The error codes are the standard keyboard's (0x80DA00xx); the console's codes for this library are unverified. On PS4 the sysmodule id that loads it (0xa3) is flagged as a devkit-only module ([shadPS4 sysmodule_table.h](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/sysmodule/sysmodule_table.h#L464), flag 8 at [L32](https://github.com/shadps4-emu/shadPS4/blob/23c41333822fe8eca4c609b43119180af63ae4ac/src/core/libraries/sysmodule/sysmodule_table.h#L32)), so a retail console normally does not load it for a title; AnyPS5's sysmodule loads 0xa3, and whether a retail PS5 answers these calls at all is unknown. A title that kept debug-keyboard code therefore sees host key presses there too
- [sceKeyboardGetDeviceInfo and sceKeyboardSetProcessFocus](../../../core/libs/prx/libSceKeyboard/Export.cpp): pointer arguments are passed to device ioctls. Device-info storage is 168 bytes in the connection-query caller, but its fields and the process-focus layout remain unresolved.
- [sceKeyboardConnectPort, sceKeyboardDisconnectPort and sceKeyboardDeviceOpen](../../../core/libs/prx/libSceKeyboard/Export.cpp): argument widths are confirmed. The meaning/order of the two 32-bit port arguments and the final 32-bit device-open argument still require the device-service backend.
- [sceKeyboardPadEmulateClose and sceKeyboardPadEmulateOpen](../../../core/libs/prx/libSceKeyboard/Export.cpp): the supplied keyboard library has neither export; their signatures remain unresolved.
